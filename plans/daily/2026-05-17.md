## 리스크와 확인 필요
- 확인 필요: Android 실폰, USB 디버깅, ADB, LAN, HTTPS 중 하나가 준비되지 않으면 실폰 field 항목은 완료가 아니라 `수동 검증 대기`다.

- 확인 필요: 5/16에는 Docker socket/PostGIS 접근이 막혀 reports runtime PASS가 확인되지 않았다. 일반 개발 세션에서 재검증해야 한다.
- 확인 필요: `서울역으로 안내해줘` 같은 자연어 목적지 표현은 제품 판단이 필요하다.
- 확인 필요: 일부 상태 문서는 2026-05-13 기준이라 최신 `/detect` adapter, server mode E2E, STT 연동과 충돌한다.
- 리스크: v2 모델은 class `0 damaged_tactile_block` 중심 baseline이다. 4-class 서비스 성능으로 주장하면 안 된다.
- 리스크: VL2+VS2 external metric은 tactile subset 전용이다. AI Hub 513 전체 validation 또는 4-class validation으로 해석하면 안 된다.
- 리스크: fake 신고는 API/UI/운영 흐름 검증용이다. 정확도, 지연시간, 실제 안전 판단 근거로 사용 금지다.
- 리스크: server mode E2E PASS는 headless fixture/known-positive 근거다. 실폰 목걸이 카메라 field 성능 근거와 분리해야 한다.
- 리스크: `/reports`, `/uploads`, status patch는 인증 없이 열려 있다. 외부 공개 전 인증/권한, CORS, rate limit, storage 정책이 필요하다.
- 리스크: Qwen3-TTS 동적 생성은 기존 기록상 2초 이상 걸릴 수 있어 보행 중 위험 경고 primary path로 두면 안 된다.
- 리스크: SW는 shell/static fallback 중심이다. 오프라인 신고 큐나 재전송 보장으로 표현하면 안 된다.
- 리스크: full test failure sampling은 exit code 137로 중단된 기록이 있다. 같은 방식의 대형 재실행보다 subset/streaming/저장량 제한이 필요하다.
- 리스크: failure CSV는 자동 후보다. 수동 시각 검수와 개인정보/위치정보 비식별 확인 전 v3 학습 데이터로 확정하면 안 된다.
- 리스크: `best.onnx`는 export와 raw tensor smoke 근거만 있다. full metric equivalence와 browser/ONNX Runtime Web latency는 미실행이다.
- 리스크: 촬영 이미지, 위치, 음성 샘플, 생성 WAV, `.pt`, `.onnx`, `runs/`, `outputs/`, 데이터셋 이미지는 GitHub 업로드 대상이 아니다.
- 리스크: 실폰 테스트는 안전한 실내/통제 환경에서만 수행하고 실제 시각장애인 대상 현장 검증으로 표현하지 않는다.
