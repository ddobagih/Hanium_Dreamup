## 이번 주 핵심 목표

1. 일반 개발 세션에서 공통 runtime gate를 고정한다: PostGIS `5432`, backend `8000`, web `3000`, voice `9001`, Android 접속 방식, 주요 env.
2. PostGIS/Alembic/reports API를 skip 없이 재검증하고, 생성 row/upload cleanup 기준을 확정한다.
3. Android 실폰/목걸이 착용 fake mode smoke와 `/admin` 운영 흐름을 신고 ID 기준으로 닫는다.
4. server mode는 `/detect/health ready` 이후 `source=server`, `metadata.source=server` 저장 근거만 확인하고 field 성능으로 확대하지 않는다.
5. voice HTTP contract, CORS, TTS HTTP cache header, 브라우저/실폰 마이크 E2E를 direct-call 근거와 분리해 검증한다.

7. 주말에는 데모/보고 기준과 문서 충돌을 정리해 다음 주 작업이 바로 시작될 수 있게 한다.

## 리스크와 확인 필요

- Android에서 `127.0.0.1`은 휴대폰 자신이므로 ADB reverse, LAN IP, HTTPS 중 실제 경로 확정이 필요하다.
- LAN HTTP는 카메라, 위치, 마이크, service worker 권한이 secure context 문제로 막힐 수 있다.
- 같은 sandbox 조건이면 Docker, local TCP, ADB 검증이 다시 막힐 수 있다. 이 경우 `BLOCKED`로 쓰고 일반 개발 세션 필요 조건을 남긴다.
- `source=fake`는 UI/API/운영 흐름 검증용이다. 정확도, 지연시간, 실제 안전 판단 근거가 아니다.
- `source=server` headless PASS는 known-positive fixture smoke다. 실폰 목걸이 field 성능 근거와 분리한다.
- v2 모델은 class `0` baseline이다. class `1..3` 한국 GT가 없으므로 4-class metric을 산출하거나 주장하지 않는다.
- `/` 사용률 99% 기록이 있어 full inference, 새 학습, 대형 산출물 생성은 디스크 gate 없이 시작하지 않는다.
- STT 8/8 성공과 TTS direct-call cache는 로컬 프로토타입 근거다. HTTP/PWA/실폰/청취 성공으로 확대하지 않는다.
- `/reports`, `/uploads`, status patch는 인증 없이 열려 있다. 외부 공개 전 권한/rate limit 정책이 필요하다.
- 원본 이미지, 위치 데이터, 음성 샘플, 생성 WAV, `.pt`, `.onnx`, `runs/`, `outputs/`, dataset images/labels는 GitHub 업로드 대상이 아니다.
- 실폰 테스트는 안전한 실내/통제 smoke로만 표현하고 실제 시각장애인 대상 현장 검증으로 쓰지 않는다.
