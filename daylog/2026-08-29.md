## 잔여 기능 실행 계획과 production report queue

- Wave 1~6 뒤 남은 18개 항목을 `NOW`, `DECISION`, `EXTERNAL`로 다시 분류하고 성공 기준·결정 질문·외부 증빙을 `docs/planning/walksafe-remaining-feature-execution-plan-20260829.md`에 고정했다.
- production report queue는 기본 비활성을 유지하면서 build 입력 7개, 실제 암호화 저장 byte, 최대 stored entry, 자동신고 한도와 최대 entry 한 건의 명시 신고 reserve를 구현했다. 승인 수치는 임의로 넣지 않았다.
- queue envelope 생성·최종 admission·게시를 같은 OS file lock 안에서 수행하고, 손상·미인식 regular file도 사용량에 포함했다. symlink·특수 파일·예상 밖 디렉터리는 fail-closed 처리한다.
- 비활성 build에서도 명시적 consent/account privacy purge는 실행한다. 미완료 의도를 담은 `lifecycle-pending`을 먼저 내구화하고 대상 fence, 전체 삭제, 키 폐기·필요한 fresh key, pending 제거 순서를 적용했다. account 삭제는 terminal 우선이며 key lifecycle 실패·crash 뒤에는 모든 consent의 저장·조회가 재시도 완료 전까지 차단된다.
- 조회·복호화, receipt exact-match·삭제, 만료 판정·삭제를 같은 file lock과 durable fence 판정 안으로 옮겼다. 시간 기반 경쟁 검사는 실제 OS lock 보유 확인으로 보강했다.
- 기관 제출·checkpoint·Goal graph·hash 봉인·승인·제어 자동화는 추가하거나 실행하지 않았다.

## 이메일 가입·동의 v1.1·잔여 기능 구현 마무리

- 현재 가입 방식을 휴대폰/PASS가 아닌 이메일·비밀번호와 이메일 6자리 OTP로 고정했다. 사용자가 입력한 생년월일을 서울 날짜 기준으로 계산해 만 14세 미만에는 OTP·enrollment·계정을 만들지 않으며, 이를 본인·명의·공적 연령 인증으로 표현하지 않는다.
- Android→Gateway→Backend 가입·로그인, 로그인 뒤 사용자가 시작하는 전경 기기점검과 `FULL`/`LIMITED` 기능 gate, 버튼형 STT와 Gateway/단말 TTS 경로를 구현했다. 승인 호출어 자산이 없는 `길라잡이` wake word는 default-off다.
- 통합 동의를 `FP-013-1.1.0`으로 맞추고 Backend authoritative receipt, authenticated bootstrap, 이전 Backend receipt CAS, exact replay, actor/account-generation/installation 격리, 알려진 v1의 안전한 재동의 전환을 Android·Gateway·Backend에 연결했다.
- migration `202608290016`은 과거 v1 증거를 보존하되 신규 event는 v1.1만 허용하고 v1.1 증거가 남은 downgrade를 거부한다. migration `202608290009`도 계정·enrollment·가입 receipt 자료가 남으면 파괴적 downgrade를 SQLSTATE `55000`으로 거부하도록 보강했다.
- 신고 정정은 허용 필드의 append-only content revision, 신고 물리삭제는 내용 없는 tombstone, raw v2 원본은 commit 뒤 최대 14일, 승인·비식별 학습자료는 dataset 승인부터 최대 3년으로 구현했다.
- 계정 삭제 worker v4는 삭제 시작 시 enrollment UUID를 고정해 commit 응답 유실 뒤 같은 이메일의 새 enrollment가 생겨도 새 행을 삭제하지 않는다. CRITICAL incident는 기록·조회·상태 전이만 하며 자동 복구·자동 제어·자동 통지를 추가하지 않았다. restore는 외부 tombstone ledger/trusted head가 없거나 불일치하면 공개를 막는 fail-closed 계약을 유지했다.
- 관리자 신고 목록 projection에 추가된 `content_revision`과 단위 테스트 allowlist가 어긋난 회귀 1건을 수정했다.
