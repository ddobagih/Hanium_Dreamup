# 2026-08-31 추가 — TMAP 실키 연결과 3단 관통 검증

## 한 일

TMAP 앱키를 받아 로컬 스택에 넣고, **Backend → Gateway → App 순으로 실제 트래픽을 흘려 확인**했다.
제품 소스는 고치지 않았다. 변경한 것은 `backend/.env`(비추적)와 Docker 컨테이너 구성뿐이다.

## 검증한 것 — 실제 응답으로

| 구간 | 결과 |
|---|---|
| Backend → TMAP | 서울역→시청 **2,090m / 1,628s**, steps 17, guide_points 16, `provider_result_code 0` |
| Gateway → Backend → TMAP | field-session·목적지검색·보행경로 **전부 200**. 값이 Backend 직접 호출과 일치 |
| App → Gateway → Backend | `adb reverse tcp:8081` 경유 실제 로그인, `POST /accounts/authenticate` **200**. 앱이 첫 실행 1/6 → 4/6 → 5/6단계 진행 |

첫 안내 문구는 `"보행자도로를 따라 80m 이동"`으로 한국어가 그대로 온다.

## 막힌 곳 — 에뮬레이터의 경계

- **첫 실행 5/6단계에서 정지.** 「미터 단위 거리 측정」 점검이 ARCore를 요구하는데 에뮬레이터에 없다.
- **DEBUG 미리보기로 보행 화면까지는 도달**했으나(10/10) 목적지 검색은 실행되지 않는다. 버튼은
  `enabled=true`이고 질의도 입력돼 있지만 요청이 나가지 않는다. 원인은 `MainActivity.kt:24257`의
  `gatewaySessionOrNull("destination_search") ?: return false` — 미리보기 상태에는 보행 세션이
  결속되지 않는다. **미리보기는 화면을 보는 용도이지 동작시키는 용도가 아니다.**
- `adb shell input text`는 **한글에서 NPE로 죽는다**(비ASCII 미지원). 자동화로 한글 목적지를 넣을 수
  없다. 실기기에서도 IME나 음성으로 넣어야 한다.

## 해결한 함정 넷 — 같은 데서 두 번 막히지 말 것

1. **Gateway 프로세스가 25시간 묵은 코드로 돌고 있었다.** `dist`는 다시 빌드해 최신인데 Node가 옛
   모듈을 메모리에 들고 있어 `grant_type=password` 로그인이 400 `field_session_request_invalid`로
   거부됐다. **`docker restart`로 해결(`rm` 아님 — `/srv/secrets`의 keyring이 사라지면 기존 암호화
   상태를 못 읽는다).** 소스를 고치기 전에 프로세스가 그 소스를 실제로 들고 있는지 먼저 볼 것.
2. **DB가 저장소에 없는 리비전 `202608300001`에 스탬프돼 있었다.** 철회된 FP-010 스택의 로컬
   마이그레이션이고 git 이력에도 없어 downgrade가 불가능했다. PostGIS 확장은 `deptype='e'` 제외
   조건으로 보존한 채 애플리케이션 테이블·ENUM·**함수 41개**를 걷어내고 head `202608290016` 도달.
   테이블 정리만으로는 부족하다 — 함수가 남아 `walksafe_reject_audit_mutation already exists`로 막힌다.
3. **컨테이너 env가 `.env`를 이긴다.** `load_dotenv`는 이미 설정된 변수를 덮지 않으므로, 컨테이너에
   `TMAP_APP_KEY=`(빈 값)가 박혀 있으면 파일에 키를 넣어도 반영되지 않는다. 컨테이너 재생성이 답이다.
4. **탭이 조용히 빗나간다.** 단계마다 버튼 위치가 바뀌어 같은 좌표를 반복 탭하면 아무 일도 없이
   지나간다. **매 회 `uiautomator dump`로 bounds를 다시 읽을 것.** 08-30 기록과 같은 함정이다.

## 로컬 환경 현황

- 스택 3개 정상: `walksafe-backend`, `walksafe-gateway`, `walksafe-postgis`
- **Backend는 macOS에서 여전히 기동 불가.** `os.listxattr` 부재로 lifespan이 fail-closed 한다.
  `--lifespan off`로 라우터만 띄우는 것은 기동이 아니다. Linux 컨테이너가 유일한 경로다.
- 계정 암호화 키 3종을 새로 만들어 `backend/.env`에 적었다(비추적). env 파일 없이 컨테이너를
  재생성해도 `.env`만으로 계정 결속이 서는 것을 확인했다.

| 같은 DB 재실행 | 60 failed / 1233 passed |

**세 번 모두 동일하다.** 이전에는 같은 코드가 122 / 85 / 117로 흔들렸다. 이제 DB를 새로 만들든
재사용하든 같은 수가 나오므로, **베이스라인을 비교 대상으로 쓸 수 있다.**

앞 절에 적은 「베이스라인은 새 빈 DB 첫 실행으로만 비교 가능」 제약은 이 수정으로 사라졌다.

## 새 베이스라인

```
Gateway   144 / 144 통과, 실패 0
Backend   60 failed, 1233 passed, 19 skipped   (재현 가능)
```
