## 기기점검 완료 후 단계 전환 교착 수정 및 SM-G981N 재배포

- 기기점검 통과 직후 새 FP004 진행 상태가 프로세스 세션의 이전 snapshot에 의해 되감기던 경로를 수정했다. 동일 로그인 generation에서 더 최신 FirstRun snapshot만 반영하고, 같은 actor의 오래된 callback은 로컬 진행 상태를 덮지 못하게 했다.
- 로그인 직후 만든 빈 안전교육 정책이 actor별 저장 진도를 가리던 경로를 수정했다. 기기점검 완료 시 저장된 FP004 진도를 다시 결속하고, 이미 교육이 끝난 경우 COMPLETE 전환을 재조정한다.
- 완료된 FULL/LIMITED 기기점검은 잠깐의 백그라운드 전환으로 폐기하지 않되, 실행 중인 점검은 계속 fail-closed 재검사하도록 분리했다. COMPLETE 화면에서도 기기점검 재실행 버튼을 노출했다.
- 런타임 계측 시작 latch, AR 사전점검 renderer 복귀, 카메라 timeout의 PASS 보존, 장착 확인 전 프레임 거부, GPS 15초 timeout·고정밀 새 위치·mock 위치 거부를 보강했다.
- CameraX 전체 해제 대신 각 흐름이 소유한 use case만 해제하고, 재시도 generation·프레임 timestamp를 확인해 이전 시도의 지연 프레임이 새 결과를 덮지 못하게 했다.
- 카메라 timeout과 분석 callback의 generation 폐기·증거 비교/commit을 같은 lock에 묶었다. 장착 센서 시작 실패 시 ACTIVE 상태로 남지 않고 SAFE_STOP하며 서버 보행 lease도 best-effort 종료한다.

- 위치 실패 사유를 권한·위치 서비스 꺼짐·시간 초과·낮은 정확도·오래된 위치·mock 위치로 구분했다. 좌표는 저장하지 않고 결과·사유·정확도 구간·경과시간 구간만 영속 진단 기록에 남기며, 계정 삭제 때 함께 삭제한다.
- 빠른 설정에서 위치나 권한을 바꾼 뒤 앱으로 돌아오면 live 상태를 다시 검사한다. 이미 보행 중인 상태에서 필수 조건이 무효화되면 안전 정지한다.
- CameraX 종료는 analyzer 장벽과 실제 `CameraState.CLOSED`를 확인한 뒤에만 ARCore fallback을 허용한다. 2초 내 안전 종료를 확인하지 못하면 fallback을 시작하지 않는다.
- 기기점검의 시작·timeout·카메라/위치/계측 callback·권한 복귀를 actor, Gateway session generation, attempt generation에 결속해 이전 로그인이나 이전 시도의 지연 결과가 현재 상태를 바꾸지 못하게 했다.
- 동일 이메일 사용자의 재로그인은 첫 실행 진도를 보존하면서 새 기기점검을 요구한다. 오래된 세션 정리 버튼은 일반 로그아웃과 분리해 세션만 정리하고 진행 상태는 지우지 않는다.
- 독립 상태 검수에서 일반 세션 정리 버튼이 삭제 복구 전용 세션을 폐기할 수 있고, 실제 저장소 차단은 남았는데 coordinator 표시만 해제할 수 있는 두 MEDIUM 경로를 추가로 발견했다. 삭제 복구·저장소 차단 중에는 일반 정리 버튼을 숨기고 늦은 클릭도 거부하도록 수정했다.
- 일반 stale-session 정리는 같은 process generation·같은 GENERAL session·정상 저장소 상태를 coordinator lock 안에서 확인하고 operation을 선점하는 CAS를 사용한다. 검사 직후 삭제 복구 publish나 storage block이 발생해도 새 상태를 지우지 않도록 동작 회귀 테스트를 추가했다.
- FP004 교육·안전장소·연습은 live 기기점검 gate를 통과해야만 시작할 수 있다. gate 무효화 시 진행 중 피드백을 취소하고, 늦게 도착한 callback은 자신이 소유한 상태만 정리한다.
- 호출어 점검은 버튼을 누르면 즉시 시작하며 TalkBack 지연이나 안내 음성과 입력 겹침을 제거했다. timeout·세션 변경·백그라운드 실패·gate 무효화의 최종 안내는 중복 발화 없이 한 번만 접근성 포커스를 준다.

## 단축 테스트 이메일 계정 생성

- 실행 중인 Gateway·Backend·PostgreSQL·로컬 SMTP 환경을 사용해 앱 입력 규칙을 만족하는 단축 테스트 이메일 계정을 OTP 정식 가입 흐름으로 생성했다.
- 필수 가입 동의 3개만 승인하고 원본 수집·자동 신고·학습 재사용 선택 동의는 모두 거부 상태로 생성했다.
- Gateway password grant 로그인, 인증 상태 조회, 테스트 세션 로그아웃을 순서대로 확인했다. 결과는 HTTP `200`, authenticated `true`, 로그아웃 `204`였다.
- 휴대폰에서 로컬 Gateway를 사용할 수 있도록 `adb reverse tcp:8081 tcp:8081`을 설정했다.
- 비밀번호와 OTP는 daylog에 기록하지 않았다.
