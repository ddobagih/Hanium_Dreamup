- hardened one-shot을 원문 그대로 호출했으나 승인된 root-owned quiesce marker가 없어 `QUIESCE_APPROVAL_REQUIRED`로 fail-closed했다. 호스트 PG client와 설치된 backend venv도 없어 실제 backup 생성·격리 restore는 모두 `NOT_RUN`; 생성 artifact·합성 row·잔존 컨테이너·network·volume·임시 경로는 0이다.

## Wave 4 백업 계정·공유 잠금·삭제/보존 안전성 보완

- backup을 API와 다른 `walksafe-backup` Unix 계정으로 분리하고, `walksafe-backup-readers`와 `walksafe-maintenance-lock` 전용 group 및 sysusers/tmpfiles/systemd 초안을 추가했다. backup 실행 시 exact 계정·primary GID·home·shell과 허용된 세 group 외 예상 밖 effective group이 없음을 fail-closed로 검사한다.
- upload root와 암호화 `.wse` 계약을 운영 환경 `2750/0640`, exact backup-reader GID, access/default ACL 없음으로 통일했다. Backend 쓰기·startup reconciliation·원본 읽기, 삭제 worker, retention, backup source가 descriptor/path identity와 ACL을 읽기 전후 검증한다.
- root가 미리 만든 shared maintenance lock 하나를 API는 shared, 삭제·retention·backup은 exclusive로 사용한다. lock parent/leaf는 각각 `root:walksafe-maintenance-lock 0750/0440` exact 계약이며 group collision과 root GID를 거부한다.
- retention wrapper의 공개 manifest 검증을 실제 producer와 맞췄다. 암호화 객체 6필드, `reconciled_runs`, 모든 실패 상태의 `error_type`·`restore_errors`를 exact 검사하고, 후보가 있는 완료/실패 전 복구 증거를 현재 top-level run ID와 동일 candidate IDs에 결속한다. 생성하지 않는 구형 `completed_with_cleanup_errors` 상태는 제거했다.
- 삭제 worker는 PREPARED crash 때 quarantine `0640`/`0600` 두 정상 상태만 exact 검증해 복구한다. create-only dir-fd rename, unlink 전후 inode·hash·ACL 결속, unlink 후 link count 0, 파일이 이미 없는 재시도의 양 parent `fsync`를 추가해 덮어쓰기·완료 오판·내구성 빈틈을 막았다.
- 기존 host 마이그레이션 순서는 sysusers/tmpfiles 적용 전에 계정·group·upload/lock ACL을 읽기 전용 검사하고, 적용 뒤 다시 검사하도록 보완했다. tmpfiles가 기존 ACL을 제거한다고 가정하지 않는다.
