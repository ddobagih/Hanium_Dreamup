## WalkSafe RC2 speech delivery and recovery hardening

- Web speech output now distinguishes queued, started, completed, failed and cancelled delivery; risk, interaction, navigation and availability fallback keep explicit priority, bounded retries and stale-callback guards.
- Android feedback now owns audio focus, STT exclusion and start/terminal watchdogs explicitly. Policy cooldown is reserved first, confirmed only after TTS completion or an actual STOP haptic/TalkBack dispatch, and rolled back on failure, lifecycle cancellation or higher-severity preemption.
- Backup/restore now requires one explicit PostgreSQL target and verified remote TLS, rejects non-PostGIS user objects in the restore target against a pinned PostgreSQL 16/PostGIS 3.5.2 baseline, isolates ambient shell/libpq/Python state, pins private upload/output descriptors, publishes with no-replace rename, and binds restored report/image bytes to stable FD snapshots and the signed receipt digest.
- Report writes, backup and retention now flock the same private parent-directory inode. A late reverse audit showed that trusting only its immediate root-owned ancestor still allowed a higher service-owned directory to swap authority entries. Every ancestor from `/` to the lock parent is now opened root-first and bound by FD, absolute path and parent entry; root ownership, mode, effective ACL write access and the exact parent `dev:ino` all fail closed. The field launcher keeps the validated `/run/user/$UID` parent FD and creates the lock through its `/proc/self/fd` anchor.
- Retention and release-evidence validation require the new source-consistency, lock-authority and restored-image hash evidence. The issue ledger records the current layer counts and three unresolved product decisions.
