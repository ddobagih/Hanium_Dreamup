# S10-18: 혼잡 표본의 300개 제한 계측

## 실제 측정

현재 앱의 21클래스 YOLO11n Float32 768 모델·클래스별 임계값·allowlist를 유지했다.
원 제공 `full_all.txt` 27,021장 중 YOLO 라벨이 20개 이상인 **전 149장**을
절대 경로 순서로 실행했다. 원 제공 라벨 수의 최대는 34개다.
여기서 혼잡도는 라벨 개수를 이용한 정적 표본 선정 기준이다.

| 측정 | 실제 값 |
| --- | ---: |
| 원 제공 사진 | 27,021장 |
| 라벨 20개 이상인 선정 사진 | 149장 |
| 전체 원출력 anchor | 1,802,304개 |
| 유효 원사진 내용과 교차하는 anchor | 1,116,541개 |
| 현재 top1 클래스 임계값을 통과한 pre-NMS 후보 | 19,616개 |
| 사진 한 장의 pre-NMS 후보 최대 | 218개 |
| pre-NMS 후보 300개 이상인 사진 | 0장 |

NMS와 후속 좌표 dedup은 후보 수를 늘리지 않는다. 따라서 이 host 측정 표본에서는
300개 제한으로 제거된 후보가 없다. 원문은 실제 제한에 도달하는지 먼저 계측하고,
문제가 확인되면 후보 보존 정책을 검토하도록 요구한다. 이 결과로는 제한을 늘리거나
새 선별 정책을 도입할 근거가 없으며 운영 파서·모델·임계값을 변경하지 않았다.

실제 실행은 TensorFlow 2.19.1 / OpenCV 4.13.0 / NumPy 2.1.3,
CPU XNNPACK 2스레드로 종료 코드 0이었다. 첫 별도 실행과 보관한 self-relative 스크립트 실행도 모두 종료 코드 0이며
각 실행에서 149장 전부의 사진/input/raw SHA와 사진별 후보 수·전체 수치를 재현했다.
독립 읽기 검토에서도 원 목록·선정·라벨 수·사진 SHA·파서 자격 조건과 후보 상한을 확인했다.

## 자료와 재현

- `result.json`: 측정 합계와 149장별 라벨 수·사진/input/raw SHA, 모델·설정·원 목록·선택 SHA.
- `selection.json`: 선정 사진의 원본 절대 경로와 포함된 라벨 클래스.
- `execution.txt`: 최초 실제 native 모델 실행의 시작·진행·완료.
- `reproduction.txt`: 첫 별도 재현과 보관한 self-relative 스크립트의 실제 재현 기록.
- `reproduce_host_evaluation.py`: 보관한 결과와 원 제공 사진·라벨·현재 모델을 읽고
  선택 SHA 및 149장별 모든 값과 사진/input/raw SHA를 대조한다. 결과는 새 임시 폴더에 쓴다.

## 해석 범위

측정은 생산 파서의 top1 첫 동점 선택·Float32 임계값·allowlist·유효 normalized box·
원사진 내용 교차 조건을 적용한 **NMS 이전 후보 상한**이다.
149장 전체의 Android 파서나 Android YUV 입력 비트 동등성을 실행한 결과는 아니다.

제공 라벨의 완전성, 실제 300객체 stress, 전체 모집단의 제한 발생률, 위험 객체 누락률,
실제 보행·GPU·단말 성능을 검증하지 않았다. 0건은 이 선정 표본의 관측 결과다.
300개 가까운 후보가 발생하는 새 데이터에서는 위험 후보의 보존 여부를 다시 측정해야 한다.
