# WalkMate YOLO26n 교체 — 2026-10-28

사용자가 제공한 `YOLO26n_final.pt`를 Android 기본 객체 인식 모델로 변환했다. 원본 체크포인트와 TFLite의 SHA-256 및 정확한 클래스 순서는 `export_manifest.json`에 기록했다.

## 적용 계약

- 원본: YOLO26n, Ultralytics 8.4.115. 재학습 또는 가중치 수정 없이 변환.
- TFLite: float32 입력 `[1,768,768,3]`, 출력 `[1,300,6]`. 출력 행은 **입력 영상 픽셀 단위** `x1,y1,x2,y2,score,classId`.
- 21개 출력 ID, 20개 고유 이름. 사용자 결정에 따라 ID 9·10 모두 `e_scooter` / **킥보드**. 방치·이동 상태를 이름에서 추론하지 않는다.
- 기존 ID별 검출 임계값 유지: 9번 0.25, 10번 0.15. 다른 ID도 모두 기존값 유지. 두 ID의 점수 필터를 적용한 뒤 공통 이름으로 전달한다.
- 기존 거리 계산, 위험 단계 조건, 정지 음성 우선순위는 변경하지 않았다.
- 손상 점자블록의 신고 모델 식별자 `walkmate_21cls` 유지.
- 새 모델 해시·설정·ID별 임계값·점검 자료에 기기 점검 결과를 연결한다. 구 모델의 점검 결과를 새 모델의 검증으로 재사용하지 않는다.
- YOLO11n 모델과 기존 시험 자료는 역사적 검증용으로 보존한다. Release 모델 목록은 새 YOLO26n과 기존 FastSAM이며, 구 YOLO11n은 제외한다. 개발용 APK는 기존 정책대로 과거 모델도 포함한다.

## 변환 재현

사용한 별도 환경: Python 3.12, torch 2.10.0, Ultralytics 8.4.115, TensorFlow/tf-keras 2.19.0, onnx 1.17.0, onnx2tf 1.28.8. 체크포인트는 검토된 torch/ultralytics 클래스만 허용하는 `weights_only=True` 로더로 열었다.

```python
YOLO('YOLO26n_final.pt').export(
    format='saved_model', imgsz=768, batch=1, nms=False,
    quantize=32, dynamic=False, device='cpu', opset=17,
)
```

해당 버전의 SavedModel 변환이 함께 생성한 `YOLO26n_final_float32.tflite`를 사용한다. `format='tflite'` 별칭은 이 버전에서 다른 변환기로 연결되므로 같은 과정으로 간주하지 않는다. 변환에 필요한 패키지는 프로젝트의 별도 로컬 환경에만 설치했다.

## 실제 수행한 호스트 검증

- 원본 PT와 TFLite에 같은 RGB/114 패딩/양선형 letterbox/255 정규화 입력을 전달했다.

- 21개 대상 사진 중 **16개**에서 목표 객체와 IoU 0.5 이상으로 일치했다. 미충족 5개는 선형 점자블록, 손상 선형 점자블록, 손상 점형 점자블록, 기존 이동 킥보드 표본, 쓰레기통 표본이다. 이는 부분 주석 사진의 표본 결과이며 전체 정확도/mAP가 아니다. 실패 표본을 삭제하거나 임계값을 낮추지 않았다.
- 배경만 담은 영상 표본 3개에서 임계값을 통과한 검출은 0개였다.
- 기존 점검 사진 `coco_885`는 새 모델에서 임계값 부근 출력을 만들지 않았다. 기존 시험 자산의 원본 `coco_872`로 교체했으며 실제 경계 후보 2개를 관측했다. 임계값·허용오차는 그대로다. 885 이미지와 구 점검 manifest는 과거 회귀용으로 유지한다.
- 사진 872의 라이선스·원본 URL은 기존 COCO 메타데이터에 있고, 작성자·제목의 현재 확인은 불가능했다. 이 제한은 점검 자산 `ATTRIBUTION.md`에도 명시했다.
- 새 JVM 참조 자료는 `yolo26-model-boundary`에 별도로 저장했다. 원본 영상 해시, 실제 입력·출력 해시, 경계 후보를 결속한다. YOLO11 참조를 새 모델 결과로 덮어쓰지 않았다.
