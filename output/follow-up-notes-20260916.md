# 후속 작업 및 길안내 시작 조사 — 2026-09-16

## 보류: USB 없이 외부 네트워크 사용

사용자는 모바일 데이터 및 외부 Wi-Fi 사용을 원하지만, 지금은 보류하고 나중에 진행하기로 함.
- 현재 gateway는 PC의 127.0.0.1:8081에만 노출. 앱은 USB reverse로 연결.
- 앱은 WALKSAFE_GATEWAY_ORIGIN으로 HTTPS 주소 지정 가능.
- 외부 서버/도메인 또는 임시 외부 접속 방식은 아직 선택하지 않음. 외부 공개 작업 없음.
- 모바일 데이터 전송 허용 설정도 확인해야 함.
- 휴대전화 연결 해제됨. 이후 현장 테스트에서 다시 연결 예정.

## 안내 중 메인 화면으로 이동

continuePendingExplicitRouteStartIfReady()가 GPS 대기 후 경로 요청을 시작하면
clearNativeDestinationSearchState()와 showNativeUiPage(HOME)를 실행하고 있었음.
음성 경로 안내는 유지되므로 사용자가 보고한 증상을 설명하는 확정적 코드 경로임.
목적지/시작 승인 상태를 유지하고 GUIDANCE 화면으로 이동하도록 로컬 수정.
실제 프로세스 충돌 여부는 기기 로그가 없어 확인하지 못함.

## 시작 직후 위치 문제 및 재시작 요구

- 사전 점검의 위치 증거와 실제 경로에서 사용하는 latestTrustedLocation은 별도 상태.
- 실제 위치 요청은 setMaxUpdateAgeMillis(0L)로 새 측정을 요구함.
- 실제 경로용 LocationTrustPolicy는 정확도 15m 이하, 최대 경과시간 10초, 비현실적 위치 점프 검사를 적용.
- 시작 승인은 위치 대기 중 15초간 유지되고, 그 안에 유효 위치가 없으면 만료되어 명시적 재시작을 요구.
- 추가로 위치 신뢰도 하락 시 방향 안내를 제한하는 별도 정책이 존재.
- 이번 사례의 직접 원인이 15초 만료인지, GPS 정확도 저하인지, 위치 신뢰도 전환인지는 실기기 로그로 확인 필요.
- 위치 기준/대기시간은 변경하지 않음.

## 다음 기기 테스트

GPS 대기 후 성공해도 안내 화면/선택 목적지가 유지되는지 확인.
시작 확인부터 첫 유효 경로용 위치까지 시간과 위치 정확도, 보행 상태 전환을 함께 기록.
15초 만료 안내와 즉시 발생하는 위치 품질 경고를 구분하고, 결과에 따라 위치 상태 인계 및 재시도 UI 검토.

## 임시 Cloudflare 테스트 재개

사용자가 직접 연 터널 주소: https://sec-recommendation-employees-searched.trycloudflare.com
외부 /internal/health HTTP 200 확인. 앱 빌드에 -PWALKSAFE_GATEWAY_ORIGIN으로 지정.
명시적으로 HTTPS 주소를 준 debug 빌드는 저장된 USB 주소보다 빌드 주소를 우선함.
임시 주소를 기본 배포 주소로 하드코딩하지 않음. 이후 재빌드에도 같은 옵션 필요.
터널 재시작 시 주소가 바뀌면 새 주소로 다시 빌드. 계정 상태는 기존 origin 검증을 유지.
기기 미연결로 설치와 모바일 데이터 실기기 검증은 아직 하지 않음.
