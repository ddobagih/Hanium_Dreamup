# 조원 AI에게 이 문제를 인계하는 방법

## 읽는 순서

1. `docs/status/device-check-object-recognition.md` — 현재 결론, 입력/설치 기준선, 소스 위치, 해결 경로, 미확인과 다음 분석.
2. `docs/status/device-check-object-recognition-history.md` — 과거 변경/검증과 앞으로 추가할 진행 이력.
3. 보고서에 연결된 실제 소스/증거. 문서만 전달받았다면 로컬 증거가 자동으로 존재하는 것은 아니다.

이 파일과 나머지 보고서는 개발 기록이다. 소스/로그 없이 보고서만 받은 AI는 내용을 **전달받은 관측**으로 구분하고, 직접 검증했다거나 최종 기기점검이 성공했다고 주장하지 않는다.

## 조원에게 전달할 최소 문장

> Android 기기점검 객체 인식 문제는 조건부 수치 마스크 동등성 수정 후 실제 폰에서 전체 객체 strict/soak/qualification/adoption/publish를 통과했다. 기존 차이1개는 유효 경계 픽셀이고 IoU0.9999323272653448 및 자체 raw sign을 실제 검증했다. 전체 attempt는 호출어 UNAVAILABLE로 FAIL이지만 호출어 품질은 사용자 요청으로 범위 밖이다. 새 브랜치 fix/walkmate-device-check-20261106은 테스트한 ZIP 원본 시점에서 분기했으며 조원들의 이후 integration 변경과 자동 병합한 결과가 아니다. 보고서와 진행 이력을 읽고 source/test 수정, 테스트용 이름·패키지·서명 변경, 실기기 성공 범위와 미확인 범위를 구분하라. 새 결과마다 두 문서에 이어서 기록하라.

## ZIP만 전달받은 경우

- `docs/status/` 아래 문서를 그대로 읽거나 조원의 동일 snapshot 저장소에 복사한다.
- 함께 들어 있는 `AGENTS-ADDENDUM.md`는 해당 저장소 AGENTS에 **병합할 짧은 안내 절**이다. 전체 AGENTS를 덮어쓰지 않는다.
- 소스/증거 로그/모델/앱/비밀값을 포함한 ZIP이 아니다. 코드 변경까지 이어갈 경우 같은 원본 archive와 누적 소스 diff/해당 증거를 권한 있는 환경에서 별도 확보해야 한다.
- 공유 ZIP는 내보낸 시점의 snapshot이다. 이후 최신 상태는 원래 프로젝트의 두 문서에서 갱신하며, 조원에게 다시 전달하려면 갱신된 문서를 재전달해야 한다. 원격 동기화는 설정하지 않았다.

## 다음 작업자가 기록할 최소 항목

- 시각과 대상 버전/APK SHA
- 관측 사실과 가설의 구분
- 실제 코드/정책 변경 및 사용자 승인 범위
- 실행한 검증 결과와 증거 경로
- 아직 실행하지 않은 검증과 남은 실패
- 다음 단일 작업

현재 작업의 착수/완료 여부와 승인 범위는 현황 보고서의 최신 상태와 진행 이력을 우선한다. 문서화나 작업 위임을 native 재측정·빌드·설치·해결 완료로 기록하지 않는다.
