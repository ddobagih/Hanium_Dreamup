1. 읽는 법

이 문서의 주 목적은 “어떤 기능을 구현할지 가감하기”입니다. 따라서 첫 번째로 기능군 전체 인벤토리를 보고, 필요한 기능을 남기거나 삭제한 다음, 구현 순서와 Goal 프롬프트 초안을 수정하면 됩니다.
표기 의미 구현 판단
구현 코드 또는 문서+테스트 근거가 있음 그래도 Device/Release PASS와는 별도입니다.
부분 일부 lane에서만 동작하거나 정책/스캐폴드만 있음 대부분 실제 제품 연결 또는 실기기 검증이 남아 있습니다.
미구현 기능 요구는 있으나 현재 코드가 없음 구현 대상 후보입니다.
Gate 다른 기능을 켜기 전 반드시 통과해야 하는 조건 현재 최우선은 Android bbox-depth 정합입니다.
승인 필요 비용, 계정, 개인정보, 외부기관, 배포 영향을 가짐 goal에 넣기 전 사용자 명시 승인이 필요합니다.
중요한 해석: Web/PWA에 기능이 구현되어 있어도 Android 주 사용자 앱에 구현된 것은 아닙니다. PWA는 demo, API contract 검증, admin 보조 경로로 유지하고, 실제 사용 앱은 Android native 기준으로 판단합니다.

13. 다음 구현용 Goal 프롬프트 초안

아래 프롬프트에서 빼고 싶은 기능을 삭제하고, 추가할 기능을 넣으면 바로 다음 구현 작업 지시로 쓸 수 있습니다.

/home/ddobagi/Code/hanium-dreamup 프로젝트에서 WalkSafe Assist를 Android native 주경로 기준으로 모델 제외 완성 상태에 가깝게 구현해줘.

기준:
- Web/PWA는 demo/admin/API 검증 보조 경로다. Android Device PASS를 대체하지 않는다.
- 모델 학습/정확도 자체는 제외하되, 최종 TFLite 모델이 들어왔을 때 앱이 바로 연결될 수 있어야 한다.
- raw image/depth/audio/GPS 과다 저장과 외부 전송은 금지한다. frame capture는 승인 전 field 기능으로 쓰지 않는다.

P0:
1. Android bbox overlay가 실제 객체와 맞는지 실기기 체크리스트 기준으로 검증/보강한다.
2. ARCore Raw/Full Depth sample이 bbox와 같은 객체를 보도록 coordinate mapper와 metadata를 보강한다.
3. detector stale guard와 metadata-only debug log를 검증 가능하게 만든다.
4. Android report upload 전에 source=android 여부, APK/model/config hash, depth quality, coordinate gate status metadata allowlist를 확정한다.

P1:
