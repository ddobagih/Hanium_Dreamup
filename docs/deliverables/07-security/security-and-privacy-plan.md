## 이 문서를 읽는 방법

보안과 개인정보를 개발·설계·운영에 어떻게 적용하고, 무가림 원본·권한·비밀값·삭제를 어떤 규칙으로 통제하는지 설명합니다.

`Draft`는 작성 가능한 정책·절차·명세를 적었다는 뜻이며 실제 시험 통과나 외부 승인을 뜻하지 않습니다. 역할명은 책임을 나타내며 서로 다른 사람이 이미 배정됐다는 뜻이 아닙니다. 1인 개발 단계에서는 가짜 검토자를 만들지 않고, 독립 검토가 필요한 항목은 실제 검토자가 참여할 때까지 미승인으로 둡니다.

## 공통 통제 경계

- 현행 정식 제품은 Android 사용자 앱과 별도 비공개 Android 관리자 앱입니다.
- Web/PWA는 재승인 전까지 레거시 참고 범위입니다.
- 위치·영상·음성·서명 등 민감 원본은 Git에 넣지 않습니다. Git에는 통제 저장소 ID, SHA-256, 접근등급, 보존기한과 판정만 둡니다.
- 구조검사 통과는 구현 완료·시험 통과·출시 가능을 의미하지 않습니다.


## 승인 입력과 현재 경계

- 원본 수집 정책은 승인됐습니다. 동의한 활성 보행에서 영상·음성·정확 위치·센서·탐지·경로·신고·성능과 주변인의 얼굴·번호판·목소리를 가리지 않은 수집 원본을 다룹니다.
- 원본 정책의 출시 전 독립검토는 아직 실행되지 않았습니다. 따라서 정책 재논의 없이 설계는 진행하되 출시 승인은 차단됩니다.
- FP-035 일반 활동원본은 보행 중 전송하지 않습니다. 정책 1.0.1의 승인된 exact overlay에 따라, 정지 뒤 이동통신망 전송을 명시적으로 선택한 경우에만 허용된 이동통신망을 사용하고 미선택 시 Wi-Fi만 사용합니다. 정책 변경은 유효하지만 휴대전화 대기열 용량, 서버 용량상태 계약과 관련 통합시험은 `NOT_RUN`입니다.
- 민감 원본과 서명 원본은 Git 밖 통제 저장소에 두고, 이 저장소에는 식별자·hash·상태·보존기한만 둡니다.

### 포함 내용과 완료 기준

**반드시 들어갈 내용:** - 보안 목표·범위<br>- 역할·분리·교육<br>- 위협모델·review 시점<br>- scan·시험·수정 SLA<br>- release gate·예외<br>- 증거·보고·갱신

**완료 판단:** - 다음 핵심 내용이 근거·버전과 함께 구체적으로 작성되어 있다: 보안 목표·범위, 역할·분리·교육.<br>- 필수 내용에 공란·암묵적 가정이 없고 미결정은 소유자·기한이 있는 차단 항목으로 표시되어 있다.<br>- 상위 입력과 요구·설계·코드·시험·변경요청의 해당 추적 링크가 유효하다.<br>- 지정 검토자가 사실·일관성·추적성을 확인하고 승인자가 명시적으로 승인했다.

### 갱신·대체·폐기

- 갱신: - 자산·위협·데이터 처리·취약점·권한·법규 변경<br>- 연결된 상위 기준선·사용자 승인 결정·외부 의무 변경<br>- 검토에서 사실 오류·누락·stale 판정 또는 유효기간 만료
- 검토 주기: 변경 발생 즉시. 보안 정책·원장은 활성 프로젝트 동안 최소 월 1회, 실행 증거는 새 build·기기·환경·도구 결과마다 검토합니다.
- 변경: 정책·명세는 변경요청과 영향분석 뒤 새 버전을 만들고 이전 승인본을 `Superseded`로 보존합니다. 원장은 과거 행을 지우지 않고 상태변경 행을 추가합니다. 실행 증거는 손으로 고치지 않고 새 입력 형상으로 다시 생성합니다.
- 보존·폐기: 프로젝트 생명주기와 종료계획을 따릅니다. 개인정보·외부 원본은 SEC-07 보존표와 통제 저장소 삭제 영수증을 따르며 Git에 원본을 보관하지 않습니다.

### 갱신·대체·폐기

- 갱신: - 자산·위협·데이터 처리·취약점·권한·법규 변경<br>- 연결된 상위 기준선·사용자 승인 결정·외부 의무 변경<br>- 검토에서 사실 오류·누락·stale 판정 또는 유효기간 만료
- 검토 주기: 변경 발생 즉시. 보안 정책·원장은 활성 프로젝트 동안 최소 월 1회, 실행 증거는 새 build·기기·환경·도구 결과마다 검토합니다.
- 변경: 정책·명세는 변경요청과 영향분석 뒤 새 버전을 만들고 이전 승인본을 `Superseded`로 보존합니다. 원장은 과거 행을 지우지 않고 상태변경 행을 추가합니다. 실행 증거는 손으로 고치지 않고 새 입력 형상으로 다시 생성합니다.
- 보존·폐기: 프로젝트 생명주기와 종료계획을 따릅니다. 개인정보·외부 원본은 SEC-07 보존표와 통제 저장소 삭제 영수증을 따르며 Git에 원본을 보관하지 않습니다.

### 개인정보 영향평가 초안

승인된 정책은 동의한 활성 보행에서 무가림 원본을 수집하는 것입니다. 이 Draft는 그 결정을 재논의하지 않고 목적 제한·접근통제·보존·권리행사를 설계에 옮깁니다. 다만 출시 전 독립검토 gate는 `NOT_RUN`이고 법률 적합성을 확정하지 않습니다.

| 처리 | 필요성과 범위 | 주 위험 | 확정 통제 | 남은 확인 |

### 2026-07-27 프로젝트 수준 개인정보 영향평가

이 평가는 한이음 프로젝트가 설계·개발·통제된 시험을 준비하는 현재 단계의 `WS-PIA-20260727-001`입니다. 처리 주체와 최종 책임자는 프로젝트책임자 김민호이며, 실제 cloud 운영자·기관 전달자·법적 지위는 배포 형상이 확정될 때 다시 평가합니다. 이 평가는 법률의견, Google Play 승인 또는 실제 사용자 대상 처리 승인을 대신하지 않습니다.

#### 처리 범위와 수명

| 데이터 묶음 | 목적·필요성 | 기본 흐름 | 최소화·수명 통제 |
|---|---|---|---|
| 계정·session | 사용자와 기기 session 식별, 분실기기 폐기 | Android → gateway/backend → 계정·session 저장소 | opaque token은 digest 보존, 만료·폐기·계정삭제 상태 기록 |
| 정확 위치·목적지·경로 | TMAP 보행경로와 이탈·도착 판단 | Android → gateway → TMAP/backend → Android | 활성 길안내에 필요한 값만 전송, query 포함 access log 금지, 세션 종료 뒤 목적 외 사용 금지 |
| 영상·음성·센서·탐지·성능 | 실시간 안전 보조와 동의한 학습·품질 개선 | 기본 단말 처리, 동의한 원본만 암호화 queue → backend 통제 저장소 | 보행 중 일반 활동원본 전송 금지, 목적별 동의·용량상한·보존표·삭제 receipt 적용 |
| 자동신고 자료 | 손상 점자블록 검수와 기관 전달 준비 | 탐지 이미지·위치·판정 → backend → 관리자 검수 | 자동신고 별도 상태, 접근 최소화, 철회 뒤 새 후보 중단, 보존·삭제 결과 기록 |
| 관리자 audit | 고위험 작업·조회·상태변경 책임추적 | 관리자 앱/gateway/backend → append-only audit | token·원본을 audit payload에 넣지 않고 접근·보존 제한 |

#### 필요성·비례성 판단

- 실시간 안전 보조에는 카메라·위치·센서가 필요하지만, 가능한 처리는 단말에서 수행하고 서버 전송을 자동 전제로 두지 않습니다.
- 모델 개선 목적의 무가림 원본은 안전 보조 자체보다 침해 위험이 크므로 별도 목적·명시적 동의·전송 조건·삭제 경로와 출시 전 독립검토를 요구합니다.
- 주변인의 얼굴·번호판·목소리가 포함될 수 있어, 수집 활성화 전 고지와 접근제한을 적용하고 목적 달성에 필요하지 않은 공유·공개를 금지합니다.
- 외부 기관 자동 연계가 운영 중이라고 가정하지 않습니다. 기관 전달은 승인된 관리자 검수와 전달 절차가 마련된 범위에서만 수행합니다.

#### 위험·보호조치·잔여위험

| 위험 | 초기 위험 | 보호조치 | 잔여위험·판정 |
|---|---|---|---|
| 주변인 포함 무가림 원본의 과수집·유출 | CRITICAL | 명시적 동의, 보행 중 전송 금지, 암호화 queue, 최소권한, Git 원본 금지, 보존·삭제 receipt | HIGH. 독립 출시 검토 전 실제 서비스 수집 금지 |
| 위치·목적지로 생활패턴 추론 | HIGH | 세션 목적 제한, access log query 금지, 최소 보존, 권리요청·삭제 | MEDIUM. 실제 배포 log·보존 설정 검증 필요 |
| 동의 상태와 서버 처리 불일치 | HIGH | 목적별 상태, 정책 버전, idempotent sync, 실패 시 수집·전송 중단 | MEDIUM. offline·재시도·철회 E2E 필요 |
| 단일 관리자 계정 탈취·분실 | CRITICAL | MFA 설계, 기기별 session, 고위험 proof, audit, 작업 동결 | HIGH. 실제 복구훈련 전 사용자시험·배포 차단 |
| 대기열 초과로 예기치 않은 삭제·장기보존 | HIGH | 암호화 queue, byte limit gate, capacity-state contract, fail-closed 전송 | HIGH. 두 gate 전 용량 기준 확정 불가 |
| 오신고·잘못된 기관 전달 | HIGH | 제한된 신고 대상, 관리자 검수, 상태·audit, 사용자 권리 경로 | MEDIUM. 실제 전체흐름 시험 필요 |

정보주체는 접근 가능한 권리요청 경로에서 동의 철회, 계정·연결 데이터 삭제와 처리 결과를 요청할 수 있어야 합니다. 거부·철회가 안전 핵심 기능을 불가능하게 만들면 앱은 이유를 알리고 안전정지하며, 이미 적법하게 처리된 자료의 보존 예외가 필요하면 항목·근거·기한을 별도로 통지합니다.

**평가 결론:** 현재 프로젝트 문서·개발 준비를 위한 영향평가 내용은 작성 완료입니다. 무가림 원본, 단일 관리자 복구, 실제 배포 형상의 잔여위험은 수용하지 않았고 관련 gate가 닫히기 전 출시는 `NOT_ELIGIBLE`입니다. 실제 처리 범위·보존·제공이 바뀌면 이 평가를 새 revision으로 다시 수행합니다.
