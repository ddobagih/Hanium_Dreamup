[발견사항과 조치]

  • DOC-D02-01 — 문서 오류, 해결 확인
    • P001의 TTL은 생성자 설정값이 아니라 CONFIRMATION_TOKEN_TTL_MS=30_000L const다. P018 최대 정리 시도는 MAX_STOP_DELIVERY_ATTEMPTS=3 private const다.
    • 수정본 두 mutable 필드가 코드 고정임을 명시했다. 값·경계 자체는 처음부터 코드와 일치했다.
  • DOC-D02-02 — 근거 범위 누락, 해결 확인
    • F016/P016이 최초에 Main 30953–30973 dispatcher만 인용하여 실제 support 조회·finally close·결과 저장 근거가 빠졌다.
    • 수정본은 continueRuntimeMetricPreflightStart 30974–31021과 finishDeviceMetricDepthSupportCheck 31023–31079를 추가했다.
  • DOC-D02-03 — 완료 의미 과장, 해결 확인
    • F032의 “drain ACK는 실제 worker 종료 뒤”는 result.complete(acknowledged)가 worker task 내부에서 실행되는 코드보다 강하다.
    • 수정본은 이전 in-flight/control task의 직렬 처리 뒤 quiescence ACK이며 executor terminated 보장은 아니라고 고쳤다. purge future의 삭제 성공과도 분리했다.
  • DOC-D02-04 — 완료 의미 내부 충돌, 해결 확인
    • F034 정상 종료 문장은 모든 owner 실제 close 후 Activity 반환처럼 읽혔으나 closeDetectorAsync() 등은 요청 후 비동기로 끝난다.
    • 수정본 JSON과 F034 도표 N이 cleanup 단계/요청·fence와 각 owner의 실제 release ACK를 분리했다.
  • DOC-D02-05 — 도표 대안 경로 오류, 해결 확인
    • 최초 F017은 UNSUPPORTED terminal→profile null UNKNOWN terminal→qualification AVAILABLE을 직렬 연결했다.
    • 작성자가 support/profile 분기에서 terminal을 별도 종료로 수정했다.
    • 재검토에서 일반 evaluator의 depthSupport == SUPPORTED 최종 성공 조건과 timestamp 0 대기를 추가 요청했고 최종 도표 C/F에서 해결을 확인했다. Main은 SUPPORTED로 생성하므로 이것은 현재 Main 오동작 지적이 아니라 일반 평가기 도표 조건 누락이었다.
