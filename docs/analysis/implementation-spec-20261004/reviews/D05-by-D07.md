## 발견 사항과 수정 요청

1. **R1 — 문서 오류 / F-D05-010·P-D05-010: hard cap의 예외 누락.**
   - 초기 steps의 “중간 frame은 연결 gap≤120ms일 때만 생략”은 `InterFrameDetectionTracker.kt:672-707`과 다르다.
   - 코드가 먼저 gap을 보존하는 unprotected 후보를 찾지만, 없으면 첫 unprotected, 그것도 없으면 index0을 제거해 상한을 지킨다. 따라서 연속성·source 보호가 무조건 보장되지는 않으며 후속 history/gap 검사가 실패 처리한다.
   - 요청: 안전 trim 우선과 강제 cap의 우선순위·실패 결과를 함께 기술.
2. **R2 — 도표 오류 / F-D05-010: 모든 invalid 입력을 clear로 표시.**
   - 초기 D05-F010.mmd의 epoch/key/pixels 실패가 일괄 clear로 향했다.
   - `InterFrameDetectionTracker.kt:84-125`에서 낮은 epoch·geometry와 순서 역행은 상태를 보존한 거절이다. 같은 identity의 pixel/key 충돌 또는 같은 context의 dimensions 변경은 clear한다.
   - 요청: 거절 보존과 충돌 초기화 분리.
3. **R3 — 도표 오류 / F-D05-002: uncached GPU 성공을 CPU로 표시.**
   - 초기 D05-F002.mmd의 “cache 없이 재시도 또는 CPU 허용” 노드가 CPU 생성으로만 향했다.
   - `GpuSerializationCache.kt:57-76`은 uncached GPU 생성 성공을 반환하며, `TfliteAndroidFrameDetector.kt:789-793`도 GPU delegate를 유지한다. `DelegateFallbackRuntime.kt`의 CPU fallback은 별도 조건이다.
   - 요청: uncached GPU 성공·실패와 CPU fallback 경로 분리.
4. **R4 — 도표 누락 / F-D05-013: CPU init 실패 경로.**
   - 초기 D05-F013.mmd에서 CPU init 뒤 READY만 있었다.
   - `TfliteFastSamEngine.java:237-240`은 CPU 생성 실패를 전파하며 service는 terminal failure/해제로 진행한다.
   - 요청: CPU 초기화 실패에서 FAILED/STOPPING으로 연결. uncached GPU 재시도 성공도 실제 backend대로 표현.
   - 1차 수정본에서 SHA·deadline·tensor 검증 실패까지 CPU fallback으로 향하는 추가 도표 오인을 발견했다. `TfliteFastSamEngine.java:42-78,207-241`에 따라 native GPU 생성 실패만 재시도/fallback할 수 있도록 분리 요청했다.
5. **R5 — 시험 추적성 / F-D05-007·F-D05-014·F-D05-019.**
   - 구조 검사에서 세 기능의 tests가 빈 배열이었다. F014는 이 발견 외 decoder 전체 의미 검토 대상이 아니다.
   - 요청: 기존 독립 시험의 검증 기대를 연결하거나 연결 부재·미검증을 명시. 인접 helper 시험은 Main 전체/기기 시험으로 기술하지 않아야 한다.
6. **R6 — 도표 추적성 / 24개 기능.**
   - 기능에 연결된 Mermaid 원문에서 F002, F003, F005..F026에는 P-D05 식별자가 없었다. F001·F004만 정책 ID가 있었다.
   - authoring brief의 기능/정책 ID 표기 기준에 따라 정책 ID 연결 요청. 이는 형식·추적성 검사이며 해당24개 기능 전체 내용 검토를 뜻하지 않는다.

- 위 항목은 문서·도표·추적성 문제다. 이 검토만으로 별도 제품 결함을 확정하지 않았다.
- 실행 미확인: GPU/CPU 실제 backend 지원, Native 해제 완료 시간, LK 성능, TTL 안의 처리 성공, 장치 UI·안전성은 판단하지 않았다.
