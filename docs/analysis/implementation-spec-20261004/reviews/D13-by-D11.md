### F-D13-017 / P-D13-017 서버 삭제 worker

- HTTP 작업이 아니라 전용 DB role/동일 filesystem/maintenance lock을 요구하는 one-shot이다. run_once는 모든 기존 journal을 먼저 reconcile한 뒤 bounded pending batch를 처리하고 한 요청 예외는 전파한다. 내부 무한 retry는 없다.
- process_request가 request identity를 재확인하고 subject/storage/capacity lock 및 RAW pending write를 확인한다. PREPARED journal→파일 quarantine→DB row 삭제→외부사본수 재조회와 inventory0→DB commit→후처리 순서를 확인했다.
- commit_attempted 이전 실패는 파일을 원복한다. commit acknowledgement가 모호하면 임의 원복하지 않고 다음 reconcile에 맡긴다. journal PREPARED이면서 실제 row count가 기대치와 같을 때만 RESTORED, 전부0이면 후처리를 계속하고 부분 삭제/불일치는 거부한다.
- 후처리에는 객체 삭제 후 DB0/tombstone1/item9/보존 signup receipt/동의 대상 검증, create-only manifest, 서버상태 반영, quarantine/journal 정리가 있다. manifest 생성이 전체 계정 삭제 완료를 뜻하지 않는 설명은 맞다.
- 본문/선택 도식 핵심 흐름 일치. timeout 일반문구는 전역 job timeout 부재로 좁게 해석하며, 본문에 기록된 lock1..300초를 없애지 않는다. 실제 systemd15분/stop30초 배치는 D11 연결 범위다.
- 판독: `scripts/account_deletion_worker.py:2171-2263,2264-2489,2515-2578`; `privacy_lifecycle.py:2725-2885`. 파일 검증/권위/SQL inventory helper 전체는 독립 재감사하지 않았다.

### F-D13-026 / P-D13-026 RAW chunk

- raw flag, FIELD actor와 request-bound proof, exact application/octet-stream, 누적8MiB, 실제 Content-Length/hash 확인 뒤 anyio thread로 guard와 storage를 호출한다. 선언 Content-Length의 ge/le validation과 누적 초과413은 서로 다른 경계다.
- shared maintenance lock과 subject ingest fence/consent chain 재검증 뒤 storage write lock과 collection 행 잠금이 적용된다. manifest/owner/purpose/walk/receipt/index 결속, exact chunk 재생, 완료 candidate의 object digest 검사, key synchronize와 AES envelope journal→file→DBcommit→cache→journal 정리를 확인했다.
- 신규 ack201/정확 재생200, 일부 수신 응답 RECEIVING와 전체 DB READY_TO_COMMIT, digest_rejected 영속 표지와 모호한 commit503 설명은 맞다.
- RV-01 도식은 수정본에서 해결 확인했다. HTTP 취소 시 worker thread 내부 atomicity나 실제 filesystem crash recovery 성공은 실행하지 않아 확인하지 않았다.
- 판독: `api/raw_collections.py:97-225,253-287,617-684`; `services/raw_collection_ingest.py:180-253`; `raw_collection_storage.py:2736-2955`. 암호 primitive/하위 FD publish/검증 cache 전체는 미검토다.

### F-D13-039 / P-D13-039 dataset revision 승인

- dataset 단위 advisory transaction lock, latest parent CAS, nonempty/중복/누락/split 검사, source tombstone/current consent/exact receipt, canonical sorted member-set digest, DB whole-second 승인시각+달력3년, APPROVED 생성 및 parent RETIRED event를 같은 commit에 넣는 설명이 일치한다.

### F-D13-042 / P-D13-042 training retention

- ACCOUNT_DELETED→CONSENT_WITHDRAWN→모든 연결 expiry<=as_of 순서, 빈 expiry 목록의 비삭제, exact receipt가 바뀌면 consent 사유 후보, envelope hash/size, apply FOR UPDATE를 확인했다.
