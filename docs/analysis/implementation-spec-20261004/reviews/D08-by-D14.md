[발견 사항과 조치]

1. **RV-01 — 로그인 제한 우선순위 오기, 문서 오류.** 최초 F009/P006/도표는 IP→global→total→capacity로 적었으나 `auth.ts:1503` 부근에서 capacity를 먼저 검사한다. `:1528–1533`은 IP와 global의 더 늦은 blockedUntil을 적용하고 동률은 global code를 택한다. 1차 수정본에서 실제 순서로 고쳐졌음을 확인했다.
2. **RV-02 — v4 서명키 설명 오기, 문서 오류.** 최초 F059는 “HMAC 목적파생키”라고 했으나 `backend.ts:524,556`은 설정된 session secret을 직접 HMAC 키로 사용한다. `:506–510`의 고정 label HMAC은 kid 계산이다. JSON과 F059 도표가 이를 구분하도록 수정되었다.
3. **RV-03 — refresh의 Backend 우회·폐기 범위가 상태도에서 소실, 문서 오류.** `field-long-session.ts:1580`은 검증된 consumed proof면 Backend current를 조회하지 않는다. legacy refresh도 별도 Backend 확인이 없다. 또한 reused proof는 활성 actor의 전체 family/short 세션 폐기로 이어지지만, Backend denied·만료·회전 상한은 해당 family만 폐기한다(`:1599–1638`). 최종 JSON과 상태도·sequence에서 우회와 family-only 폐기 분리를 확인했다. 추가로 `routes.ts:817`의 cookie scope 확인이 refresh admission보다 먼저 상태를 읽을 수 있으므로 “제출 refresh family의 본검사/잠금 전”으로 한정했다. `field-long-session.ts:1070–1086,1168–1182,1666–1670` 및 `auth.ts:973–984`에 따라 long 전체 폐기+reuse watermark는 같은 write, short 정리 callback은 actor lock 밖이며 실패할 수 있고 short는 watermark 검사로도 무효화된다고 보완한 것을 확인했다.
4. **RV-04 — 원문 식별자 불일치와 legacy 참조 범위 누락, 문서 오류.** `acquireFieldSessionRefreshAdmission`→`admitFieldSessionRefresh`(`refresh-admission.ts:122`), `createAccountDeletionOutboxWorker`→`AccountDeletionOutboxWorker`(`account-deletion-outbox-worker.ts:2`), `actorAssertionV4`→`createBackendActorAssertionV4`(`backend.ts:521`), legacy refresh 함수 범위 `field-long-session.ts:1402–1524` 추가를 확인했다. F009의 `loginAdmission/recordCredentialFailure`도 최종본에서 실제 `gatewayLoginAdmission/gatewayLoginFailure`(`routes.ts:757,769`)로 고쳐졌다.
5. **RV-05 — static token payload 및 recovery scope 설명 오기, 문서 오류.** static token allowlist에는 `remember_me`가 없다. recovery도 generation/fence를 거치며 concealed report는 404를 반환한다. `routes.ts:1106–1110,1138–1145,2944–2945`와 수정된 입력·단계·분기를 대조했다.
6. **RV-06 — unknown409 전용 카운터처럼 적은 재시도 임계, 문서 오류.** `markOperationRetry`(`privacy-deletion-v2.ts:1938–1951`)와 unknown409 처리(`:2049–2050`)는 같은 `operation.attempts`를 증가시킨다. 이전 일시오류가 누적됐다면 첫 unknown409에서도 terminal이 된다. 수정본의 단계·P020 임계·state도표에 누적값임이 반영되었다.
7. **RV-07 — flock helper timeout 오류 유형과 queue 분기 도표, 문서 오류.** `exclusive-file-lock.ts:176–191`의 timeout은 SIGKILL/close 후 IntegrityError이며 exit1만 BusyError다. `run`과 `runPriority`는 하나의 순차 처리 흐름이 아니다. P024 및 F048 도표에 분리된 분기가 반영되었다.
8. **RV-08 — 장기 세션 기본 활성처럼 보이는 상태 표기, 문서 오류.** `config.ts:171–176`은 미설정/false에서 기능을 반환하지 않는다. F010/F011의 `ACTIVE`와 공통 전제만으로는 이를 알 수 없었다. 수정본은 `CONDITIONAL`과 구체 설정 전제 및 503 비활성 결과를 명시한다. 운영 환경값은 확인하지 않았다.
