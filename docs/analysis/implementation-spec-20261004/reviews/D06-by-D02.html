DOC-D06-R01 문서 오류 F007 도표가 기존 receipt 처리 뒤 404 POST로 직렬 연결되었고 cleanup은 없다고 적혔다. 최초 수정 도표에는 status HTTP 오류의 공통 catch도 빠졌다. status existing/404 분리, JSON에 finally/exact outer/nested cancel 추가, status·POST 모두 QUAR/AUTH/RETRY로 분기하는 최종 D06-F007 확인.
DOC-D06-R02 문서 오류 F009 full purge → fresh key → automatic-only purge가 하나의 순서처럼 그려져 목적별 철회의 차이가 사라졌다. 전체 철회·자동 opt-out·계정삭제 등 요청 종류를 나눈 D06-F009 확인.
DOC-D06-R03 문서 오류 F023 전체 전제에 RAW_CONTINUED 조건이 들어가 철회·null·버전 gap을 배제했고, continuity → revoke → account delete가 직렬 연결되었다. 일반 이벤트 진입 전제와 CONTINUED의 전체 조건을 분리하고 continuation/철회/policy/account 이벤트를 나눈 JSON·D06-F023 확인.
DOC-D06-R04 문서 오류 F004/P004 및 explicit 상태도에 TTS 경로만 있어 ON_SCREEN draw 전달 경로가 빠졌다. VOICE onCompleted와 ON_SCREEN 첫 OnDraw → posted delivered 및 문맥 재검사를 JSON·정책·상태도에서 확인.
DOC-D06-R05 문서 오류 D06-F029의 >= 치환이 초과 =로 표시되어 archive index와 활성 age 경계가 흐려졌다. index 20 이상·활성 age 14일 이상, 완료 age 14일 초과로 구분한 최종 도표 확인.
DOC-D06-R06 문서 오류 F029 일반 보존→전체 purge→재동의가 직렬로 연결되었다. 재작성 도표가 healthy raw 재동의에도 verified purge 증거를 요구했고, 공용 실패 노드는 모든 실패에 marker 삭제를 적용하는 것처럼 보였다. retention/purge/reset/debug purge 분리, healthy raw-fence 경로와 verified/enrollment 경로 분리, 실패 라벨을 purge와 reset 경로별로 구분한 JSON/P027·최종 D06-F029 확인.

[미검토와 증거 한계]

  • D06 나머지 30개 기능의 전제·분기·정책·도표는 독립 전수 검토하지 않았다. 전체 inventory 확인이나 인접 호출 읽기를 해당 기능 검증으로 세지 않았다.
  • P024는 F029 보존 한도와 관련 부분, P028은 F032 export binding 관련 부분만 확인했다. P008의 모든 protocol parsing, report/raw 암호 저장 내부 전체, 녹화/프레임 수집, recorder live 수집·복원, debug 측정, 외부 provider/server/API 실제 동작은 미검토다.
  • 관련 state/sequence도는 표에 적은 기능 연결·분기만 확인했다. 예를 들어 D06-fieldlog-state의 ACTIVE 측정/복원 전체는 이번 독립 검토 범위가 아니다.
  • 테스트 경로·기대는 제품 실행 결과가 아니다. 이 리뷰에서는 테스트 본문 전체 재검토나 테스트 실행을 하지 않았다. 실제 SAF/파일시스템 장애/계정삭제 경쟁/네트워크 재접속/음성 청취 결과는 미확인이다.
  • SVG 렌더·레이아웃·도표 전체 연결 검사와 도메인 간 통합은 Root의 별도 검증 대상이다. 이 기록은 아래 버전에서 검토한 범위의 코드-명세 대조 근거다.
