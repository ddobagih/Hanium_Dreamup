# D14 독립 명세 검토 — D15 작성자

[판정]

- 선택한 핵심 9개 기능의 입력·수치·반환·transaction 경계와 11개 Mermaid 원본을 대조했다. 문서 수정 요청 3건은 작성자의 수정본에서 해결됐음을 재확인했다.
- 전체 33개 기능의 전수 정확성을 승인한 검토가 아니다. 알려진 제품 정적 연결 불일치 R-D14-008과 미실행 범위는 유지한다.
- 제품 코드·대상 JSON·Mermaid는 직접 수정하지 않았다. 이 검토 파일만 작성했다.

[기준 버전]

- 고정 코드: `/tmp/walksafe-spec-20261004-source`, 2026-10-04T10:33:40+09:00, base `2e5744725a8c033a1817f3cc8a8ec679bc15ac9d` 및 WIP snapshot.
- 시작 D14 JSON SHA256: `afe1b0e4e9423c3e586ae38a437fff340f890fe8ebffc7517820e688fa26c952`.
- 중간에 작성자가 요청 3건을 수정했다. 영향 범위 F-D14-026·F-D14-033의 JSON·도표를 다시 읽고 실제 코드와 대조했다.
- 종료 D14 JSON SHA256: `684f009acbd721bb09e28bccf834386b7d1cb400d49153139872b1ff3f4a4d45`.
- 검토자는 별도 D15 작성자이며 D14 작성자와 다르다. 대상 기능 상태 CONDITIONAL과 운영 설치·기기·외부 보장 분리를 확인했다.

[도표 대조]

- 실제 읽은 Mermaid 원본: `D14-F001.mmd`, `D14-F007.mmd`, `D14-F008.mmd`, `D14-F016.mmd`, `D14-F017.mmd`, `D14-proof-state.mmd`, `D14-F019.mmd`, `D14-F020.mmd`, `D14-security-sequence.mmd`, `D14-F026.mmd`, `D14-F033.mmd`.
- `D14-proof-state.mmd`: 발급/소비/논리만료를 구분하며 만료 행 물리삭제를 주장하지 않는다. consumed 검사는 시간검사보다 우선한다.
- `D14-security-sequence.mmd`: nonce commit→ACTION proof 소비→같은 identity의 route 호출 순서 및 step_up None403 분기가 JSON·교차 source 관찰과 일치한다. 모든 관리자 쓰기가 이 timestamp 검사로 실패한다고 확대하지 않는다.
- 수정된 F026 도표는 failure helper의 사전 metadata 구성을 별도 분기로 두며 일반 감사에 alert가 무조건 붙지 않는다. 수정된 F033은 try 이전/try 내부/yield 이후 예외 경계를 나눈다.
- 이 리뷰에서 Mermaid parser 또는 시각 렌더를 직접 실행하지 않았다. 작성자의 39개 parse/render 성공 메시지는 별도 수행자의 보고이며 본인의 실행 증거로 사용하지 않았다.

[발견사항과 수정 확인]

- C1 — 문서 연결 오류, 해결: F033 cleanup/도표의 운영 도구 담당 `D16`을 `D11`로 교정하도록 요청했다. 종료 SHA에서 JSON과 F033 도표 모두 D11을 확인했다.
- C2 — 문서 처리 순서 오류, 해결: 기존 F026 도표의 `commit→failure helper alert fields` 직렬 흐름은 코드와 달랐다. `record_admin_security_failure`는 details를 `_append_admin_security_audit`에 먼저 전달한다. 종료 SHA에서 `helper 분기→details→검증/hash/flush→caller별 commit`으로 교정된 것을 확인했다.
- C3 — 문서 예외 범위 오류, 해결: F033의 모든 진입 전 예외를 frozen으로 변환한다는 문구와 SQL 오류→HTTP503 기본문구가 CLI 계약을 과장했다. 코드의 action/enabled/필수입력 검사는 try 밖 자체 RuntimeError, try 안 mutation scope 진입 전 오류만 frozen, yield 이후 오류는 원예외다. 종료 SHA에서 JSON·도표·failure 계약의 교정을 확인했다.
- P1 — 알려진 제품 정적 연결 불일치, 유지: R-D14-008의 재확인 timestamp NULL→기존 identity 반환→특정 업무 context403은 D15 caller(admin_reports.py:147-172, :776-898; report_user_requests.py:245-285, :1301)와 대조된다. 제품 코드 수정이나 실제 HTTP/PostgreSQL 재현은 이 문서 작업에서 수행하지 않았다.

[실제 검증과 미검토]

- 실제 수행: JSON 읽기·SHA256 계산, 지정 코드와 SQL 조각의 정적 열람, 11개 도표 원문 대조, 수정본의 영향부분 재검토. 비밀키·토큰·실제 사용자 자료 열람 없음.
- 제품 시험/빌드/서버/CLI 운영 호출/DB migration/외부기관·기기·HSM 검증은 실행하지 않았다. 테스트 본문이나 과거 DONE 기록을 이번 통과 실적으로 인용하지 않았다.
- 미검토: 나머지24개 기능 상세, 복구 transaction/token rotation 전체, 모든 PG security-definer·ACL·trigger DDL, 모든 감사 projection, 전체 네트워크 미들웨어와 Android 기기서명 구현. 선택한 코드의 호출자 전수·동시성 및 보안 독립감사도 이 검토 범위가 아니다.
- Root가 전체 산출물 통합과 완료 판정을 담당한다. 현재 리뷰의 세 문서 수정요청은 해소됐으나 제품 정적 불일치/운영 미검증을 DONE으로 전환하지 않는다.
