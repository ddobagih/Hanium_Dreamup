## 코드 대조 결과

경로는 모두 고정 snapshot의 `apps/android/app/src/main/java/kr/co/hanium/dreamup/walksafe/` 기준이다. 다음의 통과는 나열한 주장의 정적 일치를 뜻한다.

1. **F002 / P002 — 위치 신뢰·시각과 이동 방위: 통과.** `navigation/LocationPolicy.kt:33–138`, `NavigationTestLocationPolicy.kt:4–17`, `MainActivity.kt:43554–43563`을 대조했다. 좌표·mock·accuracy 검증, 이전 위치가 있을 때 시간과 거리 일관성, `freshOrNull`의 별도 10초 age 검사가 구분된다. 보고된 bearing은 speed≥0.3m/s이고 bearing accuracy가 **없거나** 유효한 0–35도이면 사용 가능하다. 명시적 speed=0에서는 displacement fallback을 쓰지 않으며, 변위 방향은 최소 3m와 두 accuracy 합을 고려한다. helper의 조건을 GNSS estimator 전체 입력 정책과 혼동하지 않는지 확인했다.
2. **F010 / P010 — route compass fallback과 PDR 분리: 통과.** `navigation/RouteCompassHeading.kt:104–121,211–426`, `RouteCompassSensorState.kt:191–302`, `AndroidEarthOrientationTracker.kt:74,136–157,211–225`를 대조했다. gravity+magnetic 우선 평가, 없을 때 가속도 200ms 구간의 서로 다른 3개 표본과 tilt≤10도, 시간 age≤500ms 및 각속도에 따른 skew bound, magnetic 강도·수평비·inclination 검사 순서를 확인했다. 새 저품질 rotation-vector가 있는 동안 fallback을 막는 상태와 회복 조건이 있다. route용 fallback 조회가 strict PDR heading 공급 경로로 둔갑하지 않는다. SensorThread callback과 synchronized 조회 경계도 확인했다.
3. **F015 / P015 — GNSS downweight와 지연 fix 재생: 통과.** `navigation/positioning/PedestrianPositionEstimator.kt:162–231,306–445,587–673,954–978,1256–1290`, `PositioningCoordinator.kt:102–108,187–270`, `MainActivity.kt:44487–44556`을 대조했다. 관측 age≤10초, accepted GNSS 중복·역순 거절, hard corrupt jump와 soft Mahalanobis gate 5.991, informative weight≥0.25, posterior uncertainty 2/5/15m와 informative clock이 구분된다. 지연 GNSS는 5초 이내와 보존 checkpoint를 요구하고, 삽입 실패 또는 retained replay 실패 시 state/history를 원복한다. measurement-time estimate와 현재 estimate를 구분한다. fresh 추정에 대한 첫 독립 CORRUPT_JUMP만 Main이 유지하며, 연속 거부 등은 fail-closed로 처리한다. debug navigationTestFix 예외는 production 동작과 구분한다.
4. **F016 / P016 — PDR 원 측정시각·owner gate·rollback: 통과.** `PedestrianPositionEstimator.kt:452–586,676–915` 및 `PositioningCoordinator.kt:273–392`를 대조했다. owner/generation, step 원 시각과 receipt 지연≤2초, 양의 유효 보폭, 중복·count≤64, heading conflict와 turn 조건을 확인했다. 이미 commit된 시각보다 과거인 입력은 방향 품질 검사보다 먼저 2초 지연/history gate를 거친다. LOW/no heading도 이 순서를 우회하지 않는다. 유효 directed 입력의 위치·공분산 갱신과 velocity extrapolation 중단, undirected 입력의 평균 유지·공분산 증가 및 extrapolation flag 미변경을 구분했다. retained 이벤트 재생 실패 시 기존 state/history를 복구하는 제어 흐름을 확인했다. 전체 행렬 수학의 독립 재유도나 모든 수치 경계 테스트는 하지 않았다.
5. **F019 / P019 — 보정 입력 watermark와 irreversible rejection: 통과.** `TimestampAlignedWalkingCalibration.kt:18–203`, `MainActivity.kt:43956–43974,45052–45110`을 대조했다. HIGH 단일 hardware step·엄격한 step 원 시각·receipt≤2초, bounded history/pending queue, accepted non-downweighted raw GNSS와 fresh MOVING 근거를 보정 입력에 한정한다. newestStep≤fix 시각이면 WAITING 상태로 pending 유지한다. newestStep>fix가 되면 dequeue 후 `before≤fix<after`의 bracket 유무, gap≤2초, 확인 wait≤2초를 검사하며 실패는 segment reset+REJECTED이다. 이 실패를 무기한 대기로 표시하지 않는지 세 도표에서 확인했다.
6. **F020 / P020 — 직선 raw segment 보정 승인: 통과.** `WalkingCalibrationSegmentPolicy.kt:42–269` 및 `WalkingCalibrationEndpointEvidence.kt:4–24`를 대조했다. raw age≤500ms, accuracy>0..3m, speed 0.6..2.4m/s, speed accuracy≤0.35와 speed−accuracy≥0.4m/s, bearing accuracy≤15도를 확인했다. fix gap≤2.5초·segment≤60초·step silence≤2초, coarse reversal/lateral corridor 및 course spread≤15도, 충분한 거리의 course agreement≤20도, 최소 20걸음·10초·max(15m,5×endpoint uncertainty) 이동, 속도 적분 일치 조건을 비교했다. 완료 endpoint를 다음 segment 시작으로 사용하여 구간이 겹치지 않는 흐름을 확인했다. 실제 보폭 보정 성능은 미검증이다.
7. **F027 / P027 — RAW motion 집계 소비 경계: 통과.** `MotionStateAggregate.kt:6–161`, `MainActivity.kt:28183–28220`, `rawcollection/RawRuntimeWindowAccumulator.kt:103–110`을 대조했다. ACTIVE walk epoch 검사와 RAW 동의 뒤 read-only `peekUserMotion`을 사용하므로 navigation motion publication을 새로 수행하지 않는다. reason count와 유효 timing 집계를 구분하며, generation 변화는 이전 interval 연결을 끊는다. 만료된 이전 snapshot의 interval은 UNKNOWN으로 집계한다. `summary()`는 별도 조회이고 `resetWindow()`는 Unit 반환·구간 통계 초기화·이전 표본 유지, `resetAll()`은 모두 정리하는 차이를 확인했다.
8. **F028 / P028 — 전송 전 정지 helper의 미연결 상태: 통과.** `TransferStationaryEvidencePolicy.kt:12–34`와 `src/main` 전체 심볼 검색을 대조했다. 현시점과 동일한 evaluate 시각, STATIONARY/확정 reason, non-null 원 센서 시각과 만료 여부, 연속 상태·quiet 근거 각각≥5초를 요구한다. 함수 선언 외 production 사용처가 없어 **UNCONNECTED**가 맞다. 실제 전송 큐가 이 gate를 통과하거나 정지 상태까지 자동 대기한다고 단정하지 않았다.

## 미검토와 남은 통합 책임

- D04 38개 기능 중 위 8개만 독립 검토했다. F001/003–009/011–014/017–018/021–026/029–030은 이번 검토 대상이 아니다. 해당 코드가 연관 경로에서 일부 보였더라도 기능 전체 검토로 계산하지 않았다.
- 작성자가 별도 추가한 debug `OutdoorPositionTestActivity` 기반 F031–F038은 이 검토 범위에서 제외한다. 다른 검토 결과와 합칠 때 담당·버전을 구분해야 한다.
- RouteNavigator의 경로 정책, D03 음성·검색·경로, 다른 도메인의 motion consumer 전체, 센서 firmware/native 동작과 모든 테스트 코퍼스, 부동소수점 수학의 완전한 증명은 미검토다.
- 현장 위치 정확도·센서 freshness의 실제 지연 분포·PDR 오차·보행 보정 품질·전송 행동을 실행으로 확인하지 않았다. 코드 조건의 존재만으로 안전성이나 성능이 입증되었다고 해석하면 안 된다.
- Root가 다른 도메인·신규 debug 검토와 통합하고 전체 인수 조건을 판정한다.
