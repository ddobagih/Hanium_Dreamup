# 상태와 동시 실행의 연결

[전체 목차](README.md) · [주요 시나리오](05-scenarios.md) · [정책 목록](03-policies.md)

프로젝트 전체에 하나의 공통 상태 기계나 전역 실행 순서를 새로 정의하지 않는다. 앱 UI·보행 세션·음성 서비스·카메라·네트워크 요청·저장 queue·서버 transaction·별도 worker는 각자의 상태와 소유권을 가진다. 아래는 실제 분야 명세의 상태/비동기 처리 계약을 모은 색인이다. S- 접두어와 일부 처리 단계 이름은 추적용 문서 별칭이며 실제 enum 이름이라고 단정하지 않는다. 구체적인 이벤트·초기 상태·허용/금지 전이·우선순위·시간 경계는 각 상세 링크를 따른다.

특히 현재 화면/actor/session 세대 검증, stale timestamp 처리, queue/worker 직렬화, 단회 토큰·멱등성, deadline·취소·late callback, 종료와 자원 해제 확인은 서로 대체할 수 없다. 일부 기능에서 보장되는 규칙을 다른 기능이나 전역 정책으로 일반화하지 않는다. 명시되지 않은 정책 충돌 순서는 미정의/미확인으로 남긴다.
