# 모델 v1 데이터셋 계획

## 목표

모델 v1은 시각장애인 보행 중 실제 충돌 또는 낙상 위험으로 이어질 가능성이 높은 객체만 탐지한다. 초기 버전에서는 클래스 수를 늘리지 않고, 데이터 수집과 라벨링 품질을 우선한다.

## 한국 기준 원칙

실제 모델 v1의 기본 대상은 `datasets/walksafe_kr_v1`이다. 한국 보행 환경에서 동작해야 하므로 validation/test는 한국 직접 촬영 데이터 또는 한국 인도보행 데이터셋만 사용한다.

해외 공개 데이터로 변환한 `datasets/walksafe_v1`은 데이터 로딩, 라벨 파싱, smoke training, pretrain 후보로만 사용한다. 최종 정확도와 시연 품질은 한국 기준 데이터로 다시 평가한다.

점자블록은 한국 점형/선형 점자블록과 국내 보도 환경을 기준으로 판단한다. 정상 점자블록은 `damaged_tactile_block`으로 라벨링하지 않고, 빈 label 파일을 가진 negative 이미지로 확보한다.

## 클래스 정의

| ID | 클래스명 | 포함 대상 | 제외 대상 |
| --- | --- | --- | --- |
| 0 | `damaged_tactile_block` | 파손, 단절, 규격 불량 점자블록 | 정상 점자블록, 단순 그림자 |
| 1 | `parked_kickboard_bicycle` | 보행로에 방치된 킥보드, 자전거 | 정상 주행 중인 자전거, 차도 위 이동수단 |
| 2 | `construction_obstacle` | 공사 구조물, 안전콘, 임시 펜스, 불법 적치물 | 고정된 건물, 벽, 일반 가로수 |
| 3 | `pothole` | 보행로 포트홀, 꺼짐, 깊게 패인 구간 | 단순 얼룩, 얕은 색상 차이 |

## 데이터 후보 출처

1. 직접 촬영 데이터
   - 스마트폰을 가슴 높이 또는 목걸이형 바디캠 높이에 맞춰 세로로 촬영한다.
   - 실제 PWA 사용 환경과 가장 가까우므로 v1에서 가장 중요하다.

2. 한국 인도보행 데이터셋 후보
   - AI Hub 또는 SideGuide 계열의 한국 보도/인도 데이터셋을 우선 검토한다.
   - AI Hub `보행 안전을 위한 도로 시설물 데이터`는 점자블록 양호/불량, 보도/보도블록 파손 데이터 후보로 우선 검토한다.
   - AI Hub `인도(人道) 보행 영상`은 인도보행 장애물과 노면 상태 후보로 검토한다.
   - AI Hub `1인칭 시점 보행영상`은 스마트폰/PWA 사용 시점과 가까운 데이터 후보로 검토한다.
   - 계정, 이용약관, 원본 반출 제한을 확인한 뒤 사용한다.
   - 한국 데이터는 validation/test 후보가 될 수 있으나, 클래스 매핑과 라벨 품질을 직접 확인한다.

3. 공개 보조 데이터셋 후보
   - 도로 파손, 포트홀, 공사 장애물 데이터셋은 smoke test 또는 pretrain 후보로만 검토한다.
   - 라이선스와 촬영 시점이 프로젝트 목적에 맞는지 확인한 뒤 사용한다.
   - 보행자 1인칭 시점이 아니거나 한국 환경이 아니면 최종 validation/test에서 제외한다.

4. 합성 또는 증강 데이터
   - 데이터 부족 클래스에 한해 밝기, 흔들림, blur, crop 증강을 적용한다.
   - 실제 객체 형태가 바뀌는 과한 합성은 v1에서는 사용하지 않는다.

## 한국 데이터 확보 우선순위

1. `damaged_tactile_block`
   - 가장 시급하다. 현재 공개 baseline에는 이 클래스가 0개다.
   - AI Hub `보행 안전을 위한 도로 시설물 데이터`의 점자블록 양호/불량 데이터를 최우선 후보로 쓴다.
   - 파손/단절/탈락/매립/오염/잘못된 방향 연결 사례를 모은다.
   - 정상 점형/선형 점자블록 negative 이미지를 함께 모은다.

2. `parked_kickboard_bicycle`
   - 한국 공유 킥보드와 자전거가 점자블록 또는 보행 동선을 막는 사례를 우선 수집한다.
   - 단순 차도 주행 자전거는 제외한다.

3. `construction_obstacle`
   - 한국 보도 공사 안전콘, 임시 펜스, 공사 표지판, 적치물, 이동식 간판을 모은다.
   - 안전콘 하나만 많은 데이터로는 클래스가 좁아지므로 실제 공사 구조물을 보강한다.

4. `pothole`
   - 도로 포트홀보다 보도/이면도로 꺼짐과 깨진 보도블록을 우선한다.
   - 빗물, 얼룩, 그림자만 있는 이미지는 negative로 분리한다.

세부 기준은 `docs/korean_data_strategy.md`를 따른다.

## Smoke training 결과

1 epoch smoke training으로 데이터셋이 실제 YOLO 학습 루프에 들어가는지 확인했다.

- 모델: `yolo11n.pt`
- 환경: CPU, Apple M1
- 목적: 성능 평가가 아니라 데이터 로딩, 라벨 파싱, 학습 루프 검증
- 결과: 학습/검증 루프 완료, corrupt image 0개

전체 baseline 성능 평가는 데이터 보강 후 별도로 실행한다.

## 직접 촬영 기준

- 각 클래스별 최소 200장 이상을 1차 목표로 한다.
- 낮, 흐림, 야간, 역광, 실내 복도, 지하철역 주변 등 조명 조건을 나눈다.
- 같은 객체를 같은 각도에서 반복 촬영한 이미지는 과하게 늘리지 않는다.
- 같은 장소에서 연속 촬영한 이미지는 한 split에만 둔다.
- 사람 얼굴, 차량번호, 상호명 등 민감 정보는 비식별 처리하거나 학습 데이터에서 제외한다.
- 위험한 장소에서 촬영할 때는 보행 보조자와 함께 진행한다.

## 라벨링 규칙

- 객체 전체가 보이면 전체 영역을 bounding box로 표시한다.
- 일부만 보이더라도 보행 위험 판단이 가능하면 보이는 영역을 표시한다.
- 너무 작거나 흐려서 사람이 구분하기 어려운 객체는 라벨링하지 않는다.
- 하나의 객체가 여러 클래스에 걸쳐 보이면 실제 위험 원인에 가장 가까운 하나의 클래스로만 라벨링한다.
- 좌표는 YOLO 형식인 `class_id x_center y_center width height`를 사용하고, 모든 좌표는 0~1 사이 정규화 값이어야 한다.

## 데이터 분할

- train: 70%
- val: 20%
- test: 10%

같은 장소에서 연속 촬영한 유사 이미지는 train, val, test에 섞지 않는다. 같은 장면이 여러 split에 들어가면 실제 성능보다 평가 점수가 높게 나올 수 있다.

## v1 완료 판단

- 데이터셋 구조 검증 스크립트가 통과한다.
- 한국 validation 기준 전체 mAP 0.9 이상을 목표로 한다.
- 실제 테스트 이미지 20장 이상에서 위험 객체 박스가 사람이 보기에도 납득 가능해야 한다.
- 성능이 낮은 클래스는 데이터 부족, 라벨 품질, 클래스 정의 문제 중 원인을 기록한다.
