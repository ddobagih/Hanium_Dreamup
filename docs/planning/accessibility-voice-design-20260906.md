# WalkSafe 접근성·음성 사용 설계

작성일: 2026-09-06 KST. 범위: Android 사용자 앱의 TalkBack, 교육·약관 읽기, 보행 음성 입력·출력. 상태: 공식 자료 조사와 기존 명령 선언을 바탕으로 한 구현 설계. 이 문서는 기능 구현·실기기 시험의 완료 증거나 승인 정책 변경이 아니다.

## 결정

**TalkBack은 화면 탐색·입력·본문 읽기를 맡고, 앱은 사용자가 요청한 콘텐츠 재생과 보행·위험·명령 결과를 말한다. 주 STT는 번들 Vosk 한국어 모델 하나, 주 앱 TTS는 Android 오프라인 한국어 음성 하나로 통일한다.** 화면 진입 때 모든 내용을 자동으로 읽는 별도 앱 음성을 추가하지 않는다. 교육의 실제 재생 완료 조건과 필수약관의 명시적 동의 조건은 유지한다.

| 용도 | 기본 담당 | 앱이 제공해야 할 조작·상태 |
|---|---|---|
| 화면·버튼·입력·오류·선택 상태 | TalkBack을 포함한 사용자의 접근성 도구 | 의미 있는 라벨, 역할, 선택·비활성 상태, 논리적인 탐색 순서, 접근 가능한 오류 설명 |
| 안전교육 듣기 | 사용자가 시작한 앱 TTS | 재생, 중단, 다시 듣기, 현재 재생 상태, 실제 완료 이후의 기존 확인 절차 |
| 회원가입 약관 읽기 | 접근 가능한 본문과 TalkBack, 선택 가능한 앱 TTS | 조항별 본문, 읽기 시작·중단, 필수·선택 구분, 독립된 동의 조작 |
| 보행 경로·객체·위험 안내 | 앱 TTS와 기존 짧은 음·진동 | 우선순위에 따른 짧은 안내, 현재 상태, 최신 경로 재청취, 일시정지·종료 |
| 음성 명령 결과 | 앱 TTS | 인식 대기, 선택 내용, 성공 또는 실패와 복구 방법을 한 번 안내 |

이 분담은 Android의 접근성 라벨·의미 정보 원칙과 TalkBack 자체 읽기 제어를 적용한 **WalkSafe 설계 판단**이다. TalkBack은 화면 내용을 읽고 문자·줄·문단 단위 탐색과 읽기 속도를 사용자 설정으로 제어할 수 있다. 앱의 자동 중복 낭독으로 이 제어를 덮어쓰지 않는다. [Android 접근성 원칙](https://developer.android.com/guide/topics/ui/accessibility/views/principles-views), [TalkBack 메뉴와 읽기 제어](https://support.google.com/accessibility/android/answer/6007066?hl=en).

## 사용자와 장착 조건

- 시각장애인 모두가 TalkBack을 쓰거나 음성 입력을 선호한다고 가정하지 않는다. 저시력 사용자의 확대·큰 글씨·대비, TalkBack 숙련도의 차이, 청각·발화 조건을 함께 고려한다. RNIB도 음성만 쓰는 기기, 큰 글씨와 음성을 함께 쓰는 기기, 물리 키패드를 선호하는 사용자를 구분한다. [RNIB 스마트폰 안내](https://www.rnib.org.uk/living-with-sight-loss/assistive-aids-and-technology/phones-and-tablets/what-is-a-smartphone/).
- 가입·약관·교육·권한·목적지 준비는 안전하게 멈춘 상태에서 한다. 보행 중에는 휴대전화를 세로로, 상단이 위를 향하고 후면 카메라가 바깥을 향하도록 고정한다. 화면을 만지기 위해 장착을 자주 풀도록 설계하지 않는다.
- 고정 방향은 이번 사용 조건이다. 장착 확인만으로 카메라·위치·자세 측정이 정상이라고 판정하지 않는다. 실제 센서·권한·기기 확인과 기존 보행 시작 조건을 유지한다.
- 자동 객체 설명은 카메라의 실제 관측 범위에 한정한다. 관측하지 않은 뒤쪽·사각지대, 불확실한 거리·방향을 확정적으로 말하지 않는다. 길안내 문장을 횡단 가능이나 장애물 부재의 보증으로 표현하지 않는다.
- 주변 소리를 들을 수 있는 출력 방식을 사용자가 선택할 수 있어야 한다. 특정 헤드폰이 항상 안전하다고 보장하지 않는다. RNIB는 주변 소리가 들리는 청취 방식을 권하며 GPS가 흰지팡이·안내견과 보행 기술을 대체하지 않는다고 설명한다. 이 자료의 과거 앱 가격·제품 상태는 이번 설계 근거로 사용하지 않는다. [RNIB GPS 안내](https://www.rnib.org.uk/living-with-sight-loss/assistive-aids-and-technology/navigation-and-communication/what-is-gps-navigation/).

## 주 엔진 선택과 한계

| 항목 | 결정 | 이유와 한계 |
|---|---|---|
| 주 STT | `vosk-model-small-ko-0.22` | 기존 번들 모델을 버튼 입력과 호출어 입력에 공통 사용한다. 입력 진입점별 엔진·결과 처리 차이를 줄이고 음성 인식에 인터넷을 필수로 만들지 않는다. |
| 주 앱 TTS | Android `TextToSpeech`의 실제 사용 가능한 한국어 오프라인 voice | 현재 기기에서 확인된 Google TTS 바인딩과 실제 선택 voice·재생 성공을 구분한다. 오프라인 한국어 음성을 선택·확인하고 실패하면 복구 상태를 알린다. |
| Android `SpeechRecognizer` | 기본 버튼 경로에서 Vosk로 통일하는 대상 | API 자체가 무조건 온라인인 것은 아니다. Android는 별도 기기 내 인식 API도 제공하지만 기기·언어별 가용성 확인이 필요하다. 기존 제공자별 동작 차이를 남긴 채 무조건 성공하는 fallback으로 간주하지 않는다. |
| 서버 Whisper·Qwen TTS | 별도 서버 경로로 유지하되 앱의 기본 음성 경로로 사용하지 않음 | 네트워크 지연·단절과 운영 의존성이 생긴다. 서버 코드의 기본 모델명을 실제 기기 버튼의 STT나 기본 앱 TTS로 표시하지 않는다. |

Vosk 공식 목록은 한국어 소형 모델을 82MB, Zeroth Test의 WER 28.1로 기재한다. 이는 해당 평가 데이터의 수치이며 WalkSafe의 지명·상호명·거리 소음 조건에서 측정한 정확도가 아니다. 따라서 이번 선택은 기존 오프라인 자산을 이용하는 일관성과 운영 조건에 따른 선택이며, 한국어 인식 정확도가 가장 높다는 결론은 아니다. 고유명사 오인식 시 이름·주소가 포함된 후보를 듣고 명시적으로 선택할 수 있어야 한다. 검색어를 바꾸거나 TalkBack 키보드·텍스트 입력으로 복구하는 경로도 유지한다. [Vosk 공식 모델 목록](https://alphacephei.com/vosk/models).

Android 문서는 일반 `SpeechRecognizer` 구현이 서버로 음성을 보낼 수 있고 지속 인식에는 배터리·대역폭 문제가 있다고 설명한다. Vosk 통일이 상시 마이크의 배터리 비용까지 제거하는 것은 아니다. TTS는 `Voice.isNetworkConnectionRequired()`로 네트워크 필요 여부를 확인할 수 있다. 엔진 초기화 성공·한국어 voice 존재·실제 합성 및 재생을 구분해야 한다. [SpeechRecognizer API](https://developer.android.com/reference/android/speech/SpeechRecognizer), [Voice API](https://developer.android.com/reference/android/speech/tts/Voice).

STT와 TTS가 오프라인이어도 목적지 검색·경로 계산·서버 인증 등 기존 네트워크 기능까지 오프라인이 되는 것은 아니다. Vosk score와 기존 Android confidence는 같은 확률 척도라고 가정하지 않는다. 점수가 없거나 부적절한 값을 확신으로 바꾸어 종료·확정·동의를 실행하지 않는다.

## TalkBack·교육·약관의 구체 동작

### 공통 화면

- 동일 기능은 TalkBack·터치·음성 진입점에서 같은 실행 조건과 상태 전이를 사용한다. 버튼의 동작·현재 상태를 접근성 정보로 제공하고, 아이콘만 있는 조작에는 목적을 설명하는 라벨을 붙인다. 장식은 탐색 대상에서 제외한다.
- 화면 제목, 본문, 입력, 현재 오류, 다음 조작의 순서로 탐색할 수 있게 한다. 긴 약관을 하나의 거대한 버튼 라벨로 합치거나 시각적 색상만으로 필수·선택·실패를 전달하지 않는다.
- 빠르게 바뀌는 탐지·위치 값을 매번 TalkBack 알림으로 보내지 않는다. 사용자가 확인하는 상태는 접근 가능하게 유지하고, 보행 중 자동 안내는 앱의 음성 우선순위를 거친다.
- 접근성 서비스 활성 여부로 교육·보행 TTS를 통째로 끄거나 UI 기능을 숨기지 않는다. `isTouchExplorationEnabled()`는 TalkBack 식별자도 발화 중 신호도 아니다. Android는 이 상태에 따라 별도 UI·행동 경로를 만드는 접근을 피하라고 안내한다. [AccessibilityManager API](https://developer.android.com/reference/android/view/accessibility/AccessibilityManager#isTouchExplorationEnabled()).

### 안전교육

1. 사용자가 교육 화면에서 재생을 명시적으로 요청한다. 화면 진입이나 TalkBack 포커스 이동만으로 시작하지 않는다.
2. 앱이 재생 중·미완료·완료 상태를 관리한다. 중단·오류·화면 이탈·시간 초과로 재생을 끝냈으면 미완료로 유지하고 다시 듣는 방법을 제공한다.
3. 완료는 현재 교육 버전·재생 세션·발화 ID에 대응하는 정상 완료 콜백으로만 인정한다. 여러 조각을 재생한다면 필요한 모든 조각의 완료를 확인한다. 오래된 완료 콜백이 새 재생이나 다른 사용자를 완료시키지 않는다.
4. 완료 뒤 기존 이해 확인·다음 단계 gate를 적용한다. TalkBack이 본문을 읽었다는 추정이나 재생 요청을 큐에 넣었다는 사실로 완료 처리하지 않는다.

`UtteranceProgressListener.onDone()`은 음성 출력의 재생 완료를 나타내고, `onStop()`은 중단 또는 큐 제거를 나타낸다. `onError()`도 완료가 아니다. 콜백은 출력 파이프라인의 근거이지 사용자가 실제로 들었거나 이해했다는 증거는 아니므로 기존 확인 절차를 대체하지 않는다. [UtteranceProgressListener API](https://developer.android.com/reference/android/speech/tts/UtteranceProgressListener).

### 회원가입 약관

1. 승인된 실제 약관 본문을 제목·조항 단위로 접근 가능하게 제공한다. 필수·선택 항목과 동의 상태를 화면 읽기로 구별할 수 있어야 한다.
2. 본문 읽기와 앱의 선택 재생은 내용을 확인하는 수단이다. 읽기 시작·끝·중단을 동의로 바꾸지 않는다. 승인 본문을 요약문으로 대체하지 않는다.
3. 동의는 해당 항목에 대한 명시적 조작으로만 변경하며, 최종 가입은 기존 필수 동의 조건을 유지한다. 선택 동의를 일괄 강제하거나 음성 사용 동의와 다른 수집·전송 동의를 합치지 않는다.
4. 음성 동의 전용 명령이 구현·검증되지 않은 상태에서는 지원한다고 안내하지 않는다. TalkBack으로 동의 항목과 가입 조작을 수행하는 경로를 제공한다.

## 보행 음성의 우선순위와 충돌 방지

아래는 앱이 소유한 출력 큐의 우선순위 설계다. 다른 앱이나 TalkBack을 강제로 제어할 수 있다는 보장이 아니다. APH의 Indigo도 회전·교차로·검색 상태에 음성, 짧은 음, 진동을 함께 사용한다. WalkSafe에서는 기존에 의미가 정해진 진동·신호를 사용하고 새로운 패턴을 임의로 늘리지 않는다. [APH Indigo](https://www.aph.org/product/indigo/).

| 우선순위 | 내용 | 처리 |
|---|---|---|
| 1 | 현재 관측으로 확인된 긴급 위험 | 하위 앱 발화를 중단하고 짧은 경고와 기존 진동·신호를 제공한다. 오래된 위험은 재생하지 않는다. |
| 2 | 안내를 계속할 수 없는 기기·권한·위치·음성 상태 | 제한 상태와 필요한 다음 행동을 짧게 알린다. 실패했는데 계속 정상 안내 중이라고 말하지 않는다. |
| 3 | 시간에 민감한 경로 안내 | 최신 위치·경로·보행 세션에 유효한 안내만 재생한다. 지연된 회전을 뒤늦게 이어 읽지 않는다. |
| 4 | 사용자가 요청한 명령 결과·후보 선택·현재 안내 | 한 번에 한 대화 흐름을 유지한다. 확인 문장 후 입력 가능한 시간을 보장한다. |
| 5 | 반복 객체 설명·긴 콘텐츠 | 중복·낡은 설명을 버린다. 교육·약관 같은 긴 콘텐츠는 보행 준비 또는 일시정지 상태에서 사용한다. |

- 일시정지·취소 요청이 실제 입력으로 전달되면 긴 발화가 끝날 때까지 실행을 미루지 않는다. 종료·후보 선택 같은 확인 대기는 현재 보행 세션과 해당 질문에 결속하고, 다른 화면·새 보행·취소 뒤에 도착한 이전 응답으로 행동하지 않는다.
- 앱의 음성은 공유 출력 중재 경로를 사용한다. 동일 상태를 앱 TTS와 별도 접근성 강제 알림으로 동시에 읽지 않는다. TalkBack 포커스·상태 읽기는 사용자의 탐색을 위한 접근성 정보로 유지한다.
- 오디오 포커스 요청에 실패하면 재생 성공으로 처리하지 않는다. 포커스를 잃으면 앱의 긴 말소리를 중단·일시정지하고 해당 안내의 유효성을 다시 판단한다. Android는 말소리에 자동 음량 감소가 부적절할 수 있으므로 일시정지를 처리하도록 설명한다. [Android 오디오 포커스](https://developer.android.com/media/optimize/audio-focus).
- 외부 TalkBack의 정확한 발화 시작·종료를 일반 앱의 TTS 콜백으로 관찰할 수 있다고 가정하지 않는다. 앱 내부 중복 제거와 오디오 포커스 협조 이후에도 실제 기기·TalkBack 버전·출력 장치 조합의 충돌 시험이 필요하다.

### 앱 발화의 자기 인식 억제

1. 앱이 말하기 전에 명령 수락을 닫고 현재 인식 세대를 무효화한다. 앱 음성이 들어간 마이크 버퍼·부분 결과·늦은 최종 결과를 다음 명령으로 재사용하지 않는다.
2. 앱 발화가 실제로 끝나거나 취소·실패로 정리된 뒤 녹음 버퍼와 recognizer 상태를 정리하고 새 인식 창을 연다. 스피커·블루투스의 잔향 및 지연은 기기 측정으로 결정한다. 고정 지연값 하나로 모든 출력 장치의 자기 인식이 사라졌다고 주장하지 않는다.
3. 호출어 뒤에만 명령 창을 열고, 재생된 질문과 연결된 제한된 확인 문맥을 사용한다. 확인 대기 시간은 안내가 끝나 입력 가능한 시점부터 계산해야 한다.
4. 외부 TalkBack·주변 사람·방송도 마이크에 들어올 수 있으므로 앱 자체 발화 억제가 모든 오인식을 해결하지는 않는다. 마지막 확인 문맥 없이 단독으로 들린 긍정 표현을 종료·선택 동의로 사용하지 않는다.

**한계:** 재생 중 STT를 닫는 방식에서는 그동안 사용자의 음성 중단 명령도 받을 수 없다. 현재 긴 교육·약관의 중단은 접근 가능한 화면 조작으로 제공해야 한다. 보행 안내는 짧게 말하고 입력 가능한 구간을 확보한다. 긴 콘텐츠를 화면 조작 없이 즉시 중단할 수 있다고 하려면 검증된 재생 중 음성 끼어들기 또는 별도 접근 가능한 제어가 실제 구현되어야 한다. 이 문서만으로 그 기능을 지원 처리하지 않는다.

## 실제 명령 범위에 맞춘 행동 표

현재 선언 근거는 [AndroidVoiceCommand.kt](../../apps/android/app/src/main/java/kr/co/hanium/dreamup/walksafe/navigation/AndroidVoiceCommand.kt), [WalkSessionVoiceControlPolicy.kt](../../apps/android/app/src/main/java/kr/co/hanium/dreamup/walksafe/navigation/WalkSessionVoiceControlPolicy.kt), [WakePhraseCommandExtractor.kt](../../apps/android/app/src/main/java/kr/co/hanium/dreamup/walksafe/voice/WakePhraseCommandExtractor.kt)다. 아래의 지원은 **조사 시점 parser·정책 선언 확인**을 뜻한다. Activity 연결, 서버 결과, 설치 APK 동작까지 확인한 것은 아니다. 문구 확장은 구현 담당의 최종 명령 목록과 함께 검증해야 한다.

핸즈프리 호출어는 `길라잡이`다. 예를 들어 `길라잡이, 보행 일시정지`라고 말한다. 버튼 입력은 사용자가 이미 입력 시작을 선택했으므로 호출어를 반복 요구하지 않고 같은 명령 해석·권한 검사를 사용하도록 통일한다. 호출어 대기와 명령 입력 중은 구별 가능한 상태로 알린다.

| 행동 | 현재 선언된 대표 명령 | 확인·동의 | 취소·되돌리기 | 성공·실패 안내 설계 |
|---|---|---|---|---|
| 목적지 검색 | `서울역으로 안내해줘`, `목적지 서울역 설정` | 검색어를 알리고 실제 검색 결과를 기다린다. 검색만으로 보행을 시작하지 않는다. | 선택 전 검색 취소 경로를 제공한다. 활성 경로와 후보 대기를 구분한다. | 이름·주소·거리와 번호를 포함한 후보 또는 결과 없음·통신 실패·이용 조건을 안내한다. |
| 목적지 선택 | `1번 선택`, `첫 번째 선택` | 먼저 읽은 후보의 번호 선택을 명시 선택으로 취급한다. 현재 페이지·검색 세대에 없는 번호는 확정하지 않는다. 기존 후속 확인·시작 gate를 유지한다. | 선택 전 취소는 원래 경로를 보존한다. 선택 후 변경은 새 목적지 흐름으로 수행한다. | 선택한 실제 이름·주소와 경로 요청 결과를 알린다. 잘못된 번호에는 현재 선택 가능한 범위를 말한다. |
| 후보 더 듣기 | `더 듣기` | 현재 검색 대기에서만 다음 후보 묶음을 읽는다. | 후보 선택·검색 취소로 대기를 끝낸다. | 다음 묶음 또는 더 이상 후보 없음. 외부 추가 검색 실패는 기존 후보와 구별한다. |
| 목적지 취소 | `목적지 취소` | 후보 대기 취소인지 현재 목적지 제거인지 실행 문맥을 구별한다. | 취소 결과를 알리고 재검색을 허용한다. | 후보만 닫았는지 활성 목적지가 제거됐는지 정확히 말한다. |
| 다음 경로 듣기 | `다음 안내 알려줘`, `다음 경로 뭐야` | 추가 확인 없이 현재 유효한 경로를 읽는다. | 재생 중단은 가능한 제어로 제공한다. | 다음 안내 또는 활성 경로 없음·위치 확인 필요. 오래된 안내를 재사용하지 않는다. |
| 재탐색 | `새 경로 찾아줘`, `경로 다시 찾아줘` | 실제 기존 재탐색 조건을 확인한다. | 취소·실패 시 기존 경로의 유효 상태를 명확히 한다. | 요청 시작과 실제 완료를 구분하고, 실패 시 재시도 조건을 말한다. |
| 위치 재확인 | `위치 다시 확인`, `위치 확인해줘` | 실제 측정·권한 조건을 유지한다. | 대기 취소가 연결되지 않았다면 가능하다고 안내하지 않는다. | 확인 결과 또는 현재 위치 불확실·권한 필요를 알린다. |
| 도착 확인 | `도착했어`, `도착 확인` | 도착 확인을 기다리는 현재 목적지 문맥에서만 처리한다. | 확정 전 `도착 아니야`로 거절한다. | 실제 도착 처리 결과 또는 확인 중인 목적지 없음. |
| 도착 거절 | `도착 아니야`, `아직 도착 아니야` | 도착 확인 문맥에서만 처리한다. | 추가 안내·위치 재확인 등 실제 가능한 다음 행동을 제공한다. | 도착 확정하지 않았음과 안내 유지 상태를 말한다. |
| 길안내 종료 | `길안내 종료`, `길안내 중지` | 보행 세션 종료와 구별한다. 기존 길안내 종료 조건을 적용한다. | 다시 목적지를 선택할 수 있다. | 길안내 종료 여부와 보행·객체 안내가 유지되는 실제 상태를 구분해 말한다. |
| 신고 요청 | `신고해`, `여기 신고해줘` | 실제 대상·보행·동의·저장·전송 조건과 기존 확인 절차를 유지한다. 명령만으로 수집·자동 신고 동의를 새로 부여하지 않는다. | 별도 음성 신고 취소가 선언되지 않았으므로 현재 UI의 실제 취소 경로만 안내한다. | 저장됨·대기 중·서버 접수됨·실패를 구별한다. 외부 기관에 전달됐다고 임의로 말하지 않는다. |
| 보행 일시정지 | `보행 일시정지` | ACTIVE에서 신뢰도·현재 세션 조건을 통과하면 추가 확인 없이 정지한다. | `보행 재개`는 재확인 조건 뒤 수행한다. | 실제 PAUSED 반영과 안내 중단 범위를 말한다. 비활성 상태이면 현재 상태를 알린다. |

| 보행 종료 확정 | `보행 종료 확인` | 같은 세션의 유효한 종료 대기가 있어야 한다. 단독 확인이나 이전 세션 결과는 실행하지 않는다. | 확정 전만 취소할 수 있다. 종료 뒤에는 새 보행 시작 절차가 필요하다. | 실제 종료 후 종료됐음을 알린다. 대기가 없으면 종료 요청이 없음을 안내한다. |

| 미인식·지원하지 않는 말 | 위 목록과 맞지 않는 문장 | 부정 표현·낮은 신뢰도·모호한 단독 긍정으로 행동을 추정하지 않는다. | 입력 대기를 종료하거나 기존 상태를 유지한다. | 짧게 인식 실패 또는 지원하지 않는 명령을 알리고 현재 쓸 수 있는 예시를 하나 제시한다. |

조사 시점 후보 안내는 원하는 번호를 말하라고 하지만 parser는 `1번 선택`처럼 선택 동사를 요구한다. 안내를 실제 허용 문구로 맞추거나, 후보 대기 문맥에 한해서 번호만 받도록 구현·시험해야 한다. 문서만으로 `1번` 단독 입력을 지원한다고 주장하지 않는다.

| 약관 동의·철회·선택 개인정보 설정 | 위 parser에 전용 명령 없음 | 각 항목의 접근 가능한 조작과 기존 저장·서버 확인을 사용한다. 읽기·침묵·재생 완료는 동의가 아니다. |

| 앱 전체 읽기 중단·다시 듣기·상태·명령 도움말 | 위 parser에 일반 전용 명령 없음 | `다음 안내 알려줘`는 현재 경로에 한정한다. 일반 명령으로 확장하려면 실제 handler와 도움말을 함께 구현한다. |
| 설정 변경·삭제·로그아웃·신고 취소·긴급전화·신호등 판독 | 위 parser에 전용 명령 없음 | 지원한다고 말하거나 인접 명령으로 추정 실행하지 않는다. 실제 존재하는 화면 조작과 기능 한계를 안내한다. |

## 구현 수용 기준과 남은 검증

- [UI·입력 연결] -> 검증: TalkBack ON/OFF에서 같은 버튼·명령이 같은 권한·기능 gate를 거치고, 모든 필수 조작을 읽고 실행할 수 있는지 확인한다.
- [교육·약관] -> 검증: 재생 요청만 한 상태, 정상 완료, 취소, 오류, 늦은 완료 콜백을 구분한다. 미완료 교육 통과·읽기만으로 동의·필수약관 미동의 가입이 없어야 한다.
- [명령·확정·취소] -> 검증: 표의 명령마다 실제 행동을 한 번만 실행한다. 부정·미인식·오래된 후보·다른 세션·대기 없는 종료 확인은 행동을 실행하지 않아야 한다.
- [음성 출력·마이크] -> 검증: 앱이 호출어·목적지·종료 확인 예문을 읽어도 자기 명령이 실행되지 않는지 확인한다. 중단·오류 이후 마이크나 TTS가 영구 무응답이 되지 않아야 한다.
- [보행 중재] -> 검증: 객체·경로·위험·명령 응답이 동시에 들어올 때 우선순위와 최신성, TalkBack 읽기와의 겹침, 통화·포커스 상실·출력 장치 변경을 실제 기기에서 확인한다.
- [오프라인 경계] -> 검증: 인터넷이 없어도 준비된 모델의 명령 인식과 한국어 TTS가 동작하는지 확인하고, 온라인 검색·경로 요청 실패는 별도로 정확히 알린다.

**시각장애 당사자의 현장 사용성 검증이 반드시 남는다.** TalkBack 숙련 사용자, 초기 사용자, 저시력·확대 사용자의 참여로 안전하게 정지한 준비 작업부터 감독된 보행까지 단계적으로 확인한다. 휴대전화는 실제 고정 자세로 사용하고, 조용한 장소·거리 소음·바람·스피커·사용자 청취 장치 조건을 기록한다. 후보 선택 정확도, 첫 시도 명령 성공률, 잘못 실행된 명령 수, 응답 지연, 재생 중 취소 가능 여부, 화면을 만진 횟수, 주변 소리를 놓친 상황, 복구에 필요한 도움을 측정한다. 실험자 눈가림 사용이나 parser 단위 시험을 시각장애 사용자의 실제 보행 검증으로 대체하지 않는다.

Android 역시 접근성 서비스 직접 조작, 분석 도구, 자동 시험, 실제 사용자 피드백을 함께 사용하도록 권한다. 이 문서 작성에서는 자료 조사와 명령 선언 읽기만 수행했으며 앱 빌드·테스트·휴대전화 조작·현장 시험은 실행하지 않았다. 따라서 음성 정확도·TalkBack 충돌 없음·보행 안전성은 미검증이다. [Android 접근성 시험 안내](https://developer.android.com/guide/topics/ui/accessibility/testing).

조사 방법: Android·Google TalkBack 공식 자료, RNIB, APH, Vosk 공식 모델 목록을 확인했다. `find-docs`의 Context7에서 Android 문서 식별 후 조회했으나 TTS 콜백 질의의 충분한 결과를 얻지 못해 해당 Android 공식 API 페이지를 직접 확인했다. 사용자 인터뷰·동료심사 연구의 새 실험 결과를 확보한 것으로 표현하지 않는다. 작업 기록은 부모 에이전트가 통합한다.

## 후속 구현 반영: 명령·청취 UI와 기기 재검증 상태

2026-09-06 KST 갱신. 아래 내용은 앞 절의 **조사 시점 미지원·연결 미확인 항목에 대한 후속 구현 차이**다. 앞의 명령 표와 충돌하는 경우 이 절의 현재 범위를 따른다. 구현 연결과 정적 계약을 반영한 것이며, 모든 명령의 실기기 성공이나 접근성·보행 안전 검증 완료를 뜻하지 않는다.

### 현재 역할과 결정 근거

- TalkBack 등 접근성 도구는 화면 탐색, 입력, 버튼·동의 상태와 약관 본문 읽기를 맡는다. 본문을 조항별로 접근 가능하게 유지하며, 화면 진입이나 포커스 이동을 앱 콘텐츠 재생 요청으로 바꾸지 않는다.
- 앱의 오프라인 한국어 TTS는 명시적으로 요청한 교육·약관 듣기, 명령 결과, 현재 경로·객체·위험 안내를 맡는다. 앱 소유 메시지를 TalkBack 활성 여부만으로 다른 출력 경로에 넘기지 않으며, 동일 메시지의 강제 접근성 알림과 live 알림 중복을 줄인다. 화면의 상태 정보는 사용자가 찾아 읽을 수 있게 유지한다.
- 이 분담은 사용자가 접근성 도구로 읽기를 제어하도록 보장하고, 앱 안내에는 실제 TTS 완료·실패와 위험 우선순위·최신성 검사를 적용하기 위한 설계 판단이다. 접근성 서비스 활성 여부는 발화 중 신호가 아니며, 앱은 외부 TalkBack을 완전히 음소거하거나 정확한 발화 종료를 관찰한다고 가정하지 않는다. 근거: [Android 접근성 원칙](https://developer.android.com/guide/topics/ui/accessibility/views/principles-views), [AccessibilityManager](https://developer.android.com/reference/android/view/accessibility/AccessibilityManager), [TTS 완료·중단 콜백](https://developer.android.com/reference/android/speech/tts/UtteranceProgressListener).

### 구현에 맞춘 명령과 복구 범위

버튼으로 시작한 입력은 호출어 없이 같은 명령 처리를 사용한다. 핸즈프리 입력은 기존 호출어 `길라잡이`와 현재 기능·세션 조건을 유지한다. 아래의 실패·재시도는 기존 상태를 임의로 성공 처리하거나 권한·동의·교육·보행 준비 조건을 생략하는 경로가 아니다.

| 조작 | 현재 명령 예 | 실행 범위와 실패·재시도 |
|---|---|---|
| 목적지 검색 | `서울역으로 안내해줘`, `목적지 서울역 설정` | 실제 검색 결과의 이름·주소와 후보를 안내한다. 결과 없음·통신 실패에는 검색어 변경 또는 재시도를 제공하며 검색만으로 보행을 시작하지 않는다. |
| 후보 선택 | `1번 선택`, `첫 번째 선택`; 조건부 `1`, `1번` 등 번호 단독 | parser의 `allowBareDestinationIndex` 기본값은 `false`다. 현재 활성 목적지 후보가 있고, 동일 검색어에 속하며, 검색 요청이 끝났고, 현재 선택 허용 상태일 때만 1~20의 단독 번호를 허용한다. 실제 후보 범위를 벗어난 번호, 이전 검색·대기 중 요청의 결과로는 선택하지 않는다. |
| 후보 이어 듣기·취소 | `더 듣기`, `목적지 취소` | 현재 후보 문맥에 적용한다. 후보 없음·더 이상 후보 없음·추가 검색 실패를 구분한다. 후보 취소와 활성 목적지 제거는 기존 실행 문맥을 유지한다. |
| 안내 시작 | `안내 시작`, `길안내 시작` | 현재 선택·확인 중인 목적지로 기존 준비·권한·세션 조건을 거쳐 안내를 시작한다. 목적지나 준비 조건이 없으면 필요한 다음 조작을 안내한다. |
| 현재 안내 재청취 | `다시 말해줘`, `다음 안내 알려줘` | 현재 유효한 경로 안내를 읽는다. 과거 위험 메시지나 종료된 경로를 다시 재생하는 일반 출력 이력 기능이 아니다. 유효한 안내가 없으면 그 상태를 알린다. |
| 명령 도움말 | `도움말` | 실제 지원하는 명령과 사용 예를 안내한다. 가입·약관 동의·비밀번호 입력 등 미지원 음성 조작을 지원한다고 설명하지 않는다. |
| 경로·위치 재확인 | `경로 다시 찾아줘`, `위치 다시 확인` | 실제 요청 시작과 완료·실패를 구분한다. 현재 위치·권한·경로 조건을 만족할 때 재시도하며 실패를 정상 안내로 표시하지 않는다. |
| 도착·길안내 종료 | `도착 확인`, `도착 아니야`, `길안내 종료` | 도착 판단은 현재 확인 대기에 결속한다. 길안내 종료와 전체 보행 종료를 구분한다. |
| 신고 요청 | `여기 신고해줘` | 기존 대상·동의·확인·저장·전송 조건을 유지한다. 저장·전송 대기·서버 접수·실패를 구분하고 외부 기관 전달 성공으로 확대하지 않는다. |
| 보행 일시정지·재개 | `보행 일시정지`, `보행 재개` | 실제 상태 전이를 확인한다. 재개는 기존 기기·권한·환경·세션 재확인 조건을 유지하며, 차단 원인을 해결한 뒤 다시 요청한다. |
| 보행 종료 확인·취소 | `보행 종료`, `보행 종료 확인`, `보행 종료 취소` | 현재 보행 세션의 종료 확인 대기에만 응답한다. 안내 재생 실패, 확인 대기 없음, 취소·세션 변경 뒤의 오래된 응답으로 종료하지 않는다. |
| 미인식·지원하지 않는 말 | 위 명령에 맞지 않는 입력 | 동작을 추정 실행하지 않고 짧은 실패·사용 예를 안내한다. 새 입력이나 화면 조작으로 재시도한다. |

### 교육·약관 청취와 동의의 분리

교육은 기존 듣기 버튼에서 재생을 시작하고, 재생 중에는 접근 가능한 중지 조작을 제공한다. 완료된 콘텐츠는 다시 듣고, 중단·실패한 콘텐츠는 재시도할 수 있다. 현재 재생 세대·계정·교육 문맥에 대응하는 실제 정상 완료 콜백에서만 완료를 표시하고 기록한다. 요청 수락, 추정 시간 경과, 중지·오류·다음 발화 시작으로 청취 완료를 만들지 않는다. 이미 유효하게 완료한 기록과 이번 재생의 미완료 상태를 구분하며, 기존 교육 확인·동의 조건을 유지한다.

약관은 조항 본문을 TalkBack으로 읽거나 선택 듣기 버튼으로 재생한다. 버튼은 듣기 중지·다시 듣기·재시도와 실제 완료 상태를 구분한다. **듣기 시작·완료·중지는 해당 동의 체크를 변경하지 않는다.** 필수 동의는 명시적 조작으로 확인하고, 가입의 기존 필수 동의 조건을 유지한다. 청취 취소·화면 이탈·계정 또는 요청 세대 변경 뒤의 콜백은 현재 청취나 교육 증거를 완료시키지 않는다.

앱 발화 동안 자기 음성이 명령으로 다시 인식되지 않도록 기존 입력 억제를 유지한다. 그동안 음성 중단 명령을 받을 수 있다고 안내하지 않으며, 긴 콘텐츠의 중지는 접근 가능한 화면 조작으로 제공한다.

### 최종 기기 확인에서 발견한 문제와 남은 범위

실제 휴대전화 확인에서, 가입 약관 듣기가 전체 기기 점검의 `BLOCKED` 상태에 함께 막히는 문제가 확인됐다. 가입 전 약관 청취에는 보행용 카메라·위치 준비 완료를 요구하지 않도록 **약관 전용 `speakConsentClause` 경로로 분리하는 수정과 기기 재검증이 진행 중**이다. 이 경로도 오프라인 한국어 TTS의 실제 `READY`, 오디오 포커스, 정상 완료·실패 구분을 유지한다. 약관 청취 허용을 보행·위험·교육의 기존 게이트 완화로 확장하지 않는다. 재검증 결과가 확정되기 전에는 약관 듣기 문제 해결 완료나 모든 청취 상태 통과로 보고하지 않는다.

시각장애 당사자의 실제 사용성, 외부 TalkBack과 앱 음성의 기기·출력 장치별 충돌, 카메라 관측과 위험 안내, 실제 장착·실보행 검증은 아직 완료되지 않았다. 정적 검사·빌드나 정지 상태의 일부 휴대전화 재현을 이 범위의 완료 증거로 대신하지 않는다. 최종 빌드·휴대전화 재검증 결과와 작업 기록은 부모 통합 보고에서 별도로 확정한다.

## 최종 휴대폰 재검증 결과 (2026-09-06)

앞 절의 약관 `speakConsentClause()` 재검증 대기 상태를 갱신한다. 최종 APK에서 TalkBack OFF의 서비스·개인정보 약관이 실제 재생 완료 후 다시 듣기로 바뀌었고 동의 체크는 자동 선택되지 않았다. TalkBack ON에서도 서비스 바인딩과 터치 탐색을 확인하고, 켜진 동안 uiautomator를 호출하지 않는 screencap 시험으로 개인정보 약관의 재생 중·완료 전환을 확인했다. 원래 접근성 설정은 복원했다. 초기 dump 반복 시험에는 TalkBack 서비스를 억제·재연결시키는 도구 간섭이 있었으므로 제품 회귀의 확정 근거로 채택하지 않았다. 실제 음질·소리 겹침·초점 탐색·당사자 이해도 검증과 교육 전체 완주는 남아 있다. 자세한 검증 범위는 `docs/reports/overnight-stability-20260906.md` 참조.
