# 미학습 객체 영역·깊이 후보 통합 시험 계획

## 목표와 범위

현재 사용자 앱의 13클래스 모델을 유지하면서, 그 모델의 클래스에 없는 물체의 **영역**을 추가로 찾고 해당 영역에 **깊이/거리**를 붙일 방법을 시험한다. 이름 맞히기는 요구하지 않는다. 새 WalkMate 모델 교체는 보류 상태를 유지한다. 휴대폰 움직임 보정·물체 접근 판단·음성 위험 안내는 이번 후보 선정 이후 단계다.

후보 모델에서 반환한 마스크 → 원본 RGB 좌표로 복원 → 같은 관측에 연결된 이미지-깊이 좌표 변환 → 영역 내부의 유효 깊이 표본 → 거리와 품질/미확인 상태가 통합 경로다. 서로 다른 모델 입력 해상도를 통일할 필요는 없다. 기존 모델 768을 유지하고 FastSAM 640·768을 비교한다.

## 담당과 보존

- Root: 통합 계획/결과 문서, 기기·ADB, 결과 통합, daylog. 원본 앱/모델을 교체하지 않는다.
- unknown_fixture: COCO 미학습 클래스 중심의 고정 정답 자료, 출처와 선택 기준.
- unknown_candidates: FastSAM-S 및 YOLOE prompt-free, 기존 모델의 동일 입력 비교와 변환. 이번 작업의 PC GPU 실행 단독 담당.
- unknown_depth: 마스크-깊이 좌표·단위·유효성 처리 구현과 합성 회귀 시험.
- unknown_android_audit: 기존 Android 하네스와 연결 지점 읽기 전용 검토.
- unknown_rgbd_fixture: 작은 공개 RGB-D 참조 자료 확보와 단위/정답 범위 검증.
- 별도 검토자: 결과가 준비된 뒤 시험·집계·해석의 독립 검토.

## 비교 규칙

- 고정 예비 비교: confidence 0.25, NMS IoU 0.7, 최대 후보 100, batch 1, 실제 정사각 입력(`rect=False`), FP32. 마스크 복원 방식도 기록한다. 이는 제품 임계값 확정이 아니다.
- `unknown`은 현행 custom primary의 COCO 교집합 7클래스(person/bicycle/car/motorcycle/bus/truck/traffic light) 밖이다. COCO 벤치는 legacy fallback 허용 목록에 존재하므로, primary 기준과 전체 가능한 앱 동작을 혼동하지 않는다.
- 기존 검출기는 bbox만 있으므로 영역 마스크 정확도와 비교하지 않는다. 클래스명을 무시한 bbox 중첩은 해당 객체를 올바르게 이름 붙였다는 뜻이 아니다.
- COCO가 모든 장면 영역을 라벨링하지 않으므로, 맞는 GT가 없는 후보를 모두 오탐으로 계산하지 않는다. proposal coverage와 일대일 매칭을 함께 보고하며 공식 COCO AP와 구분한다.
- 이미지 80장은 후보 선별용 소규모 표본이다. 야외 보행·모든 미학습 물체·프레임 간 연속성의 검증으로 확대하지 않는다.
- 먼저 수치와 실패 사례를 확인한 뒤 후보 유지/제외 및 추가 튜닝 시험을 판단한다. 결과를 본 후 데이터나 기준을 바꿔 최초 시험처럼 보고하지 않는다.

## 깊이 계약과 판정 경계

- ARCore raw depth는 희소한 깊이와 confidence를 제공한다. full depth는 보간되어 두 소스를 같은 품질로 취급하지 않는다.
- depth 원값(mm)은 광축 방향 깊이 z이며, 화면 외곽 물체까지의 직선거리와 다르다. 내참수로 변환한 ray distance는 별도 필드다.
- 실제 기기에서는 ARCore의 좌표 변환과 캡처 시각/프레임 관계가 필요하다. 단순 resize와 합성 identity 변환을 실제 카메라 정합으로 주장하지 않는다.
- 충분한 유효 표본이 없으면 객체 영역을 유지하고 거리는 미확인으로 반환한다. 0m나 배경의 거리로 확정하지 않는다.
- 사용자는 이번 연결 기기의 후면이 바닥을 향한 상태만 가능하다고 확인했다. 기기 실행 속도와 데이터 획득 상태는 시험할 수 있지만, 여러 물체의 실측 거리 정확도는 이번 조건에서 완료할 수 없다.

## 채택 판단 및 남는 단계

640은 768보다 입력 픽셀 수가 약 30.6% 적다. 연산 시간도 같은 비율로 줄어든다는 가정은 하지 않는다. 640에서 누락/경계 품질이 악화하면 768 또는 후보 변경을 선택한다. Qualcomm 공개 640 NPU 수치는 후보 모델과 특정 런타임의 근거이며, 현재 S20의 실행 시간이나 앱 전체 처리율을 보장하지 않는다.

후보 선정 뒤 제품 통합에서는 모델 마스크를 유지하는 자료구조, 동시 부하 아래 최신 결과 유효성, 중복 객체 병합과 처리 주기를 시험해야 한다. 현재 모델을 즉시 교체하거나 이번 합성/정적 이미지 시험만으로 실제 보행 안내에 투입하지 않는다.
