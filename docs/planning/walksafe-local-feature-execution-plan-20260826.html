현재 결론

제품 기능 코드는 이미 구현·집중회귀를 마쳤고, 현재 물리 checkpoint는 exact seq99 READY다. R010 write의 terminal 불확실성은 checkpoint 손상이 아니라 동일 바이트 임시 파일을 live로 오인한 provenance 결함이었다. temp가 없는 canonical 경로에서 continuation·GoalGraph·inverse·managed aggregate와 checkpoint identity를 모두 재검증했고, rollback이나 seq99 재게시 없이 R011을 진행했다. R011은 무쓰기 preflight와 실제 add-only 실행에서 5/5 PASS였으며 receipt와 로그 5개는 모두 private file 조건을 만족한다. seq100 첫 preflight는 managed 목록에 checkpoint와 direct gate evidence를 넣은 오류를 쓰기·CAS 전에 거부했다. 기존 R010/R011 파일은 수정하지 않고, fresh START-PROJECTION-R001 review가 경계 필터·exact inverse·3단계 CAS를 승인한 뒤 seq100을 게시한다. 정식시험·실기기·cloud·출시 credit은 계속 0이다.

EPIC-07 원본자료 수집·보존·삭제

  1. video, audio, exact-location, sensor, route, detection, report, performance의 exact manifest/chunk schema를 고정한다.
  2. 동의+ACTIVE 조건에서만 별도 키의 휴대전화 암호화 append store에 쓴다.
  3. 서버 ingest는 idempotency key와 chunk SHA-256을 확인하고 부적합 자료는 quarantine한다.
  4. 검증된 receipt 뒤에만 휴대전화 사본을 삭제한다.
  5. 저장소별 retention/delete 상태기계를 fake clock으로 검증한다.
  6. Noop capture를 concrete collector로 교체하고 Backend privacy lifecycle에 연결한다.

필수 실패시험: consent/ACTIVE 부재, 잘못된 receipt, crash/retry 중복, retention 경계 ±1, 삭제 fan-out 재시도에서 각각 데이터 보존·삭제가 계약대로 동작해야 한다.
