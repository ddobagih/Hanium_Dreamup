# 768 유지 성능 최적화와 고정 데이터 비교 계획

목표: 원본 YOLO26n768/FastSAM768과 안전 판단 계약을 유지하면서 실제 결과 지연·초기화 시간을 줄인다. 사용자가 2026-09-11 S25를 다시 연결했다. S20 성능 측정을 시작하기 전이므로 S25(SM-S931N)에서 기준선부터 측정한다. 두 기종 결과를 섞어 비교하지 않는다. 서버/DB·회원가입 데이터는 유지한다.

## 데이터·시험 계약

- 기존 phase3 공개 정적 RGB-D 4장(OCID2/OSD2), canonical segmentation8장, MOVi-E163 개발용24프레임과131 이전에 평가한 회귀용24프레임을 재사용한다. 원본 파일·순서·모델·입력768·임계값 해시/메타데이터를 phase5 데이터목록에 고정한다. 새로 유리한 영상으로 교체하지 않는다.
- 변경 전후 같은 기기·동일 순서·동일 예열/반복수/입력주기. 가능하면 A/B/B/A 순서로 확인하고 열상태·배터리·탈락·완료한 모든 입력을 기록한다. 프레임 누락이나 입력 장면 비중 차이가 있으면 직접비교로 채택하지 않는다.
- 준비(cold/warm)와 정상 처리 측정 분리. 평균/P50/P95, 모델/전처리/후처리/깊이/대기/완료 지연, 처리율을 구분한다. 마지막 음성시작까지의 지연은 측정한 시험에서만 보고한다.
- 깊이 계산 최적화는 동일 결과를 우선한다. 정밀도 변경은 CPU 또는 기존strictGPU 기준과 비교하며 mask IoU/누락/작은영역/깊이상태/접근오류 회귀를 확인한다. 픽셀 동일성이 깨진 후보는 원본에 무조건 적용하지 않는다.
- 추적 실험의 참값은 채점에만 사용한다. UNKNOWN/PARTIAL·소실·회전·시간역행·새객체·가려짐 경계를 포함한다. 실제 물리 깊이/접근 정확도와 합성재생 결과를 혼동하지 않는다.
- 회차300초 정책 마감, native 강제중단불가시 실제정리완료까지 소유권 유지. 기존800ms 앱캡처기준 안내시작 제한 보존.

## 단계 → 검증

1. 기준선 고정: 현재 제품코드/고정데이터 보존, 현재 연결된 S25 원본 제품서비스의 반복 재생 시험 준비 → 실제 모든 입력처리·형상/해시/소유권/기본속도 확인.
2. 깊이 처리: 마스크별 할당·반복스캔의 실측 병목부터 변경. 기존cache/histogram최적화를 중복 주장하지 않음 → 고정233mask/401component 및수치/부분깊이동일성,동일기기시간 비교.
3. GPU: 초기화 serialization 캐시를 모델/옵션/기기별 분리하고 strictGPU기본유지, 정밀도완화는명시적시험옵션으로비교 → cold/warm load·실제backend·raw/mask 품질·오류복구·release검증. 성능/품질근거부족 후보는 미채택.
4. 추적/깊이 갱신 분리: 현재 source/frame/좌표계계약 분석 후 가벼운 중간 갱신 후보 평가. 모델과 무관하게 낡은마스크를 새시각으로붙이지 않음 → 별도동적자료에서동일성·누락·거짓접근·위험판정지연이개선된경우만제품채택. 실패하면기존경로유지하고실패근거보존.
5. 통합: 채택변경만원본앱에통합,관련JVM/실기기모델·한국어안내 회귀·APK빌드/설치 → 변경별전후표·채택/보류사유를프로젝트보고서/daylog에기록.

## 역할과 보호

Root: 고정데이터목록, 계측시험, ADB·Gradle·APK·MainActivity 및 통합/기록. 기존팀의 깊이/GPU/추적 담당은각자배정소스만수정,독립검토별도. 한파일한작성자,원래WIP/기존APK/원자료보존. 모든변경은기준선보관후시작한다.

canonical8장에RGB-D4장이포함된다.131은이미평가결과를본자료이므로완전히미사용한heldout으로표현하지않는다. precision채택은모든이미지동일mask수/일대일IoU≥0.99,깊이상태동일,신규거짓접근·미확인거리경고0을요구한다. 캐시경로는mask픽셀동일을요구한다.

## 2026-09-12 실행 결과

단계 1~5의 구현·고정 데이터 비교·채택 판단·원본 통합을 완료했다. S25에서 strict 캐시의 모든 마스크 동일성과 준비 시간 약24.8초→0.31초 재사용을 확인해 채택했다. 깊이 작업 배열 재사용은 같은233마스크/401성분,200회 대조 exact,160회 ABBA의 P50 155.11→142.66ms로 채택했다. 정밀도 완화는544→541마스크 및 IoU 기준 실패, 중간 추적은0/60 갱신으로 미채택했다. 시험 코드의 해시 처리 때문에 처음 깊이시험이 마감 실패한 기록을 보존하고 동일한 조건에서 재검증했다.

원본 APK 빌드·S25 설치 및 해시 확인, 관련 JUnit492개, 실제 한국어 안내 연결2개를 통과했다. 전체 앱FPS·실제 ARCore거리·보행 접근 정확도는 별도 현장 검증 범위다. 세부 실행 조건과 산출물은 [결과 보고서](../reports/walksafe-768-optimization-fixed-data-20260912.md)에 기록했다.
