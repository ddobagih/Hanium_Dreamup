기능 구현 7개 확정 방향

2026-08-29 사용자 지시와 안전·개인정보 재검토를 반영했습니다. 정식 정책·제품 코드 반영은 저장소 시작 통제 복구 뒤 진행합니다.

1 Gateway raw 데이터 업로드동의 원장과 receipt 신뢰 경계

왜 결정이 필요한가

Gateway local ledger hash와 Backend consent receipt의 의미가 달라, 지금 연결하면 잘못된 동의를 허용하거나 정상 업로드를 거부할 수 있습니다.

확정 구현안

Backend consent receipt를 유일한 권한 근거로 사용하고 Gateway hash는 이름부터 감사 전용 필드로 분리합니다. 장·단기 세션 모두 같은 actor·계정 세대의 Backend 원장을 조회하며, Gateway와 Backend가 body 처리 전후에 각각 검증합니다.

승인 문장: “Raw 업로드는 Backend 동의 원장을 기준으로 하고 Gateway hash는 감사용으로 분리한다.”
2 신고 정정 실제 반영수정 범위·revision·재검수

왜 결정이 필요한가

현재는 정정 요청과 관리자 처리는 기록되지만, 어떤 본문을 바꾸고 기존 검수·제출본을 어떻게 무효화할지가 정해지지 않았습니다.

확정 구현안

사진·위치·시각·모델 결과·기존 제출본은 불변으로 두고 사용자 설명 등 허용 필드만 structured patch로 수정합니다. 새 content revision을 만들고 재검수하며, 기관 제출 뒤에는 기존 제출본과 연결된 별도 정정 package를 생성합니다.

승인 문장: “원본은 보존하고 허용 필드만 새 revision으로 정정하며 항상 재검수한다.”
3 신고 물리 삭제삭제 범위·legal hold·최소 tombstone

왜 결정이 필요한가

DB 행만 지워도 이미지·감사·제출본·백업에서 되살아날 수 있고, 잘못 삭제하면 복구할 수 없습니다.

확정 구현안

legal hold가 없을 때 DB 본문과 이미지·삭제 가능한 파생 자료를 전용 worker가 삭제합니다. 원문·위치 없이 불투명 key만 담은 최소 tombstone과 삭제 영수증을 분리 보존하며, 기관 사본은 삭제됐다고 주장하지 않습니다.

승인 문장: “본문·이미지·파생 자료는 삭제하고 재생 방지용 최소 tombstone과 영수증만 보존한다.”
4 수신 원본 14일 검역시작 시각·상태·만료·hold

왜 결정이 필요한가

14일을 언제부터 세는지, 승인·거부·보류 자료가 어디로 이동하는지, hold 예외와 삭제 증거가 없습니다.

확정 구현안

전체 object 검증·commit 시각부터 최대 14일로 두고, 신고 처리 승인과 학습 승인을 분리합니다. 어느 목적으로도 승인되지 않은 raw 원본은 만료 시 삭제 영수증을 남기며 hold는 법적 근거·사유·승인자·만료가 있을 때만 허용합니다.

승인 문장: “수신 완료부터 14일 검역하고 미승인 자료는 hold가 없으면 영수증과 함께 삭제한다.”
5 승인 학습자료 3년승인·lineage·철회·파생본

왜 결정이 필요한가

신고가 들어왔다는 사실만으로 학습자료가 되는 것은 아니며, 동의 철회 시 데이터셋과 파생 자료를 어디까지 제외할지 기준이 필요합니다.

확정 구현안

별도 선택 동의·항목별 사람 승인·비식별 검사를 모두 통과한 자료만 dataset revision에 편입합니다. 정확 위치·원본 음성·식별 가능한 제3자 원본은 기본 제외하고, 승인일부터 3년 뒤 또는 철회 시 후속 학습에서 제외합니다.

승인 문장: “명시 승인 자료만 lineage와 함께 3년 보존하고 철회·만료 뒤 후속 학습에서 제외한다.”
6 관리자 중대 장애source·severity·상태전이·재인증

왜 결정이 필요한가

누가 장애를 만들 수 있는지와 CRITICAL 기준이 없으면 가짜 장애나 중복 경보가 관리자 화면을 채울 수 있습니다.

확정 구현안

허용된 내부 producer 또는 운영자만 stable ID로 생성하고 OPEN → ACKNOWLEDGED → RESOLVED와 명시적 REOPENED만 허용합니다. ACK·해결에는 재인증·사유·관찰 근거를 요구하며 자동 복구나 자동 제어는 수행하지 않습니다.

승인 문장: “허용 producer와 stable ID만 받고 ACK·해결은 재인증·사유·불변 이력을 요구한다.”
7 백업 복원 tombstone 재적용외부 원장·trusted head·복원 차단

왜 결정이 필요한가

삭제 원장이 복원 대상 DB 안에만 있으면 오래된 백업을 복구할 때 원장 자체가 사라져 삭제 자료가 부활합니다.

확정 구현안

DB 밖의 append-only 서명 원장을 신뢰 근거로 사용하고 격리 환경에서 수동 복원합니다. trusted head와 cutoff를 검증해 DB·이미지·raw·파생 자료에 tombstone을 재적용·대조한 뒤에만 서비스를 공개합니다.

승인 문장: “외부 서명 tombstone 원장을 복원 전에 재적용하고 검증 실패 시 서비스를 열지 않는다.”
코드 밖에서 받아야 할 것

외부 입력 7묶음

없다고 개발 전체가 멈추는 것은 아닙니다. interface·default-off·실패 테스트까지 만들 수 있지만 실제 활성화와 완료 판정은 할 수 없습니다.

① 휴대폰 본인확인 공급자

보호자 연동은 제거합니다. 만 14세 이상을 확인할 PASS·정식 SMS 본인확인 업체가 필요하며 NICE아이디가 1순위 상담 후보입니다.

  • 생년월일만 수신·CI/DI 미수신 가능 여부
  • sandbox·callback 서명·계약 주체·비용

② 한국어 wake-word 자산

과거 적용된 모델은 없고 현재는 버튼형 STT뿐입니다. Porcupine을 조건부 1순위로 조사했습니다.

  • 길라잡이 .ppn/.pv·SHA-256
  • 안전보조 앱 사용 서면 허용·offline/FAR/FRR 결과

③ 설치 후 전경 기기점검

가입·로그인 뒤 실제 휴대전화에서 점검하고 통과 전에는 기능을 잠급니다. 백그라운드 점검은 하지 않습니다.

  • FULL/LIMITED/FAIL/UNKNOWN 판정
  • 카메라·GPS·TTS·진동·저장공간·발열·queue 실측

④ 모델 서명·원격 교체

출시 단계로 유예했습니다. 지금은 APK/AAB 내장 모델·설정 hash 검증과 실패 시 안전 중지만 유지합니다.

  • 동적 다운로드·자동 rollback 없음
  • 출시 signer·forward-fix 절차는 마지막에 확인

⑤ 운영 인프라

local 테스트를 production object storage·KMS·TLS·backup으로 부를 수 없습니다.

  • cloud account·bucket·KMS·TLS
  • 격리 restore·rotation·alert 증거

⑥ 개인정보·위치 문안 검토

공식 자료를 반영한 회원가입·JIT 문안 초안을 만들었습니다. 김민호 검토 전에 사업자·수탁자·기간·수신기관 값을 채워야 합니다.

  • 한국어 문안 초안
  • 최종 검토·승인 ID와 적용 후보

⑦ 실환경 기능 체크리스트

사용자 앱·관리자 앱·Gateway·Backend·출시 종단을 실행 절차와 예상 결과로 정리했습니다.

  • 기능별 체크리스트
  • 기관 수동 ACK·현장/TalkBack·정식 279건은 실제 실행
