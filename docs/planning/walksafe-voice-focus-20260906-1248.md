# WalkSafe 음성 기능 집중 계획

- 시작: 2026-09-06 12:48 KST.
- 기존 프로젝트 검수는 별도 프로세스와 담당자로 유지한다. 기존 14:00 KST 점검 시점에 진행 상태를 보고하며, 미검증 기능을 완료로 표시하지 않는다.
- 동시 담당자는 최종 담당자를 포함해 7명 이하로 유지한다.
- 시스템 Goal은 기존 미완료 목표 때문에 새로 생성되지 않았다. 기존 목표에 포함된 음성 기능을 이 문서의 최우선 작업으로 구체화한다.

## 목표

사용자가 문장을 외우지 않고 목적지 설정 등 지원 기능을 요청하고, 인식 실패와 실행 결과를 음성으로 확인한 뒤 다시 명령할 수 있게 한다. 앱의 입력 엔진과 명령 해석, 출력 엔진과 안내 시점을 각각 검증한다.

## 단계와 검증

1. 입력 엔진 선택: 한국어 준비가 실제 확인된 Android 온디바이스 인식을 우선 검토하고 기존 Vosk 오프라인 경로를 보존한다. 검증: 설치 상태, 실제 인식 결과, 취소와 실패 callback, 동시 마이크 소유 수를 확인한다. 미지원 또는 데이터 미설치를 인식 성공으로 처리하지 않는다.
2. 명령 해석: 목적지 설정의 일반적인 말투를 지원하고 장소 원문을 보존한다. 검증: 사용자 예시와 일반 표현, 빈 장소와 모호한 입력, 취소·정지·신고의 부분 일치 오탐을 테스트한다. 학교 하나만 예외 처리하거나 모호한 장소를 자동 확정하지 않는다.
3. 출력과 재입력: 듣기 준비, 인식 불가, 명령 해석 불가, 검색 결과, 실행 실패와 취소를 실제 상태에 맞춰 안내한다. 검증: TTS의 실제 완료·실패 callback, 최신 응답만 반영, 교육 보호, 녹음 중 자기 음성 차단, 재입력 버튼 복구를 확인한다. 무한 자동 재녹음은 하지 않는다.
4. 서비스와 반복 사용: 화면 이탈·복귀, 시작 직후 중지, 취소 후 재시도를 검증한다. 검증: foreground-service pending-stop 재현과 보완 비교, 오래된 callback 무효화, 마이크 단일 소유를 확인한다.
5. 통합: 단위검사, APK 빌드, 가능한 실기기 확인, 사용자의 실제 발화 시험을 순서대로 진행한다. 검증: 말하기 → 명령 해석 → 검색·실행 → 응답 듣기 → 다음 입력이 연결되는지 확인한다.

## 경계

- 로그인·기기 점검·교육·실측 보행 조건을 우회하지 않는다.
- 실제 휴대폰의 계정·동의·앱 데이터를 유지한다.
- 외부 서버로 음성을 전송하는 경로를 임의로 추가하지 않는다.
- 합성 음성 시험은 실제 사람의 인식률이나 보행 안전성의 증거가 아니다.
- 위치 검색의 현재 위치 전달과 장소명 매칭은 음성 인식 엔진과 별도 계층이다.
- 발견한 새 회귀와 미검증 항목을 숨기지 않고 수정·검증 여부를 구분한다.

## 담당

- 최종 담당: Main 통합, Gradle, 에뮬레이터와 통합 검증.
- 입력 담당: 온디바이스 ASR 준비·진단·선택과 오프라인 대체 경로.
- 명령 담당: Android 명령 parser와 목적지 query 경계.
- 출력 담당: TTS 응답 보호·완료·세대 처리와 Main 연결 제안.
- 독립 검증 담당: 서비스 시작·중지와 엔진 독립 반복 사용 검증.
- 별도 검수: 기존 서버·DB 연결 시험 및 위치분석 JNI·native 회귀.
