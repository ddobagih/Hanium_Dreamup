4. 재개 단계

  1. 재개 fingerprint 확인

    HEAD, checkpoint, 세 assignment, output 부재와 dirty tree를 읽기 전용으로 다시 확인합니다.

    수용 기준: 위 기준선과 exact 일치하고 R001~R003의 result/independent가 없어야 합니다.

  2. review builder와 test를 active R004로 완성

    • R003 assignment를 세 번째 preserved input으로 exact pin하고 R003 output 부재를 검사합니다.
    • supersession reason은 R003_REVIEW_INPUT_COHORT_ABA_RETAINED_DESCRIPTOR_REQUIRED를 사용합니다.
    • confirmed finding은 REVIEW_INPUT_COHORT_ABA_CAN_PUBLISH_SELF_INVALID_EVIDENCE로 결속합니다.
    • assignment와 independent가 참조하는 전체 입력 cohort를 최초 open부터 게시 직전·직후 검증까지 retained descriptor로 유지합니다.
    • A→B→A 교체, inode·size·owner·mode·nlink 변화, close/fsync/rename 실패와 postcommit uncertainty를 fail-first로 고정합니다.
    수용 기준: builder 단독 회귀가 PASS하고 실제 review output은 한 건도 생성되지 않습니다.

  3. consumer·gate·catalog 계약을 R004에 맞춤

    continuation, Goal checker, repository catalog generator/test, private gate, seq77/seq78 apply와 각 test가 같은 active R004 triad와 R001~R003 preserved assignment를 보도록 맞춥니다.

    • 현재 review 경로 기대값은 preserved assignment 3개 + active R004 triad 3개, 총 6개입니다.
    • active R003 참조는 rejected history 검증에만 남기고 현재 authority로 사용하지 않습니다.
    • gate의 exact pytest selector와 후속 event가 생겨도 seq77·78 authority가 유지되는 suffix 검증을 유지합니다.
    • managed cohort는 게시 전후 같은 집합·내용인지 검증하고 임시 provisional digest를 고정값으로 쓰지 않습니다.
    수용 기준: 네 control 모듈, 두 checker와 catalog 계약이 모두 같은 R004 상수를 사용합니다.

    • 승인된 경우에만 R004 assignment/result/independent triad가 모두 존재하도록 합니다.
    • 파일은 add-only, regular file, 허용 mode, nlink 1과 게시 후 descriptor 재검증을 만족해야 합니다.
