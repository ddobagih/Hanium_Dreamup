# WalkSafe 위치 오차 개선 단계별 계획

작성: 2026-09-08. 대상: 원본 Android 사용자 앱 `kr.co.hanium.dreamup.walksafe`.

## 목표와 판정

현재 센서 융합에서 유효한 GNSS 관측이 손실되는 조건과 보폭 학습 편향을 재현하고 수정한다. 기존 사용자 데이터·계정·다른 작업의 변경을 보존한다. 지도상의 이동이 부드러워지거나 `Location.accuracy`가 작아지는 것만으로 실제 위치 오차 감소를 주장하지 않는다.

소프트웨어 완료 기준은 재현 시험, 수정 후 위치 관련 회귀 시험, Android 빌드, 별도 코드 검토 통과다. 실제 정확도 개선은 동시간 기준 좌표와 비교한 P50/P95/RMSE, 2m 이내 비율 및 위치 제공률로 별도 판정한다. 현장 기록·기준 좌표가 없으면 해당 결과는 미측정으로 남긴다.

## 단계 → 검증

1. **기준선과 재현**: 기존 추정기·관련 테스트를 보존하고 위치 단위 시험을 실행한다. GNSS보다 먼저 처리된 PDR/ZUPT, 직선·코너 보행, 중복·오래된 관측을 분리한다. → 기존 통과 수와 실제 실패 조건을 기록한다.
2. **지연 GNSS 수용**: 최신 GNSS보다 새로운 관측이 센서 이벤트 뒤에 도착한 경우, 제한된 과거 상태에 실제 측정 시각으로 적용하고 이후 운동 이벤트를 재계산한다. → 정렬 입력과 지연 입력의 최종 좌표·공분산 일치, 걸음 중복 미적용, 오래된/중복 관측 거부, 초기화·리셋·수치 실패 보존을 검증한다.
3. **직선 구간 보폭 학습**: 필터가 스스로 만든 PDR 좌표를 학습 정답으로 재사용하지 않는다. 원시 공급자 위치와 동시간 속도·방향·걸음 증거로 충분한 직진 구간만 학습한다. 회전·정지·품질 부족·시간 공백·걸음 리셋은 구간을 끊는다. → 직선 수용, L/U 회전·튀는 위치·누락 증거 제외, 저속/불확실 입력 및 리셋 시험을 수행한다.
4. **통합·비교**: Root가 원앱에 연결하고 위치 관련 회귀, 전체 사용자 앱 단위 시험, debug APK 빌드 및 lint를 실행한다. 별도 검토자가 시간·좌표·수명주기·회귀를 검토한다. → 실행한 결과와 미실행 범위를 보고한다. APK 생성과 설치·야외 검증은 구분한다.
5. **카메라 융합 타당성**: 기존 ARCore pose의 기준 좌표/앵커, 시각, 추적 품질, 재위치 인식·리셋과 GNSS 정렬 근거를 확인한다. → 신뢰 가능한 상대 이동 관측 계약이 있는지 판단한다. 근거가 부족한 시각 이동량을 보행 위치로 바로 적용하지 않는다. 현장 관측으로 채택 여부를 판단할 실험 조건을 남긴다.

## 책임

- Root: 계획·기존 변경 보존·MainActivity/Coordinator 통합·Gradle/ADB 단독 실행·보고·daylog.
- GNSS 담당: PedestrianPositionEstimator와 시간 처리 테스트. 다른 담당 파일 수정 금지.
- 보폭 담당: 독립적인 직진 보폭 학습 정책과 테스트. MainActivity는 Root가 연결.
- 카메라·평가 담당: ARCore 위치 융합 및 현장 데이터 존재 여부를 읽기 전용 조사한 뒤, 별도 배정으로 평가 앱의 비동기 기록 처리와 회귀 시험 구현.
- 독립 검토 담당: 통합 변경의 정확성·회귀 검토. 구현과 별도 인스턴스.

## 현장 비교

- 조건: 같은 휴대폰과 장착 방식, 개활지·건물 옆·회전·정지 구간. 튜닝 기록과 확인 기록을 분리한다.
- 비교: 공급자 원좌표 / 융합 좌표 / 경로 매칭 좌표를 각각 같은 시각의 기준에 비교한다. 실패 구간을 지워서 성능을 높이지 않는다.
- 기준: 독립 측량 기준이 우선이다. 같은 휴대폰의 GNSS를 PPK 처리한 결과는 품질을 확인한 개발용 비교값이며 독립 정답으로 간주하지 않는다.
- 기존 평가앱과 오프라인 평가 도구를 재사용한다. 이 작업에 불필요한 새 통제·게이트 시스템은 추가하지 않는다.
- VPS는 시험 위치의 지원 여부·실제 위치 추정 품질을 확인한 뒤 별도 연결을 판단한다. 외장 RTK 도입은 추가 장비가 필요한 선택 사항이다.

## 진행 상태

- 1~4단계 소프트웨어 구현·통합·검증 완료. 지연 GNSS 재현을 수정하고 직진 보폭 학습·신뢰도·평가 기록에 연결했다.
- 최종 격리 검증: 사용자 앱 2,511개 통과·기존 1개 건너뜀, 평가 앱 76개 통과, 오프라인 도구 15개 통과. 두 앱 debug 빌드 및 Lint 성공(오류 0, 경고 사용자 앱 140개·평가 앱 10개).
- 독립 코드 검토 지적을 수정하고 재검토 완료. 변경한 소스·시험·스크립트 18개는 원본과 검증 복사본의 해시가 모두 일치했다.
- 동시에 진행 중인 실행 구성 변경은 검증 복사본에서만 제외했다. 원본의 다른 작업과 기존 WIP를 보존했다. APK 생성 완료, 설치·현장 시험 미실행.
- 5단계 카메라 타당성 조사 완료. 시각·지리 좌표 정렬을 먼저 검증해야 하므로 카메라 이동량 융합은 활성화하지 않았다.
- 실제 현장 오차 개선: 미측정. 아래 보고서의 현장 비교가 다음 단계다.
