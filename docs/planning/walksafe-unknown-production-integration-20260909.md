# FastSAM 768 원본 앱 및 음성 안내 연결 실행 계획

2026-09-09. 사용자 승인 범위: 단계별 구현·검증을 거쳐 원본 사용자 앱의 음성 안내까지 연결한다. 이전 별도 시험 APK의 완료를 제품 통합 완료로 사용하지 않는다.

기존 YOLO26n 768과 사용자 데이터는 유지한다. 추가 모델은 검증한 FastSAM-S 768이며 640 자동 전환은 없다. 실기기는 SM-G981N, 후면 바닥 방향 조건을 유지한다.

|---|---|---|---|

단계 1~3의 독립 구현과 4의 정책·시험 준비를 병렬로 진행한다. MainActivity와 APK·ADB·daylog는 Root만 변경·실행한다. 같은 제품 파일의 수정 담당은 한 명으로 제한한다.

5분은 모델 준비·예열·후보 비교·정리를 포함한 하나의 점검 요청 정책 예산이다. native 호출을 강제 중단할 수 없어 실제 정리는 이를 넘길 수 있다. primary 점검 뒤 별도 5분을 추가하지 않는다. 앱 내부에서 취소할 수 없는 native 호출의 종료는 실제 관측과 구분하며, 기한이 지나면 새 작업·선택 확정을 차단하고 소유권 정리가 끝날 때까지 재사용하지 않는다.

현재 바닥 방향에서는 이전 시험에서 양수 raw/full 깊이가 없었다. 합성 자료로 처리·발화 경로를 검증하고 실제 입력의 미확인 상태를 확인할 수 있으나, 독립 거리 기준에 대한 실물 접근 정확도를 완료로 표시하지 않는다.

## 착수 상태

- 이전 0~2단계 별도 APK 시험과 v2 추적 후보·실패 반례를 보존했다.
- 원본 앱은 기존 ObjectTracker → DepthEstimator → MessagePolicy 및 feedback 경로를 사용한다. 새 경로도 이 정책을 재사용한다.
- 영역 실행, 깊이 연결, tracker, 기기 선택, 음성 정책, 정답 자료, 독립 검토로 담당을 재개했다.
- 현재 진행 상태와 후속 검증 결과는 daylog 및 통합 보고서에 이어 기록한다.

## 2026-09-09 제품 통합 실행 결과

1~4단계 제품 코드 연결과 관련 회귀를 완료했고, 5단계 원본APK 빌드·데이터유지설치 및 실제모델/한국어TTS 시험을 수행했다. 최종 관련 JVM413시험이 통과했다. 실제 Main dispatcher에서 합성 객체 접근/사용자 전진 문구를 구분하여 실제 TTS완료까지 확인했다.

primary 재점검 필요시 먼저 비교하며 남은 시간의1/3(최대100초)을 배정한다. 실제 해제 완료 후 보조 비교를 같은 원래300초 마감으로 이어간다. GPU coldload76초 실측 때문에 보조 준비시간을 남긴 조정이다. 미완료 비교는 cursor/pending을 보존하며 실부하 증거가 부족하면 최적 profile이 아닌 임시 실행으로 유지한다.

원본 안내 연결 완료와 현장 접근 정확도 완료는 구분한다. 별도 heldout의 대응된 동적 관측283개에서 확정 이동방향0개, ID혼입1사례가 남아 있으며 그 관측은 운동이력0/UNKNOWN으로 접근발화를 만들지 않았다. 다음은 유효ARCore깊이와독립거리기준을확보한 실제접근·누락·오경고·지연 측정이다. 현재바닥방향제약에서 재배치를 반복요청하지 않는다.
