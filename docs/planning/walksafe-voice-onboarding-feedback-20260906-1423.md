# 실기기 음성·교육·검색 피드백 반영

## 목표와 검증

1. 호출어/일반 명령 실패 분리 -> 검증: 코드 경로와 개인정보 없는 단계별 진단.
2. 안전 교육 -> 사전 연습 구성 및 재생 버튼 수정 -> 검증: 기존 완료·동의 정책과 UI 계약 회귀.
3. 학교 약칭 검색 개선 -> 검증: 실제 공급자 정렬 비교 및 Backend 행동 테스트.
4. 설정 기술 문구 제거 -> 검증: 표시만 숨기고 동의 동기화 로직 유지.

## 확인한 원인

- 기기점검 호출어는 `vosk-model-small-ko-0.22`를 쓰는 VoskWakePhraseProbe다. 전용 호출어 모델이 아니라 일반 음성 인식의 최종 결과를 검사한다.
- 유효 단어 신뢰도 평균 0.60 이상이고, 호출어가 정확한 `길라잡이` 또는 `길라 잡이`로 판정되어야 성공한다. partial은 성공으로 사용하지 않는다.
- 20초 제한에 모델 시작과 입력 억제 시간이 포함된다. 낮은 점수·호출어 불일치·최종 결과 없음은 같은 timeout 결과로 합쳐졌다. 이 타이머와 임계값은 이번에 변경하지 않았다.
- 호출어 실패가 공통 STT 사용 불가 상태도 덮는 결합을 확인했다. 호출어 실패/핸즈프리 제한은 유지하면서 공통 STT 상태를 덮는 동작만 분리했다. 이것이 사용자의 이번 HOME 실패를 일으켰다고 확정한 것은 아니다.
- `편의점 안내해줘`는 현재 parser에서 지원한다. 이전 parser 캐시를 근거로 조사 누락이 원인이라는 초기 후보는 철회했다.
- 기존 휴대폰 로그의 TTS private-engine binding 거부는 Google fallback 기록과 함께 있었다. 그 경고만으로 실제 출력 실패라고 단정할 수 없다.
- 교육 전체 재생 Boolean을 첫 버튼에 사용해 두 번째 안내 중 첫 버튼이 중지로 표시됐다.
- 실제 TMAP `금오공대` 검색은 본교도 매칭했다. 같은 공개 서울시청 기준점에서 국립금오공과대학교는 거리순 30위, 정확도순 1위였다. 서버가 최대 10건만 요청해 거리순에서는 본교가 반환 범위 밖이었다. 사용자 실제 위치를 사용한 비교는 아니다.

## 반영 사항

- 안전 교육 이후 사전 연습으로 제목·본문 순서를 정리했다. 착용·사용환경 설명은 사전 연습 안내에 포함하고 독립 사용환경 제목을 제거했다.
- 가슴형/목걸이형 UI 구분을 공통 정면 고정 확인 하나로 통합했다. 몸 앞 세로 고정, 상단 위쪽, 후면 카메라 바깥쪽, 전면 시야 조건은 유지했다.
- 두 내부 장착 method는 같은 검사 조건이다. 기존 method는 유지하고 신규 사용자 확인에는 legacy 호환값을 사용한다. 실제 카메라·프로필·epoch·freshness 검사는 우회하지 않는다.
- 재생 중인 해당 버튼만 중지 가능하며 완료 후 다시 듣기로 표시한다. 이미 완료한 두 안내의 이력과 재청취 중 동의 가능 조건은 보존했다.
- 설정의 개인정보 서버 확인 요약은 표시만 숨겼다. 선택 동의·동기화·실패 처리·저장 로직은 유지했다.
- 보수적으로 판별한 학교 기관명 단독 검색만 정확도순을 사용한다. 편의점 등 주변 검색과 시설을 명시한 질의는 거리순을 유지한다. 검색어·현재 위치·후보 확인·반환 한도는 변경하지 않았다.
- DEBUG 전용 `WalkSafeVoiceInput` 진단으로 엔진 선택, ready, final 개수, 신뢰도 범주, 호출어/명령 판정, 출력 접수/완료/실패를 분리했다. 발화 원문·오디오·계정·토큰은 기록하지 않는다.
- 모델 교체, partial의 final 승격, 점수 조작, 신뢰도 기준 완화는 하지 않았다.
