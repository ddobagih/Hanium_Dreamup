목표 서비스의 전체 흐름

아래 순서가 기능별 설명을 읽는 기준입니다. 세부 예외는 각 기능 카드에 모두 남겨 두었습니다.

  1. 첫 실행설명·동의·권한을 확인하고 가입 또는 로그인합니다.
  2. 보행 준비카메라·위치·음성을 점검한 뒤 카메라 중심 화면으로 들어갑니다.
  3. 길안내와 경고TMAP은 큰 경로를, 단말 모델은 가까운 장애물과 점자블록을 안내합니다.
  4. 신고와 데이터신고는 서버로 보내고, 학습용 활동데이터는 걷지 않을 때만 전송합니다.
  5. 장애와 종료지속 장애는 유형을 알리고 안전하게 멈춘 뒤 확인된 절차로 복구합니다.

온디바이스

영상이나 음성을 서버로 보내지 않고 사용자 휴대폰 안에서 바로 처리하는 방식입니다.

STT·TTS

STT는 사람의 말을 글자·명령으로 알아듣는 기능이고, TTS는 글을 음성으로 읽어주는 기능입니다.

TalkBack

화면의 버튼과 글을 음성으로 읽고 손가락 동작으로 조작하게 돕는 Android 화면 읽기 기능입니다.

queue

지금 보내지 못한 신고나 데이터를 잃지 않도록 순서대로 잠시 보관하는 대기열입니다.

hash·receipt

파일이 온전히 도착했는지 확인하는 지문값과 서버의 수신 확인증입니다.

gate·rollback

gate는 다음 단계로 가기 전 반드시 통과할 조건, rollback은 문제가 생겼을 때 이전 정상 버전으로 되돌리는 절차입니다.

confidence·stale

confidence는 모델이 결과를 얼마나 믿는지 나타내는 값이고, stale은 시간이 지나 현재 상황에 쓰면 안 되는 오래된 결과입니다.

frame·TTC

frame은 카메라 영상 한 장, TTC는 지금 속도로 움직일 때 장애물과 부딪치기까지 남은 예상 시간입니다.

chunk

큰 영상·음성 데이터를 안전하게 저장하고 이어 보내기 위해 나눈 작은 데이터 조각입니다.

IdP·MFA

IdP는 로그인 신원을 확인하는 시스템이고, MFA는 비밀번호 외에 한 가지 이상을 더 확인하는 다중 인증입니다.

gateway

앱의 서버 요청을 한곳에서 받아 인증과 제한을 확인한 뒤 알맞은 서버 기능으로 보내는 공통 출입구입니다.

RTO·RPO

RTO는 장애 뒤 서비스를 다시 살리는 목표 시간, RPO는 복구할 때 허용할 수 있는 최대 데이터 손실 시간입니다.

SEV·telemetry

SEV는 장애 심각도 등급이고, telemetry는 앱과 서버 상태를 운영자가 확인하도록 보내는 성능·오류 기록입니다.

cooldown·idempotency

cooldown은 같은 신고를 잠시 다시 만들지 않는 대기시간이고, idempotency는 같은 요청을 여러 번 보내도 결과를 한 번만 만들게 하는 중복 방지 원칙입니다.

reconciliation·redaction

reconciliation은 서버 기록과 파일이 서로 맞는지 찾아 바로잡는 작업이고, redaction은 저장하거나 전달하기 전에 불필요한 민감정보를 가리는 처리입니다.

rate limit

짧은 시간에 너무 많은 요청이 몰릴 때 허용 횟수를 제한해 서버와 다른 사용자를 보호하는 기준입니다.

sampling·drop

sampling은 운영 기록 일부만 대표로 남기는 방식이고, drop은 중요도가 낮은 기록을 버려 안전 기능에 필요한 자원을 지키는 처리입니다.

postmortem

큰 장애가 끝난 뒤 원인, 영향, 대응, 재발 방지 할 일을 책임자와 함께 기록하는 사후분석입니다.
