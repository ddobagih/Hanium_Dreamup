# 미학습 객체 영역·깊이·원본 음성 안내 통합 결과

2026-09-09. 원본 사용자 앱 `kr.co.hanium.dreamup.walksafe`에 추가 영역 인식에서 기존 음성 안내까지 연결했다. 기존 YOLO26n 768은 유지하고 FastSAM-S 768을 추가했다. WalkMate21cls 모델 교체는 하지 않았다.

## 적용한 처리 흐름

카메라 영상 → 기존 YOLO 및 별도 FastSAM 영역 추론 → 같은 촬영 프레임의 raw depth·confidence·좌표 변환·pose 결합 → 영역 연속 추적 → 유효 거리·객체/사용자 이동 판정 → 기존 위험 우선순위 → 한국어 음성 안내.

FastSAM은 물체 이름을 몰라도 영역을 제안한다. 모든 미학습 물체를 검출한다고 보장하지 않으며, 기존 모델이 아는 물체도 제안할 수 있다. 단순 바운딩 박스 중첩만으로 두 경로의 객체를 제거하지 않는다.

- 원본 이미지의 버퍼 위치·crop·stride를 지키며 빌린 camera Image는 해당 프레임 작업에서만 사용한다. 전처리 복사가 끝나면 기존 소유자가 반환한다.
- GPU 모델 작업과 CPU 마스크 후처리를 분리한다. 기존 추론과 보조 추론은 서로 다른 수명주기를 가지며, 오래된 대기 결과는 폐기한다.
- 보조 거리 판정은 raw depth와 confidence의 시각이 일치하는 캡처만 사용한다. 전체 객체를 대표하지 못하는 PARTIAL 깊이로 전체 거리를 말하지 않는다.
- 카메라 세대·화면 형상·보행 세션이 달라지면 이전 결과를 무효화한다. 앱이 기록한 캡처 기준시각부터 800ms가 지난 결과는 새 음성을 시작하지 않는다. 이 기준시각은 센서의 실제 노출시각이 아니다. 기한 안에 실제 시작한 문장은 실제 TTS 완료 콜백까지 정상 처리한다.
- 접근/정지물 접근 설명은 현재의 유효한 이동 근거가 있을 때만 붙인다. 회전·깊이 없음·대표 영역 변경·모호한 대응에서는 이동 이력을 초기화하거나 보류한다.

## 휴대폰에서 직접 확인한 결과

FastSAM 제품 모델/전처리/decoder를 원본 APK에서 CPU 1스레드, GPU 순서로 실행했다. 공개 사진 1장과 검정 이미지 1장이며 반복 성능 벤치마크·최적 후보 비교는 아니다. 사진 원본은640×425지만 모델 입력은768×768이다.

| 항목 | CPU 1스레드 | GPU |
|---|---:|---:|
| 첫 로드 | 117ms | 76,220ms |
| 사진 모델 추론 | 1,556ms | 200ms |
| 사진 마스크 후처리 | 116ms | 47ms |
| 사진 제출→마스크 완료 | 1,752ms | 267ms |
| 검정 이미지 모델 추론 | 1,577ms | 195ms |
| 사진/검정 마스크 개수 | 25 / 0 | 25 / 0 |
| 실제 backend 및 native 해제·스레드 종료 | 확인 | GPU 확인, CPU fallback 없음 |

모든 출력 tensor 유한값·형상·마스크 경계를 확인했고 전체 시험은80.9초였다. 여기에는 실제 ARCore 깊이 처리·기존 모델 동시 부하가 포함되지 않으므로 원본 앱 전체 FPS나 거리 판정 처리율로 바꾸어 말하지 않는다. FastSAM 모델 SHA256: `7e65b23c52bc4a78f45c7a26ac49a8b0a3f9fc8b8ba8c98ef40f2bf45f738609`.

한국어 TTS/STT 데이터는 이미 설치되어 있어 추가 설치가 필요하지 않았다. 음성 컴포넌트3시험에서 만료된 입력·메인 루프 지연·실제 완료를 확인했다. 원본 Main 통합시험에서는 합성6상황과 무발화3경계, 실제 발화2상황을 확인했다.

- 물체 접근: “전방 약 2보 이내 물체. 이 물체가 사용자 쪽으로 다가오는 것으로 보입니다. 멈추세요. 주변을 확인하세요.”
- 사용자 전진: “전방 약 2보 이내 물체. 정지해 있는 것으로 보이며, 현재 이 물체에 가까워지고 있습니다. 멈추세요. 주변을 확인하세요.”

두 안내 모두 기한 안의 실제 시작 검사와 실제 완료 콜백, 공유 정책의 전달 확정을 통과했다. 합성 1.2m/11프레임 자료이며 실물 관측이라고 주장하지 않는다.

## 성능 점검과 재평가

기존 primary 재점검 필요 여부를 유지한다. 필요하면 보조 실행기를 실제 해제한 뒤 primary 비교를 먼저 수행하고, 새 primary 소유자로 재바인딩해 같은 원래 마감시각 안에서 보조 비교를 이어간다. primary 비교가 필요 없으면 보조 비교로 바로 간다. 동시에 서로 다른 비교 후보를 여러 개 열지 않는다.

요청 전체는 준비·예열·비교·정리를 포함해300초를 선택·새 작업 시작의 정책 마감으로 적용한다. 실행 중인 native 호출을 강제 중단할 수 없어 실제 정리는300초를 넘길 수 있다. S20에서 추가 모델의 GPU cold load만76초였으므로 primary 단계에는 남은 시간의1/3, 최대100초를 배정해 추가 모델 준비 시간을 남긴다. 이는 CPU 스레드 비율이 아니라 두 점검 단계의 시간 배분이다. native 정리가 지연되면 실제 남는 시간은 더 짧아진다. 기한 초과 때 새로운 선택을 확정하지 않으며 실제 해제 완료 전 새 소유자를 만들지 않는다.

보조 비교는 CPU 기준 출력 검증 후 GPU 우선 후보를 평가하고 CPU 스레드는 가능한 정수 후보를 탐색한다. 기존 primary 설정을 고정한 조합 비교이며 모든 primary×auxiliary 조합의 전역 최적해 탐색은 아니다. 실제 동일 부하의 비교 증거가 부족하면 `profile=null`인 임시 실행기만 유지할 수 있고 최적값으로 저장하지 않는다. 이번 GPU cold load에서는 5분 안에 전체 A/B·B/A 확정이 어려울 수 있다.

이전 비교가 미완료되면 cursor/pending을 남긴다. 실제 실행 오류나 지속적인 부하 저하는 다음 기기 점검의 재평가 사유로 기록한다. 일반 실행 중에는 부하에 맞춰 추론 간격을 조절하며 그 자리에서 무거운 전체 벤치마크를 반복하지 않는다. 앱 종료·사용자 취소·단순 시간 만료를 GPU 미지원으로 영구 판정하지 않는다.

## 남은 정확도 한계

- 휴대폰 후면이 바닥을 향한 조건을 유지했다. 이전 실카메라 시험에서 유효 깊이가 없었으며 이번 합성 시험으로 ARCore 물리 깊이·60fps를 입증하지 않는다.
- 별도 MOVi-E heldout에서 가시 정답315개 중 mask IoU0.5 대응283개(89.84%)였지만, 대응된 동적 관측283개에서 확정된 이동 방향은0개였다. 검출 영역 회복률과 접근 판정 정확도는 다르다.
- heldout에서 같은 화면 위치의 서로 다른 물체가 한 ID로 연결된1사례가 있다. 그 관측은 depth UNKNOWN/운동이력0으로 접근 판정을 만들지 않았다. ID가 같다는 사실만으로 물리적으로 같은 객체라 확정하지 않는다.
- 깊이 지지 영역의 겹침 기준이 보수적이어서 이동·확대 중 이력이 자주 초기화될 수 있다. 현재 단계는 원본 음성 경로 연결 완료이며 실제 미학습 객체의 연속 접근 탐지율 완료가 아니다.

후속 현장 검증은 밝은 장면의 유효 raw depth, 독립 거리/이동 기준, 사용자 정지·전진·물체 접근 시퀀스를 확보해 누락률·거짓 접근·경고 지연을 각각 측정하는 단계다.
