# 시선 방향과 실제 경로 위치를 반영하는 음성 안내

## 요청과 성공 기준

후면 카메라가 사용자 앞을 향하는 세로 사용에서 첫 안내와 이후 안내가 현재 바라보는 방향을 설명해야 한다. 분기점으로 접근하다 되돌아가거나 다시 접근해도 현재 남은 거리와 다음 행동을 안내해야 한다. 특정 좌표나 70/20/9m 값에 조건을 맞추지 않는다. 사용자가 요청한 정상 발화 완료 후10초 재안내와 명시적 테스트 제한 우회는 유지한다.

## 단계

1. 시선 heading, 이동 course, 경로 방위 연결과 취소/문장 생성을 독립 조사한다.
2. 기존 후면 카메라 방향의 진북 heading을 별도 시선 입력으로 연결한다. 경로 매칭의 이동 course와 혼동하지 않는다. 시각·정확도·자세가 유효하지 않으면 앞/뒤를 추측하지 않는다.
3. 현재 경로 투영 위치와 과거 최대 진행도를 분리해 거리 증가 및 이전 분기점 재접근을 처리한다. 단일 위치 오차로 분기점이 왕복 전환되지 않도록 위치 근거와 연속성을 확인한다.
4. 정방향/반대방향/재접근/지나침/방향 불확실/위치 불확실/도착·경로 변경을 구분한다. 회전 지시가 실제 시선과 충돌하거나 뒤로 걸으라는 문장이 되지 않도록 한다.
5. 동일 입력의 수정 전후 재현과 관련 회귀, 구현자와 다른 인스턴스의 최종 검토 후 피드백을 반영한다.
6. APK를 빌드한다. 실제 야외 방향·위치 정확도와 스피커 청취는 사용자 시험 범위로 구분한다. 시작 시 USB 기기는 연결되어 있지 않았다.

## 확인된 원인과 구현

1. 기존 `progressDistanceM`은 지금 위치가 아니라 지금까지 가장 멀리 간 값이었다. 후퇴해도 줄지 않았으며, 후퇴 허용 범위와 25m 근접 선분 선택이 겹쳐 다음 선분 시작점을 현재 위치로 고르기도 했다. 현재 투영거리로 남은 거리를 계산하고, 지난 안내 지점은 정확도 여유를 넘는 신선한 위치 2개로 복원한다. 중복 위치·타이머는 관측을 추가하지 않는다.
2. 기존 후면 카메라 −Z 축의 진북 방향 센서는 있었지만 경로 발화에 전달하지 않았다. Main의 최초 update·재시도·수동 요청에 별도 `RouteFacingObservation`을 연결했다. 경로 매칭의 GPS 이동 course와 시선을 혼용하지 않으며, 기존 보행/PDR 장착 확인은 별도 책임으로 둔다. 테스트 위치 경로에서도 센서 시작과 지자기 편각 기준을 갱신한다.
3. 상대 방향은 신선도 500ms·보고된 95% 방향 오차 30도 이내와 기존 후면 자세 검사를 통과한 자료에서만 계산한다. 앞·뒤를 확정할 수 없더라도 좌우 정렬 방향이 확실하면 좌우를 설명한다. 시선/위치/경로 방위가 불확실하면 경로 기준 안내임을 명시하며 GPS 이동 방향으로 대신 단정하지 않는다. 이는 안내 시작을 차단하는 새 기기점검이 아니다.
4. 수동 “다음 안내”는 자동 안내와 같은 현재 위치 context, 시선, 발화 예약·실패 재시도·완료 토큰을 사용한다. 새 위치 관측으로 중복 집계하지 않는다. 도착/경로 이탈의 사용자 결정 대기 상태에서는 실제 선택지를 설명한다.
5. 도착·이탈 선택 안내는 실제 발화가 완료된 뒤 전달 완료로 기록한다. 출력 억제/재생 실패는 현행 결정에만 재시도하고, 다른 명령·녹음·음성 입력이 끝나기를 기다린다. 새 명령이나 generic 취소가 이전 콜백을 지우기 전에 결정 안내의 실패를 전달해 재시도가 사라지지 않게 했다. 경로 교체·화면 pause·이전 완료 콜백이 새 출력에 관여하지 못하도록 소유권을 확인한다.
6. 도착 아님을 선택한 뒤 같은 위치에서 바로 재질문하지 않는다. 확실히 도착 영역을 벗어난 새 관측 2개 후 다시 접근해야 후보를 재평가한다. 도착 후보에서 옆길로 떠날 때도 경로 매칭 성공과 별개로 raw·filtered 양쪽 위치가 정확도 여유를 넘겨 벗어났는지 확인한다. 중복·불일치·부정확 좌표나 긴 간격은 이탈 증거로 이어 붙이지 않는다.
7. 겹치는 왕복 구간은 현재 진행 단계가 모호하다는 근거를 유지한다. 사용자가 승인한 DEBUG 안내 제한 우회에서는 모호한 세 가지 경로 상태에서도 speech-only 추정 안내를 계속한다. 대신 추정임을 설명하고 앞·뒤·좌·우를 단정하지 않는다. 이를 accepted match나 다른 기능의 위치·방위 근거로 승격하지 않는다. 일반 모드에서는 모호한 구간의 확정 안내·도착 판단을 하지 않는다.

## 안내 예시

- 경로가 사용자 뒤에 있을 때: “경로 진행 방향이 뒤쪽입니다. 경로 방향으로 몸을 돌리세요. 경로 기준으로 70m 앞, 오른쪽으로 꺾으세요.”
- 제자리에서 올바른 방향으로 몸을 돌린 다음 안내: “현재 바라보는 앞쪽이 경로 진행 방향입니다. 경로 기준으로 70m 앞, 오른쪽으로 꺾으세요.”
- 분기점에서 멀어질 때: 실제 현재 위치에 맞춰 9m → 20m → 70m로 남은 거리가 증가한다. 특정 70/20/9 값에 맞춘 분기는 없다.
- 시선을 확인할 수 없을 때: “현재 바라보는 방향을 확인할 수 없습니다. 다음은 경로 기준 안내입니다.” 뒤에 현재 경로 정보를 설명한다.

첫 발화에는 전체 경로 소개도 포함한다. 같은 안내 지점의 진행 중 문장은 시선·거리 변화로 끊지 않는다. 실제 발화 완료 후 10초 재안내에서 현재 위치와 시선을 다시 사용한다. 명시적 다음 안내 요청은 같은 예약/완료 경계 안에서 반복 가능하다.

## 단계별 검증과 진행 상태

- 수정 전 독립 고정 재현: L자 경로에서 현재 진행거리 30 → 80 → 30 → 91 → 80 → 30m. 기대 남은 거리 70 → 20 → 70 → 9 → 20 → 70m, 실제는 70 → 20 → 20 → 9 → 0 → 0m였다.
- 1차 수정 후 같은 독립 자료: 기대 거리와 일치. 기존 11상황의 12계약 관측에서 수정 전 8실패 → 수정 후 0실패. 경로 진행 구현자 시험 134건, 시선 helper 시험 17건 통과.
- 음성 독립 검토: 수동/자동 기준 불일치, 실패한 결정 발화를 이미 전달한 것으로 소비, 도착 거절 뒤 즉시 재질문을 재현했다. 개선 후 다른 명령이 콜백을 지우면 재시도가 사라지는 경계도 추가 보완했다. 실제 Main 메서드와 실제 callback registry를 제어 JVM에서 연결한 14건 통과.
- 추가 후퇴/도착 경계 독립 검토에서 옆길로 벗어나도 도착 후보가 남는 문제를 발견했다. 해당 조건과 DEBUG 모호성 추정 안내를 보완한 신규 구현자 회귀 4개는 수정 전 실패 → 수정 후 통과했고, 경로 관련 직접 시험 전체 138건이 통과했다.
