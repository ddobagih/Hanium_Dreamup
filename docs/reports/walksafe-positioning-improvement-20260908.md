# WalkSafe 위치 오차 개선 구현·검증 보고서

2026-09-08 · 원본 Android 사용자 앱 및 위치 평가 앱

## 결과와 범위

지연 GNSS 관측을 버리던 조건을 재현하고 제한된 과거 상태 재계산으로 수정했다. 보폭 학습은 필터 출력 대신 원본 공급자 위치와 같은 관측의 속도·방향을 사용하며, 충분히 긴 직선 보행만 수용한다. 위치 신뢰도와 평가 기록도 실제 측정 시각에 맞춰 수정했다.

실제 야외 위치 오차 개선량은 **미측정**이다. 소프트웨어 재현·회귀 결과와 실외 정확도 검증을 구분한다. 카메라 이동량은 지리 좌표·시각 정렬 근거가 부족하여 이번 보행 추정기에 활성화하지 않았다.

## 구현 세부사항

### GNSS 시간 처리

- 기존에는 PDR/ZUPT가 필터 시각을 앞당기면 뒤늦게 도착한 유효 GNSS도 `OUT_OF_ORDER`로 거부했다.
- 이제 마지막 수용 GNSS보다 새로운 측정에 대해 최대 **5초·128개 운동 이벤트** 안에서 과거 상태를 복원하고 GNSS 보정 뒤 운동을 한 번씩 재실행한다. 고빈도 이벤트에서는 실제 보관 기간이 5초보다 짧다.
- GNSS 자체의 중복·역순, 너무 오래된 관측, 리플레이 한도 초과, 잘못된 좌표·모의 위치 등의 거부는 유지한다. 무조건 오래된 관측을 수용하지 않는다.
- 실제 GNSS 측정 시각의 추정값과 재계산 후 최신 추정값을 각각 제공한다. 신뢰도 회복에는 서로 다른 유효 GNSS 증거만 사용하고 센서 HIGH 또는 정보량이 낮은 보정은 회복 횟수를 늘리지 않는다.
- debug `WalkSafePositioning` 로그에는 수용/거부 사유, 관측 나이, 상태 대비 지연, 재실행 수만 기록한다. 좌표·사용자 식별자는 넣지 않는다.

### 보폭 학습

- 원본 `Location`의 좌표와 동일 측정의 속도·방향·정확도 정보를 사용한다. 여기서 원본은 앱 자체 PDR/필터/지도 매칭 전의 Fused 좌표이며, 위성 원시 관측이라는 뜻은 아니다.
- 학습은 최소 **15m, 10초, 20걸음**이며 두 끝점 불확실성의 합성값보다 충분히 큰 변위를 요구한다. 짧은 GNSS 이동거리를 계속 더해 잡음을 보행거리로 학습하지 않는다.
- 500ms 초과 지연, 방향 전환, 정지, 관측 공백, 걸음 수 리셋, 속도·좌표 불일치는 구간을 끊는다. 원앱에서는 최근 MOVING 센서 증거도 요구한다.
- 기존 개인 프로필을 삭제하지 않는다. 새 학습 결과도 기존 중앙값/제한된 갱신 경로로 반영한다.
- 조건은 보수적인 초기값이다. 학습 기회가 적어질 수 있고, 500ms 이내 걸음 수 시각 오차와 Fused 속도의 상관관계는 남는다.

### 기록과 평가

- GNSS 행에는 해당 측정 시각의 좌표만 기록한다. 이후 운동을 재실행한 현재 좌표·경로 매칭은 별도 행에 기록한다.
- 기록 순번·수신 단조 시각·해시는 보존한다. 평가 앱은 측정 시각으로 정렬해 지연 관측과 동일 시각의 마지막 보정값을 처리한다.
- Android ns 시각과 UTC ms 사이의 양자화 차이는 원본을 변경하지 않고 평가 시각에서 최대 1ms만 앞으로 정규화한다. 100ms 원시 UTC offset 범위, 누적 2ms 역행 등 실제 시간 오류 검사는 유지한다.
- raw/filtered/matched는 채널별 최신 유효 관측과 기존 2초 한도로 평가한다. 경로 매칭이 실패한 새 보정은 이전 성공 매칭을 무효화한다.
- trace v2에 선택 Boolean `route_match_evaluated`를 추가했다. 새 기록은 함께 제공하는 업데이트된 평가 앱/오프라인 도구로 읽는다. 이전의 엄격한 평가 앱은 새 필드를 거부할 수 있다. 기존 기록과 보관 자료는 수정하지 않았다.

## 다음 현장 검증

1. 원앱의 기존 위치 평가 기록 기능으로 개활지 직선·건물 옆·L/U 회전·정지/재출발을 각각 기록한다. 같은 휴대폰·장착 방식을 유지한다.
2. 같은 시각의 신뢰 가능한 기준 좌표를 준비한다. 같은 휴대폰의 GNSS를 PPK 처리한 값은 품질을 확인한 개발용 비교값으로 한정하고 독립 측량 정답으로 단정하지 않는다.
3. raw/filtered/matched별 P50, P95, RMSE, 2m 이내 비율, 위치 제공률을 비교한다. 실패 구간과 큰 오차를 제외하지 않는다.
4. 진단 로그로 GNSS 수용률·리플레이 비율·한도 초과를 확인하고, 보폭 학습 표본 수와 회전 구간 오학습 여부를 확인한다. 학습용 경로와 확인용 경로를 분리한다.
5. 이후 ARCore와 지구방위 센서의 시각을 정렬하고 anchor→camera→sensor→true ENU의 3D 회전을 검증한다. 같은 anchor의 상대 이동을 먼저 관찰하고, PDR 중복 누적 없이 융합할 수 있을 때 위치 관측으로 적용한다.

저장소 조사에서는 실제 실외 WalkSafe 기록과 동기화된 기준 좌표 쌍을 찾지 못했다. 합성·계약 fixture 및 공개 GNSS 시험 자료를 현장 성능 근거로 사용하지 않았다.
