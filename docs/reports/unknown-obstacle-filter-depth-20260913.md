# FastSAM 전방 후보 선별·깊이 보완·안내 시작 수정

2026-09-13. 원본 사용자 앱 debug APK. 고정 시험 자료는 사용자가 준비한다.

## 원인과 변경

1. **무분별한 영역 표시**: 카메라 테스트가 FastSAM 마스크 전부를 표시했다. FastSAM 자체는 클래스 이름 없이 영역을 나누므로 이미 학습된 물체도 포함한다. 이제 원본 마스크를 세로 화면 방향에 맞춰 전방 영역과 비교한다. 화면 가로 25–75%, 세로 12–95% 띠 안에 실제 마스크 픽셀의 20% 이상이 들어오는 영역을 후보로 삼는다. 박스만 겹치고 실제 마스크에 구멍이 있으면 통과하지 않는다.
   - 거리 4m 이내 또는 기존 추적의 TTC 10초 이내 후보를 유지한다. 1.2m 이내를 제외하면 2회 이상·250ms 이상 반복 관측을 요구한다. 이것은 후보 선정이며 최종 경고 조건과는 다르다.
   - 무거리 전방 영역은 반복 관측 후 `거리 미확인`으로만 표시한다. 음성 경고 후보가 되지 않는다.
   - 카메라 화면은 가까운 거리 순으로 중복 박스를 줄여 최대 6개만 표시한다. 이 개수 제한은 경고 처리에 적용하지 않는다.
2. **미학습 객체 깊이 누락**: 기존 FrozenUnknownDepthCapture는 Full Depth를 버리고 Raw+confidence만 복사했다. 따라서 Full Depth가 있어도 Raw 마스크 표본이 부족하면 거리 없음이 되었다.
   - Raw 우선, 부족한 마스크는 같은 캡처의 Full Depth로 보완한다. Full 데이터는 CPU 이미지와 같은 timestamp여야 하며 별도 출처 `ARCORE_FULL_DEPTH`를 유지한다. 가짜 confidence나 정답 깊이를 만들지 않는다.
   - Raw의 서로 모순되는 깊이 층이나 이미 지지된 거리와 0.4m 넘는 차이는 smoothing으로 덮지 않는다.
   - Full만으로 이동 속도·TTC를 만들지 않는다. Raw↔Full 또는 대표 표본 변경 시 이전 운동 이력을 분리한다.
   - Raw confidence 0–255를 실제 통계·공간 대응 경계에서 0–1로 정규화했다. 실제 IQR을 전달하며 p80-p20을 IQR로 대신 쓰지 않는다.
3. **세로 회전 표시**: 90도는 CPU 센서 영상을 세로 화면에 맞추는 보정일 수 있다. 회전을 0으로 고정하지 않았다. 화면 문구를 `센서 영상 → 화면 방향 보정 … (휴대폰을 돌리라는 뜻이 아닙니다)`로 바꿨다. 마스크/깊이 좌표는 원본 센서 기준을 유지하고 전방 필터에만 캡처 당시 방향을 적용한다.
4. **경고 연결**: 실제 안내의 기존 `UnknownObjectFeedbackPolicy → WalkSafeFeedbackPolicy → AndroidFeedbackActuator` 경로는 유지하며 전방 후보 자격을 추가했다. 카메라 테스트는 음성 없는 뷰어다. 여기에는 거리 출처와 경고 후보를 표시하고 실제 안내에서 조건 충족 시 음성/진동을 낸다는 문구를 추가했다. 영상 단계의 반복 제한과 실제 음성 큐의 cooldown이 중복되어 초기 메시지가 사라지지 않도록, pipeline은 매 프레임 상태를 평가하고 공통 피드백 큐가 발화 간격을 담당한다.
5. **안내 시작**: 현재 debug bypass에서 이전 교정/환경/성능 점검을 취소하고 readiness를 갱신해 서버 시작 요청으로 진행한다. 새로운 보행의 foreground 상태를 복구하고 명시적 재개 요청은 추가 음성 확인 없이 처리한다. 교정·조정 UI와 잔여 카메라 품질 차단도 우회한다. 실제 로그인·서버 연결과 OS 권한/하드웨어 실패까지 성공으로 표시하지 않는다. 초기 로그인 후 기기점검 흐름과 release 설정은 별도다.

## 현재 한계와 사용자 시험

전방/근거리 선별은 위험 후보를 줄이는 휴리스틱이다. **바닥·벽·천장인지 구별하거나 지면 대비 돌출 높이를 측정하는 기능은 이번에 구현하지 않았다.** 큰 바닥 마스크가 전방 띠를 충분히 점유하면 후보로 남을 수 있다. 화면을 향한 전방은 실제 사용자의 이동 경로와 항상 일치하지 않는다. 실제 보행 위협만 완벽하게 구별한다고 주장하지 않는다.

사용자 시험에서는 전방 가까운 물체/옆 물체/먼 물체/바닥을 각각 비추고 `전체 → 전방 후보 → 표시`, `Raw 측정 / Full 추정 / 거리 미확인`을 확인한다. 안내 시작 후 교정 화면이 끼어드는지, 경고 조건에서 실제 소리와 진동이 나오는지는 기기로 확인해야 한다. 고정 자료나 현장 시험 없이 인식률·거리 정확도 향상 수치는 제시하지 않는다.

공식 근거: Raw는 일부 픽셀의 신뢰도 있는 깊이와 confidence를 제공하며, Full은 smoothing/interpolation을 거친 조밀한 깊이로 confidence 이미지가 없다. [ARCore Raw/Full 비교](https://developers.google.com/ar/develop/java/depth/raw-depth), [Depth 좌표 변환 안내](https://developers.google.com/ar/develop/java/depth/developer-guide).
