## 모델 계약과 보존

- 입력 `[1,768,768,3]` RGB FP32, 출력 `[1,25,12096]`: 픽셀 단위 중심 xywh와 21개 클래스 점수. 기존 end-to-end xyxy `[1,300,6]` 파서와 명시적으로 구분한다.
- 클래스별 NMS IoU 0.7, 최대 300개. 탐지 임계값은 기본 0.15, 점자블록/신고 등은 설정의 해당 임계값을 사용한다. 이 숫자를 새 모델의 현장 최적값으로 검증한 것은 아니다.
- 주 모델은 `models/walkmate_yolo11n_21cls_768_float32.tflite`. 실제 TFLite SHA256 `d10aa174a2ceb8ae116a09b7b570e27ff71c296fbd98f240c11e69dbdb434b57`.
- 원본 best.pt SHA256 `6f8ae9d2bb82f91e4391e42957a1b374bd4b14efa4702a86f7283454bc38cee0`. ZIP SHA256 `93102ed502a7966a193733725a0d17908c1481e4ffc02ed7e9f83b13d7259bdc`.
- 기존 주 모델과 기존 작업은 보존했다. 활성 설정의 fallback은 null이므로 로딩 실패를 구 모델의 정상 실행으로 숨기지 않는다. 미학습 영역 후보용 FastSAM 768과 기존 추적/ARCore 깊이/실제 움직임 판단은 유지한다.
- 원시 클래스명과 순서를 유지한다. 선형 정상 점자블록만 방향 경로의 후보이며 점형을 선형으로 안내하지 않는다. 손상 선형/점형은 실제 ID 1/3을 `walkmate_21cls` 신고 키로 보내고 서버 업무 분류는 기존 `damaged_tactile_block`으로 유지한다. 기존 신고 키와 저장 데이터도 지원한다.
- `moving_e_scooter`라는 모델 이름으로 실제 접근 속도를 확정하지 않는다. 기존 깊이·추적·움직임의 관측 결과를 사용한다.
- 장애물 발화의 불확실한 ‘N보’ 표현은 제거하고 객체 접근/정지물 접근 설명은 보존했다. 길안내의 이동 거리·좌우 회전 안내는 유지한다.

## 팀원 브랜치 적용 범위

기준 tip `bf0295d0dd9cbea88260c6f23294f1955f9303ff`, 공통 기준 `37dd42c8939cce5b9c43e4d620c18f3841e0d01f`. 전체 브랜치를 덮어쓰지 않고 현재 미커밋 작업에 변경을 적응했다.

- 카메라 점검은 최대 10회 중 모델 호출 성공 8회 정책. 객체를 맞힌 정확도나 보행 안전성의 점수는 아니다. 실패는 기존 카메라 기능 제한/추후 재점검 구조로 이어진다.
- 한국어 음성 합성 파일은 실제 PCM WAV 구조와 1초 이상 길이를 확인한다. 음성의 의미, 실제 스피커 소리, 사용자의 청취를 증명하지는 않는다.
- 발열 SEVERE는 기기점검 측정 대기로 분리하고 이유를 표시한다. 보행 중 전역 안전 기준은 기존 정책을 보존한다. 실패/시간 초과 상태에서는 자동 진행을 약속하지 않고 재점검을 안내한다.
- 만료된 일회성 권한 재요청, 이미 열린 요청 중복 방지, 설정에서 허용하고 돌아온 뒤 차단 화면 해제를 연결했다.
- 플랫폼에서 반환한 가변 음성 후보를 모두 검토하고, 인식하지 못하면 현재 상태에 맞는 명령 예시를 안내한다. 기존 설정 명령, 종료 확인 토큰, 세션/마이크 경계와 경로 계산을 보존한다.
- 기기점검의 위치는 권한·서비스/지원 확인이다. 위치 품질을 로그인 통과 조건으로 다시 추가하지 않았다. 실제 위치 15m 추정 불확실성 기준은 기존 보행 직전/실행 중 경로에서 확인한다. `Location.accuracy`는 실측 위치 오차가 아니다.
- 팀원의 추가 문자열 기반 릴리스 gate와 macOS 전용 도구 변경은 제품 기능에 필요하지 않아 적용하지 않았다.

## 성능 설정 주의

새 모델 해시·출력 형식·클래스·NMS와 새 자료 manifest로 프로필을 구분하므로 구 모델의 CPU/GPU 최적 설정을 그대로 확정하지 않는다. 기존 고정 이미지 자체는 유지했다. 사용자 기기점검에서 기준 출력의 임계값 ±0.02 후보가 실제로 관측되지 않으면 `near_threshold_not_observed`로 선택을 미확정 처리한다. 새 모델을 실행해 이 조건의 충족 여부를 측정한 것은 아니다.

원시 출력 1회 payload는 302,400 float, 1,209,600 bytes다. 기존 7,200 bytes보다 커졌으며 이는 계산한 버퍼 크기다. 앱 전체 메모리·FPS·실제 추론 시간은 이번 모델에서 측정하지 않았다. 이전 모델의 S25 결과를 새 모델 결과로 사용하지 않는다.

## 사용자 확인 순서

1. 새 APK 설치 후 로그인/재실행과 일회성 권한 만료·설정 복귀를 확인한다.
2. 기기점검에서 한국어 음성, 호출어, 카메라, Depth와 발열 대기/재점검 상태를 확인한다.
3. 실제 21종 객체에서 상자·라벨·중복 제거를 확인한다. 정상 선형과 점형, 손상 2종을 구분하고 손상 신고가 서버에 접수되는지 확인한다.
4. 호출어 알림음→명령 화면, 목적지/설정 이동, 미인식 도움말, 보행 재개와 거리·회전 음성을 확인한다.
5. 학습 객체와 미학습 영역의 깊이·접근 안내, CPU/GPU 재선택, 동시 실행의 지연/메모리를 확인한다.
6. SMTP 반영 후 실제 주소로 인증번호를 요청하고 수신함/스팸함 도착 및 번호 입력 후 회원가입을 확인한다.
