# 카메라 위험 안내와 미학습 후보 선별 — 1~5단계

사용자 요청: 야외 시험에서 카메라 화면의 객체 안내가 없었던 문제를 해결하고, 작은 FastSAM 영역을 무분별하게 제외하지 않으면서 보행 관련 후보를 선별한다. 새 자료는 아직 없어 기존 고정 자료로 진행한다. 이번 범위는 구현·자동 검증·APK 빌드까지다. 설치와 실제 보행 시험은 6단계로 남긴다.

## 단계와 검증

| 단계 | 작업 | 확인 방법 |
| --- | --- | --- |
| 1. 경로 확인 | 학습 모델·FastSAM → 깊이 → 추적 → 위험 판단 → 음성의 연결 확인 | 기존 카메라는 중앙 깊이 표시만 하고 음성 actuator가 없었음을 코드에서 확인 |
| 2. 카메라 안내 | 안내 시작 없이 학습·미학습 후보가 공용 위험 정책과 하나의 음성·진동 큐를 사용 | 만료·이전 epoch·지연된 출력·중복·다른 깊이·화면 종료 회귀 검사 |
| 3. 작은 영역 선별 | 근거리·접근·길거나 얇은 영역·미확인 영역 보존, 원본 검출과 화면/경고 선별 분리 | 독립 합성 위험/무해/미확인 정답에 이전·새 정책 비교 |
| 4. 크기 보조 근거 | 같은 캡처의 카메라 내참수·깊이로 관측 마스크의 투영 폭/높이 계산 | 축 회전·Raw/Full·약한 표본·영상 가장자리·낮은 깊이 해상도 검사 |
| 5. 고정 비교 | 기존 COCO 80장·RGB-D 4장 저장 출력과 합성 18개를 고정해 평가 | Kotlin 제품 정책을 동일 5,521개 입력에 호출, 정답 범위별 수치 분리 |

분담: 카메라 실행/출력 담당, 고정 자료 평가 담당, Root의 공용 선별/깊이 크기 담당이 파일을 나누어 구현했다. 별도 읽기 전용 리뷰 담당이 신규 누락·출력 수명주기 경계를 검토했다.

## 실제 연결

```text
카메라와 같은 시점의 RGB·깊이·좌표변환 저장
  ├─ 학습 모델 → 기존 ObjectDepthRuntimePipeline의 영역 깊이·추적·위험 판단
  └─ FastSAM → 실제 마스크의 Raw Depth → 필요한 경우 동일 캡처 Full Depth
               → 추적 → 전방 후보·관측 크기 확인 → UnknownObjectFeedbackPolicy
                 ↓
     카메라의 단일 WalkSafeFeedbackPolicy → AndroidFeedbackActuator → 음성·진동
```

객체를 찾았다는 사실만으로 모두 읽어주지 않는다. 유효한 거리·신선도·반복 추적·위험 등급을 만족해야 경고한다. 화면에 음성 준비, 거리 미확인, 추적 누적, 위험 조건 미충족, 출력 요청 상태를 표시한다. 출력 요청 수락은 실제 사용자가 들었거나 진동을 느꼈다는 증거가 아니다.

카메라 종료/백그라운드 이동 시 큐·TTS·진동을 닫고 세대 번호로 이전 추론/음성 콜백을 차단한다. 800ms가 지난 원본은 새로운 경고를 시작하지 못한다. 공유 출력 정책의 3회/700ms 추적, 전역·객체별 반복 간격을 유지한다. 학습 모델의 상자를 진짜 분할 마스크라고 취급하지 않는다.

## 작은 영역을 다루는 기준

모델 가중치, 입력 해상도, 검출 confidence를 바꾸지 않았다. 모든 원본 미학습 마스크와 관측 사유를 유지하고 매 프레임 다시 선별한다. 한 번 제외한 track을 영구 차단하지 않는다.

새 작은 조각 제외는 다음 조건을 모두 요구하는 제한적인 휴리스틱이다.

- 기존 전방/반복 관측 조건을 만족하고 2.5m 이상 떨어져 있다.
- 접근 추세나 짧은 TTC가 없고 거리 추세가 안정적이다. 움직임 미확인은 작은 조각 제외의 근거로 쓰지 않는다.
- 화면 면적이 0.1% 이하이고, RGB 마스크 ROI의 폭·높이가 각각 영상 축의 4% 이하이다.
- 관측 크기에 여유를 더한 폭·높이가 둘 다 4cm 이하이다. 한쪽이 긴 기둥·막대는 제외하지 않는다.
- 전체 마스크의 단일 Raw 깊이 성분, 새 깊이 표본, confidence 200/255 이상, 강건한 표본 비율 60% 이상, IQR 10cm 이하의 근거가 있다.
- 영상 가장자리 잘림·불완전한 좌표 보정 범위가 없고, 관측 크기가 3회 이상/700ms 이상 이어서 안정적이다. 크기가 갑자기 변하거나 관측/깊이가 끊기면 누적을 초기화한다.

관측 크기는 RGB 마스크를 둘러싼 영역을 축방향 깊이와 fx/fy로 투영한 값이다. 깊이를 얻은 작은 부분만으로 전체 크기를 축소하지 않는다. 세로 입력 회전은 표시 축만 바꾸며 깊이 픽셀을 임의 회전시키지 않는다. Full Depth로도 관측 크기를 표시할 수 있지만 평활화된 깊이만으로 작은 영역을 제거하지 않는다.

**이 크기는 물체 전체 크기의 정답이 아니다.** 가려진 큰 물체의 일부가 작은 마스크로 검출되면 완전성을 증명할 수 없다. 여유 폭도 실측 오차로 보정한 통계적 상한이 아니다. 따라서 이 규칙을 실제 보행 누락 0 또는 무해 판정으로 표현하지 않는다.

특히 1280×720 RGB / 320×180 Depth / fx=900이라는 대표적 합성 조건에서, 2.5m 거리의 약 3.3cm 영역은 깊이 격자 약 3×3개만 차지해 강건한 표본 기준을 충족하지 못한다. 이런 영역은 거리 미확인으로 보존한다. 작은 영역 제거가 실제 휴대폰에서 자주 작동할 것이라고 가정할 수 없으며, 효과를 만들려고 깊이 신뢰 기준을 낮추지 않았다.

## 검증 결과와 남은 경계

고정 비교의 입력·수치·도표·재현 명령은 [고정 자료 보고서](unknown-selection-fixed-data-20260913.md)에 있다. 합성 위험 10개 누락 0→0, 무해 조각 3개 중 남은 후보 2→1, 미확인 4개 보존 4→4다. 실제 저장 마스크에는 실측 크기 근거가 없어 이전·새 정책의 선택 결과가 같았다. 모델 인식률이나 실제 보행 오경고율을 개선했다고 주장할 근거는 아직 없다.

최종 관련 회귀 111개가 실패/오류 0으로 통과했고 debug APK 빌드가 성공했다. 별도로 실행한 고정 비교 JUnit 1개는 5,521개 입력을 이전/새 정책에 적용했다. `git diff --check`도 통과했다. 읽기 전용 독립 검토에서 같은 source의 별개 track 병합을 발견해 cross-source 전달 병합으로 제한했고, 최종 재검토에서 추가 지적은 없었다.

카메라의 학습 객체도 `rawDepthMotionOnly=true`로 Full 근접 안내를 유지하면서 Full에서 접근 속도·TTC를 만들지 않는다. 9프레임의 Full 깊이가 점차 가까워지는 회귀에서 속도/TTC 없음과 근접 문구 유지를 확인했다. 기존 Main 호출의 기본 동작은 이번 카메라 변경으로 바꾸지 않았다.
