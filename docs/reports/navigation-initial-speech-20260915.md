# 안내 시작 후 첫 경로 음성 누락 수정

## 요청과 완료 범위

- 목적지 설정 후 안내 시작 시 현재 위치에서 다음 안내 지점까지의 거리·방향을 말하도록 무음 경로를 수정했다.
- 구현, 독립 검토, 최종 소스 선택 회귀 2,300건, APK 빌드 및 연결된 S25 업데이트 설치 완료.
- 사용자가 실제로 겪은 순간에는 경로 발화 진단 로그가 없어 단일 원인을 단정하지 않는다. 아래 실패 조건은 현재 코드로 재현했고 해당 경로를 수정했다. 실제 스피커·실보행 검증은 사용자가 진행한다.

## 단계별 작업과 검증

1. 경로 수신 → 첫 안내 생성 → 음성 허용 → TTS 전달 흐름 조사: 목적지 응답과 길안내의 허용 경로 차이, 초기화 중 발화 누락, 동일 GPS 재입력 취소를 격리 재현했다.
2. 첫 안내 재시도: 새 GPS를 주입하지 않는 `RouteNavigator.retryGuidance(nowMs)`를 추가했다. 같은 유효 위치로 재시도하되 이동 거리·도착/이탈 판단 횟수·위치 시각은 갱신하지 않는다.
3. 앱 연결: TTS 준비 완료 이벤트와 실패/일시 점유 이후 재시도를 연결했다. 테스트 안내에서는 과거 기기점검 TTS 실패가 실제 준비된 음성 엔진을 계속 차단하지 않도록 했다.
4. 중단·교체 검토: 목적지 변경, 경로 종료, 화면 수명주기 변경 후 이전 안내가 재생되지 않도록 예약과 실제 음성을 취소했다. 위치 대기 설명도 자신이 소유한 명령 응답만 취소한다.
5. 통합 검증·설치: 기존 선택 회귀와 신규 실패 재현 시험을 실행하고 APK 코드·모델·설정·설치 파일 해시를 확인했다.

## 확인한 결함과 수정

| 확인한 동작 | 수정 후 동작 |
| --- | --- |
| 홈 목적지 음성은 나오지만, 길안내는 이전 `OFFLINE_KOREAN_TTS` 점검 실패에 차단될 수 있음 | DEBUG 안내 제한 해제 정책을 해당 음성 허용 경계에도 적용. 실제 한국어 엔진 준비·오류·오디오 포커스 판단은 유지 |
| TTS 초기화/다른 음성 점유 중 첫 발화 실패 시 다음 GPS 이벤트만 기다림 | 준비 완료 시 또는 재시도 타이머에서 현재 안내를 다시 요청. 실제 완료 콜백에서만 안내 완료 처리 |
| 같은 GPS로 `updateRouteGuidance`를 재호출하면 중복 위치 판단으로 기존 안내가 취소됨 | 별도 `retryGuidance`로 발화만 재제안. GPS 관측 처리를 반복하지 않음 |
| 경로 응답 때 현재 위치가 없으면 첫 발화 요청 자체가 없음 | 전체 경로 거리와 현재 위치 확인을 기다린다는 상태를 음성으로 설명. 실제 위치 도착 후 방향 안내 |
| 경로 토큰만 폐기하면 이미 대기/재생 중인 이전 음성이 남을 수 있음 | 경로 소유권 무효화 후 실제 경로 음성 취소. 위치 대기 설명의 소유 토큰도 취소하며 더 최신 명령 응답은 보존 |

재시도는 250ms 간격의 상태 확인이며 GPS 측정·모델 추론 주기가 아니다. 기존 발화 실패 후 2초 대기, 일반 안내 간격, 중복 안내 소비 규칙을 존중한다. 원본/안내 위치가 10초를 넘거나 경로·세션·화면 소유권이 바뀌면 재시도를 중단하고 새 유효 근거를 기다린다.

- 독립 재현: `work/navigation-initial-speech-20260915/audit/probe.log`의 3개 조건 통과. 실제 Android TTS 엔진 대신 입출력 경계만 대체한 코드 재현이다.

- 최종 Android 선택 회귀: `integration-final-v2/summary.json`, **223개 suite / 2,300 tests / 실패 0 / 오류 0 / skip 0**. APK 빌드 통과. 검사 시작/종료 및 설치 전 소스 해시 일치.
- 이전 작업에서 분리한 기존 정적 불일치 12건은 동일 목록으로 제외했다. 목록과 선행 근거: `work/navigation-session-fixes-20260914/preexisting-static-exclusions.json`. 전체 저장소 시험 통과를 의미하지 않는다.

- `git diff --check` 통과. 현재 작업은 MainActivity, RouteNavigator, 관련 신규/갱신 시험 및 본 보고서·daylog로 한정했다. 기존 WIP 보존.

## 사용자 확인

앱에서 목적지를 설정하고 안내 시작을 눌러 첫 거리·방향 음성을 확인한다. 정지·목적지 변경 시 이전 경로가 뒤늦게 발화하지 않는지도 확인한다. 실제 발화 진단을 위해 개인정보 없는 DEBUG `WalkSafeNavigation` 상태와 `speech=accepted/unavailable/completed` 로그를 추가했다. 설치 성공과 코드 시험은 실제 스피커 출력이나 야외 길안내 정확도를 입증하지 않는다.
