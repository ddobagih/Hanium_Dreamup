# 768 고정 입력 최적화 결과

2026-09-12 Galaxy S25(SM-S931N, Android API 36)에서 측정했다. 원본 사용자 앱의 YOLO26n768과 FastSAM768 모델을 유지했다. WalkMate 21클래스 모델 교체는 하지 않았다.

## GPU 준비와 추론 비교

같은 APK, 모델, 원본 RGB 8장, 순서, 예열 1회와 측정 3회를 사용했다. 회차마다 24개 입력을 모두 처리하고 native 해제 및 실행 스레드 종료를 확인했다. 모든 회차의 OS thermal status는 시작/종료 모두 0이었다. 아래 P50/P95는 24개 입력의 값이다. P95는 정렬 후 0기반 floor(0.95×24) 위치를 사용한다.

| 조건 | 모델 준비 ms | 추론 P50 / P95 ms | 마스크 처리 P50 / P95 ms | 제출→결과 P50 / P95 ms |
|---|---:|---:|---:|---:|
| 기준 A1, 캐시 끔 | 24,765.9 | 58.45 / 62.36 | 42.26 / 64.17 | 120.90 / 146.65 |
| 캐시 B1, 최초 생성 | 25,247.0 | 59.29 / 63.45 | 44.69 / 58.91 | 126.93 / 147.53 |
| 캐시 B2, 재사용 | 306.9 | 58.39 / 61.81 | 46.68 / 65.22 | 124.65 / 150.40 |
| 기준 A2, 다시 캐시 끔 | 24,784.0 | 63.78 / 67.71 | 44.13 / 61.69 | 129.69 / 151.94 |
| 정밀도 완화 후보, 미채택 | 12,955.5 | 41.93 / 44.98 | 45.57 / 66.03 | 107.27 / 125.29 |

- 캐시 재사용 시 준비가 약 24.8초→0.31초로 줄었다. 캐시 최초 생성은 약 25초가 필요했다. 프레임마다 수행하는 추론 자체가 캐시 때문에 빨라졌다는 결과는 아니다. 같은 기기의 이번 관측이며 다른 기기에서도 같은 시간을 보장하지 않는다. SDK의 `configured` 표시는 캐시 적중 여부를 직접 제공하지 않는다.
- 캐시 켬/끔은 8장×3회에서 anchor, 좌표, 면적, 마스크 픽셀 및 점수가 모두 동일했다. 다른 모델·옵션·기기·런타임에는 별도 캐시 키를 사용하고 캐시 준비 실패는 캐시 없는 GPU 초기화로 복구한다.
- 정밀도 완화는 추론을 줄였지만 8장의 검출 마스크 합계가 544→541로 줄었다. IoU≥0.99 일대일 대응은 403/544에 그쳤고 모든 영상에 기준 미달 영역이 있었다. 동일 마스크 수와 IoU 기준을 충족하지 못해 제품에는 적용하지 않는다. 마스크 게이트에서 실패했으므로 이후 깊이/접근 품질 채택 시험은 생략했다.
- 제출→결과에는 전처리·GPU 실행·출력 복사·CPU 마스크 생성·대기가 포함된다. 영상 읽기·결과 저장은 측정 경계 밖이다. 이 시험은 카메라, YOLO와의 동시 부하, ARCore Depth, 보행, 음성을 함께 실행한 전체 앱 FPS 시험이 아니다.

## 깊이 계산과 추적

깊이 계산은 객체마다 만들던 탐색 큐와 유효 픽셀·정렬 작업 배열을 계산기 내부에서 재사용한다. 계산된 결과 배열은 따로 소유하며, 임계값·깊이 선택·PARTIAL/UNKNOWN 판단은 유지한다. 고정 233마스크/401성분의 전체 결과, 선택된 픽셀과 중심 좌표가 변경 전후 일치했다. 호스트 JVM에서 호출당 새로 할당한 메모리는 평균 약 13.43→4.71 MB로 64.9% 줄었다. 이는 PC JVM 측정이며 휴대폰의 메모리 계측값은 아니다.

S25에서는 같은 APK 안에 이전/개선 코드를 함께 넣고 A/B/B/A 순서로 각각 40회, 총 160회 측정했다. 4장 각각 33/68/49/83개 마스크 전체를 처리하는 시간이다. 전처리와 모델 실행을 포함하지 않는 깊이 계산 구간이며, GPU 표의 8장 처리 지연과 단순히 더해 앱 FPS로 환산하지 않는다.

| 깊이 조건 | 호출 수 | 평균 ms | P50 ms | P95 ms |
|---|---:|---:|---:|---:|
| 이전 코드 A1+A2 | 80 | 164.14 | 155.11 | 230.59 |
| 개선 코드 B1+B2 | 80 | 152.28 | 142.66 | 208.41 |

- P50 약 **8.0%**, P95 약 **9.6%** 감소를 관측했다. 블록별 P50은 A1 160.56 → B1 142.98 → B2 142.09 → A2 150.13ms이며, 기준 회차 사이의 변동도 있다. 장시간 실제 보행의 개선율이나 통계적 일반화를 뜻하지 않는다. 깊이 P95는 `(n-1)×0.95` 위치의 선형 보간이다.
- 4장에 포함된 233마스크/401성분을 사용했다. 초기 8회+예열 32회+측정 160회, 총 **장면 호출 200회**에서 해당 장면의 모든 결과가 일치했다. 시작/종료 OS 열상태는 0, 배터리 온도는 모두 32.4°C였다. 실제 시험 시간 48.137초. 상세: `device/depth-abba-d2/{summary,metrics}.json`.
- 최초 d1은 SHA 직렬화 처리 부담 때문에 241.760초에 240초 시험 마감을 넘겼다. 완료된 149회 대조는 일치했으나 전체 시험은 실패이며 성능표에서 제외했다. 이전 시험은 완료 측정행을 성공시에만 저장하여 d1의 부분 시간값은 남지 않았다. 이 실패 원본을 보존하고 시험 코드의 해시 출력을 64KiB로 모아서 처리하며 실패에도 완료행을 저장하도록 수정했다. 이전/변경 시험의 4장×두 코어 서명 8개가 정확히 같은지 검사했다. 제품 코드·데이터·160회·예열·4분 한도는 변경하지 않았다.

중간 추적 후보는 미채택했다. 기존 PATCH_DIAGNOSTIC을 마스크 안의 영상 특징으로 제한하고 새 프레임 깊이에 연결하는 실험에서, 고정 MOVi-E 163/131 각각 60개 중간 갱신 기회 중 승인된 변환은 0개였다. 실제 초기 시도는 각각 12개이며 실패 후 LOST 상태가 유지된다. 추가 깊이 관측·접근 판정·안내 지연 개선이 입증되지 않았다. 53개 기존 회귀, 10개 어댑터 검사, 합성 RGB 추적→새 깊이 5관측은 통과했으나 공개 영상에서의 성공 근거가 되지 않는다. 이 결과를 다른 추적 방식 전체의 한계로 확대하지 않는다.

## 원본 통합과 검증

- Main의 저장 설정 복원과 보조 모델 성능 점검 경로에서 strict GPU + 캐시를 명시적으로 사용한다. 기존 생성자 기본값은 변경하지 않았다. CPU로 선택된 기기는 기존 CPU 경로를 사용한다.
- 보조 모델의 실행 계약에 캐시 옵션 버전을 결속하여 이전 점검 기록과 구분했다. 기본 모델의 전역 버전·회원가입·로그인 정보는 변경하지 않는다. 사용자 데이터 삭제 없이 `adb install -r`로 업데이트했다.
- 점검 시작을 기준으로 한 300초 정책 마감, 기존 초기화 시간 추정, native 해제 확인, 오래된 결과와 PARTIAL/UNKNOWN의 안내 제한을 유지한다. 실행 중인 native 작업을 강제로 취소할 수 없어 실제 정리 완료는 정책 마감을 넘을 수 있다. 캐시는 기기/스레드/모델/옵션에 따라 달라 처음 쓰는 조합에는 최초 준비 시간이 다시 필요하다. Android가 캐시를 비워도 다시 생성할 수 있다.
