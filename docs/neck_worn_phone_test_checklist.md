# 목걸이 착용 휴대폰 테스트 체크리스트

> **문서 상태(2026-06-02): legacy PWA field checklist.** Android Device PASS 기준은 `docs/android/android_device_overlay_depth_checklist_20260601.md`를 본다.


작성 기준일: 2026-05-12

## 2026-05-17 최신 보정

- 이 체크리스트는 안전한 실내/통제 환경의 목걸이 착용 smoke 기준이다. 실제 시각장애인 대상 현장 검증으로 표현하지 않는다.
- fake mode 결과는 API/UI/운영 흐름 검증용이고, server mode 결과는 모델-백엔드-PWA 연결 smoke 근거다. 두 결과를 정확도나 실제 보행 안전 근거로 섞지 않는다.
- 2026-05-17 기준 Android 실폰/목걸이 착용, PWA 설치/offline, TalkBack 수동 검증은 아직 완료 근거가 없다.

## 사용 전제

사용자는 휴대폰을 손에 들고 화면을 보는 것이 아니라, 목걸이 또는 스트랩 형태로 목에 걸고 보행한다. 휴대폰 후면 카메라가 전방과 바닥 일부를 함께 보며, 사용자는 주로 TTS와 진동으로 위험을 인지한다.

이 전제에서는 화면 UI보다 다음이 더 중요하다.

- 카메라가 실제 보행 방향을 보고 있는지
- TTS가 짧고 즉시 행동 가능한지
- 진동만으로 위험 알림과 신고 결과를 구분할 수 있는지
- 사용자가 화면을 보지 않고도 신고 실패/성공 상태를 알 수 있는지

## 테스트 준비

1. 휴대폰을 목걸이 또는 스트랩에 고정한다.
2. 후면 카메라가 가슴 높이에서 전방 하단을 보도록 각도를 맞춘다.
3. Android Chrome에서 PWA를 연다. ADB reverse를 쓴 경우에만 `http://localhost:3000`을 사용하고, 그렇지 않으면 LAN IP 또는 HTTPS 개발 URL을 사용한다.
4. 카메라 권한과 위치 권한을 허용한다.
5. 화면을 손에 들고 보지 않고, 목에 건 상태로 테스트한다.

## 카메라 각도 확인

| 확인 항목 | 통과 기준 |
| --- | --- |
| 카메라가 바닥만 찍지 않는다 | 전방 1~3m와 바닥 일부가 함께 보인다 |
| 카메라가 하늘/상체만 찍지 않는다 | 보행 경로의 장애물이 프레임 중앙 또는 하단에 들어온다 |
| 걸을 때 흔들림이 과도하지 않다 | 위험 박스가 계속 화면 밖으로 튀지 않는다 |
| 목걸이 줄이 렌즈를 가리지 않는다 | 프리뷰에 줄/옷깃이 크게 보이지 않는다 |

## TTS 확인

| 위험 유형 | 현재 안내 문구 | 확인할 점 |
| --- | --- | --- |
| 점자블록 파손 | 점자블록 파손. 발밑 주의. | 너무 길지 않고 즉시 멈춤/주의 행동이 가능한지 |
| 방치 킥보드/자전거 | 전방 장애물. 천천히 이동. | 장애물이라는 의미가 바로 전달되는지 |
| 공사 장애물 | 공사 장애물. 우회하세요. | 우회 행동을 떠올리기 쉬운지 |
| 노면 파임 | 노면 파임. 발밑 주의. | 발밑 위험으로 이해되는지 |

TTS는 같은 위험을 반복해서 과하게 말하지 않아야 한다. 현재 쿨다운 기준은 6초다.

## 진동 확인

| 상태 | 통과 기준 |
| --- | --- |
| 음성 켜짐 상태의 위험 알림 | 짧게 구분 가능하되 보행을 방해하지 않는다 |
| 음성 꺼짐 상태의 위험 알림 | 더 강하고 긴 패턴으로 위험을 놓치지 않는다 |
| 신고 성공 | 짧고 긍정적인 패턴으로 구분된다 |
| 신고 실패 | 성공보다 길고 강한 패턴으로 다시 조작 필요성을 알 수 있다 |
| 유사 신고 있음 | 성공 패턴과 구분 가능하지만 사용자를 멈춰 세우지는 않는다 |

## 신고 흐름 확인

1. fake detection이 발생할 때까지 기다린다.
2. 화면을 보지 않는 상태에서 TTS/진동을 듣고 위험 인지가 가능한지 확인한다.
3. `현재 위험 신고` 버튼을 누른다.
4. 위치가 있으면 중복 후보 확인 후 저장되는지 확인한다.
5. 중복 후보가 있어도 사용자에게 추가 확인 조작을 요구하지 않는지 확인한다.
6. `/admin`에서 신고 이미지, 위치, 위험 유형, `duplicate_report_ids`가 저장됐는지 확인한다.
7. fake mode와 server mode를 각각 실행했다면 신고 `source`와 `metadata.source`를 따로 기록한다.

## 현재 한계

- fake detector는 데모/API 흐름 기준이다. server detector mode는 headless smoke 근거가 있으나 실폰 field 성능 근거는 아직 없다.
- 목걸이 착용 각도에 따라 실제 모델 입력 품질이 크게 달라질 수 있다.
- PWA는 화면 꺼짐 또는 백그라운드 상태에서 카메라 동작이 제한될 수 있다.
- 실제 사용 전에는 안전 확보된 실내/통제 환경에서 먼저 검증해야 한다.
