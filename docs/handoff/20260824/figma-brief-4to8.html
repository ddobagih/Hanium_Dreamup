WalkSafe 가입 검증 단계 디자인 브리프

1~3단계 브리프의 후속이다. 같은 스크롤 면, 같은 토큰, 같은 문구 원칙을 그대로 따른다. 다른 점은 하나다 — 이 다섯 단계는 사용자가 할 일이 거의 없는 대기 화면이고, 그 대기를 어떻게 보여줄지가 설계의 전부다.

제품 맥락

시각장애인·저시력 사용자의 도심 보행을 돕는 Android 앱이다. 주 사용자는 화면을 보지 않고 TalkBack 음성으로 조작하며, 저시력 사용자는 고대비 큰 글씨로 본다. 예쁜 화면보다 이 두 조건이 우선한다.

1~3단계(목적 확인 · 연령 구간 · 통합 동의)는 이미 디자인·구현이 끝났다. 이 브리프의 범위는 그 다음인 4~8단계 가입 검증이다. 9단계 이후(권한·기기점검·안전교육)는 다루지 않는다.

이 다섯 단계는 아직 서버가 없다 운영 SMS·보호자·계정 활성화 공급자가 정해지지 않았다. 그래서 지금 만드는 것은 화면 설계이고, 구현은 서버 계약이 정해진 뒤다. 설계가 서버 동작을 가정하면 그대로 버려진다.

지금 화면에 있는 것 — 실제로 확인한 현재 상태

에뮬레이터에서 4~8단계를 강제로 띄워 접근성 트리를 뽑았다. 다섯 단계가 구조적으로 완전히 동일하며, 화면에 있는 것은 이게 전부다.

  • 취소·재시도·새로고침이 없다. 대기 중이라는 표시도 문장 한 줄이 전부다.
  • 진행 표시 막대가 3칸 모두 채워진 채 멈춰 있다. 문구는 "4단계"라고 말하는데 막대는 다 찼다고 보인다.

즉 백지에서 시작하는 게 아니라, 비어 있는 다섯 화면을 채우는 일이다.

절대 바꾸면 안 되는 것

아래 문구는 코드에 박힌 실제 문자열이다 한 글자도 바꾸거나 요약하거나 새로 쓰지 말 것. 표시 크기·위계는 자유지만 문구 자체는 그대로 써야 한다.

단계 안내 문구 5개

4단계  첫 실행 4단계. 비밀번호나 전화번호를 앱에 저장하지 않고 운영 공급자의 불투명 제출 증거만 허용합니다.
5단계  첫 실행 5단계. 운영 SMS 검증 증거를 기다립니다.
6단계  첫 실행 6단계. 미성년 사용자에게 필요한 보호자 확인 증거를 기다립니다.
7단계  첫 실행 7단계. 운영 계정 활성화 증거를 기다립니다.
8단계  첫 실행 8단계. 검증된 로그인 증거를 기다립니다.

안전 고지 — 접힌 상태 (4~8단계는 항상 접혀서 시작)

안전 제한: 워크세이프는 보행 안전을 보장하지 않으며 흰지팡이·안내견·보호자를 대신하지 않습니다.

「안전 고지 다시 보기」를 누르면 274자 전문이 펼쳐진다. 전문과 펼침 동작은 1~3단계 브리프와 동일하다.

지어내면 안 되는 것

이 단계에서 가장 틀리기 쉬운 지점이다 "가입 검증"이라는 말을 들으면 자동으로 떠올리는 화면들이 있는데, 이 앱은 그 대부분을 일부러 하지 않는다. 개인정보를 앱에 남기지 않기 위해서다.
  • ❌ 인증번호(OTP) 입력칸 — 앱은 OTP를 받지도 저장하지도 않는다. 검증은 운영 공급자가 하고 앱은 결과 증거만 받는다.
  • ❌ 비밀번호 입력칸 — 앱은 비밀번호를 다루지 않는다.
  • ❌ 입력한 전화번호를 다시 보여주기 — 원 전화번호를 저장하지 않으므로 되보여줄 수 없다. "010-****-1234" 같은 마스킹 표시도 안 된다.
  • ❌ 생년월일 입력 — 2단계에서 연령 구간만 받았다. 정확한 생년월일은 저장하지 않는다.
  • ❌ "인증 완료" "확인됨" 같은 성공 표시를 앱이 스스로 판단해서 — 공급자 증거 없이 성공을 표시하는 것은 정책이 명시적으로 금지한다.
  • ❌ 진행률 %, 남은 시간, "약 30초" — 서버 계약이 없어 전부 추측이다.
  • ❌ "보호자에게 문자를 보냈습니다" — 보호자 전달 경로가 아직 정해지지 않았다.
  • ❌ 재전송 버튼 / 만료 타이머 — 재전송 API도 만료 계약도 없다.
근거는 FP-010 Goal 완료 기준이다 — "raw 비밀번호·OTP·원 전화번호·정확 생년월일·장애유형을 저장하지 않음", "운영 signup·SMS·guardian 공급자 성공을 추측하거나 fake 성공을 출시 증거로 사용하지 않음".

구조 — 독립 화면이 아니다

단계별 화면을 그리면 옮길 수 없다 1~3단계와 똑같이, 4~8단계도 하나의 세로 스크롤 면 안의 한 블록이다. 단계가 바뀌면 화면이 전환되는 게 아니라 같은 면에서 블록의 내용만 바뀐다.

구조 규칙

5~8단계에는 주 행동 버튼을 만들지 말 것 사용자가 할 수 있는 일이 없다. "확인" "다음" 같은 버튼을 두면 눌러도 아무 일이 없거나, 더 나쁘게는 앱이 스스로 성공으로 넘어가는 구현을 유도한다. 그건 정책이 금지하는 fake 성공이다.
대기를 스피너만으로 표현하지 말 것 TalkBack에 회전하는 원은 아무것도 아니다. 상태는 반드시 문장으로 존재해야 하고, 상태가 바뀌면 그 문장이 다시 낭독돼야 한다.
취소·중단 경로는 있어야 한다 — 다만 지금 코드에 없다 FP-010 완료 기준이 "실패·취소 때 보행 화면으로 넘어가지 않음"과 "오류 복구 경로"를 요구하고, 정책 코드에 cancelAttempt()가 이미 있다. 그런데 현재 화면에서 이를 호출하는 곳이 없다. 이 브리프에서 새로 제안하는 유일한 요소이므로, 결과물에 별도로 표시해 달라. 팀 확인용 근거로 쓴다.
6단계는 만 14~17세만 본다 18세 이상은 5단계에서 7단계로 건너뛴다. 진행 표시가 단계 번호를 그대로 쓰면 성인 사용자에게 6번이 사라진 것처럼 보인다. 이걸 어떻게 다룰지 제안해 달라.
4단계 입력값은 화면에 남지 않는다 전화번호를 한 번 넣어 공급자에 넘기고 나면 앱은 그 값을 갖고 있지 않다. 입력 후 화면에 되비추는 디자인은 구현할 수 없다.
단계 안내 문장은 쪼갤 수 없다 "첫 실행 5단계. 운영 SMS 검증 증거를 기다립니다."는 한 덩어리로 음성에 읽혀야 한다. 앞머리를 작게 뒤를 크게 하는 시각적 위계는 가능하지만, 별도 요소 두 개로 나누는 것은 안 된다. 현재 구현도 이 방식이다.
스크롤 위치를 조건으로 걸지 말 것 "끝까지 내려야 활성화" 같은 패턴은 TalkBack 사용자에게 인지 불가능한 조건이다.
현재 단계와 무관한 컨트롤은 화면에 두지 않는다 설정·계정·다른 단계 버튼이 함께 보이면 낭독 순서를 채우고 잘못 누를 수 있다.

진행 표시 — 지금 깨져 있다

막대가 3칸인데 단계는 12개다 현재 코드는 FIRST_RUN_VISIBLE_STAGE_COUNT = 3으로 3칸만 그리고, 4단계 이후는 전부 "3칸 다 채움"으로 떨어진다. 그래서 4~8단계에서 막대는 완료를 보이고 문구는 4단계를 말하는 모순이 생긴다.

이건 백엔드와 무관하게 지금 고칠 수 있는 문제다. 12단계 전체를 어떻게 표현할지 제안해 달라. 칸을 12개로 늘리는 것, 단계 번호를 숫자로 쓰는 것, 구간(등록 → 검증 → 준비)으로 묶는 것 모두 열려 있다.

다만 진행 표시는 접근성 트리에서 제외돼 있다(IMPORTANT_FOR_ACCESSIBILITY_NO). 같은 정보를 단계 안내 문장이 낭독하기 때문이며, 이 결정은 유지한다. 즉 진행 표시는 시각 사용자만을 위한 보조 정보다.

자유롭게 정해도 되는 것

시각 표현은 전적으로 Figma의 판단이다
  • 대기 상태의 시각 표현 (문장이 존재한다는 전제 위에서 자유)
  • 진행 표시 방식 — 12단계를 담을 수 있는 어떤 형태든
  • 레이아웃, 여백 리듬, 정렬
  • 카드·구분선 등 면 처리
  • 4단계 입력칸의 형태와 라벨 배치
  • 취소 경로의 위계와 배치 (보조 위계 권장)
  • 타이포 위계 — 단, 본문 18sp 하한은 지킬 것
  • 전환 애니메이션

결과물로 받고 싶은 것

  • 4단계 — 입력 전 / 입력 중 / 제출 직후 세 상태
  • 5~8단계 대기 화면 각각 (또는 공통 틀 1개 + 문구 4종)
  • 취소를 눌렀을 때의 확인 경로 — 새로 제안하는 요소이므로 별도 표시
  • 진행 표시 12단계 안 — 성인(6단계 건너뜀) 경우 포함
  • 안전 고지 펼침/접힘 두 상태
  • 사용한 색과 크기 값 목록
  • 구조 제약이나 「지어내면 안 되는 것」 때문에 포기한 아이디어 — 팀에 계약 변경을 요청할 근거가 된다
이 문서를 그대로 Figma에 붙여넣고 "이 브리프대로 첫 실행 4~8단계를 디자인해 줘. 문구는 브리프에 있는 원문만 쓰고 새로 만들지 마"라고 요청하면 된다. 결과물을 받은 뒤에는 위 「지어내면 안 되는 것」 8개 항목과 하나씩 대조할 것 — 특히 OTP 입력칸이 들어갔는지 먼저 확인한다.
