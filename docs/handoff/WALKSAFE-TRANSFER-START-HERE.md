# WalkSafe 다른 컴퓨터 인계: 먼저 읽기

**최신 협업 인계는 [2026-09-30 두 사람 작업 인계](2026-09-30/README.md)다.** 아래는 9월25일 컴퓨터 전체 이전을 위한 당시 기록이다. 최신 소스/시험 코드와 항목별 잔여 발췌는 temp 브랜치의 새 인계에서 확인하고, 원시 증거·전체 분석 폴더·개인 환경의 완전 복원은 별도 범위로 구분한다.

작성 기준일: 2026-09-25 KST. 이 날짜는 **오래 진행된 작업을 이 컴퓨터에서 중단하고 옮기는 시점**이다. 작업을 하루나 이틀 동안 수행했다는 뜻이 아니다.

## 1. 이 인계가 달성해야 하는 결과

다른 컴퓨터에서 새 담당자가 21개 기능 분석과 942개 계획 항목의 원래 요구를 찾고, 장기간의 변경·실패·검토 근거를 잃지 않은 상태에서 실제 제품 문제 개선을 이어가는 것이 목적이다. 문서 몇 개를 복사하거나 9월 25일 시험 요약만 읽는 것으로는 달성되지 않는다.

**완료 조건은 네 가지를 모두 충족하는 것이다.**

1. 제품 저장소의 **전체 현재 작업 디렉터리**와 별도의 분석·원문·증거 디렉터리가 새 컴퓨터에 보존된다. 커밋 여부를 확인하지 않았으므로 원격 저장소만 다시 받는 방식은 대체가 아니다.
2. 21개 기능 분류 원문과 `942 = 원문 기반 872 + 보강 요구 70`의 행별 계획을 찾고, 역사 상태·현재 계획 상태·국소 시험 결과를 서로 구별할 수 있다.
3. 새 컴퓨터에서 필요한 의존성·SDK·비밀값을 **별도 안전 경로**로 준비하고, 복사 누락 및 좁은 재현 시험을 확인한다. 원본 컴퓨터의 자료는 확인 전 삭제하지 않는다.
4. 실패 중인 변경은 `HOLD`로 유지하고, 단일 파일 수정 담당자와 독립 검토자를 정해 다음 작업을 시작한다. 모든 942행의 상태를 임의로 올리거나 로컬 PASS를 원문 전체 `DONE`으로 바꾸지 않는다.

**현재 판정: 이전 준비 문서 작성 단계.** 대상 컴퓨터·전송 경로가 주어지지 않아 실제 복사, 복원, 파일 무결성 대조 및 대상 컴퓨터 시험은 0건이다. 이 체크리스트의 항목은 아직 완료 표시할 수 없다. 목표는 이 컴퓨터의 인계를 위해 `paused` 상태이다.

## 3. 장기간 자료의 권위와 읽는 순서

1. 프로젝트 `AGENTS.md`와 이 문서, `2026-09-25-walksafe-transfer-guide.md`, `2026-09-25-walksafe-status-report.md`, `2026-09-25-walksafe-work-queue.md`를 읽는다. 인계 문서는 **현재 중단점**이고 원문/계획을 대체하지 않는다.
2. `2026-09-25-walksafe-provenance-map.md`에서 원문 `00`, `01`~`15`, `16-17`, `18`~`21`과 색인을 확인한다. 21개 기능 분류 분석은 20개 답변으로 보존됐고 `00`은 별도 최초 분류다. `01`·`02`는 TXT 전체가 있지만 HTML은 미수집이다. 원본 채팅 링크는 `원문색인.md`/`originals/index.json`에 있다.
3. 필요한 항목의 `originals/*.txt`에서 원래 문제·발생 조건·해결/검증 기준을 먼저 읽는다. `종합분석.md`는 여러 원문의 **종합·해석**이고 원문 자체가 아니다. `S16-*`/`S17-*`는 합동 `16-17.txt`; 보강 70행은 분류 번호만으로 원문을 추정하지 않는다.
4. `전체실행계획-20260921.md`와 `implementation-plan-items-20260921.csv`에서 정확한 ID, 원문·보강 구분, 이전/현재 상태, 근거, 다음 행동을 찾는다. `implementation-plan-summary-20260921.json`과 `implementation-plan-inputs-20260921.md`는 계획 생성의 출처·집계 보조 자료다. 이 CSV의 이번 읽기 전용 집계는 942행 중 `DONE 52`, `PARTIAL 36`, 공란 854, 기타 0이다. 날짜형 파일이 별도의 최신 정본과 동일하다는 보장은 없다.
5. `implementation-progress-20260917*`, `implementation-trace-20260917.csv`, `progress-slices/`, 세 `implementation-evidence-*` 디렉터리와 양쪽의 `daylog/`에서 해당 ID의 **첫 실패, 보정, 실제 실행, 독립 검토, 마지막 판정**을 시간순으로 연결한다. 09-17/09-20의 역사 `DONE 61` 같은 수치와 09-25 날짜형 CSV의 52를 합산하거나 덮어쓰지 않는다.
6. 마지막으로 새 컴퓨터의 실제 제품 코드·시험을 확인한다. 과거 답변의 코드 확인 주장을 새 컴퓨터의 검증으로 승계하지 않는다. 원문 942행 전부가 확정 제품 버그라는 뜻도 아니다.

`RUNBOOK.md`, `progress.json`, `pending-prompts.json`은 원문 수집 당시 Chrome 자동화의 **역사 기록**이다. 그 안의 탭 ID, 35분 폴링, 당시 `ACTIVE` 목표를 새 컴퓨터의 현행 실행 지시로 사용하지 않는다.

## 4. 안전한 복사와 누락 확인

대상 컴퓨터의 호스트명, 계정, 디스크, 전송 매체가 아직 정해지지 않아 이 컴퓨터에서 복사 명령을 실행하지 않았다. 아래는 **보안이 승인된 SSH/rsync 경로를 사용할 때의 예시**다. 대상 루트에 이미 다른 작업이 있으면 덮어쓰기 전에 분리된 새 디렉터리를 선택한다. `--delete`, reset, clean은 사용하지 않는다.

```bash
# 예시: DEST_HOST와 DEST_BASE를 실제 승인된 대상 값으로 설정한 뒤 실행한다.
rsync -aH --info=progress2 \
  /home/ddobagi/Hanium_Dreamup/ \
  "$DEST_HOST:$DEST_BASE/Hanium_Dreamup/"
rsync -aH --info=progress2 \
  /home/ddobagi/Hanium_chat_review_2026-09-17/ \
  "$DEST_HOST:$DEST_BASE/Hanium_chat_review_2026-09-17/"
```

- `-aH`는 숨김 파일·심볼릭 링크·기본 권한·시간·하드링크를 포함하려는 선택이다. ACL/xattr, 소유자 ID, 특수 파일이 중요한 파일시스템이라면 별도 호환성 검토가 필요하다. 보안 관련 권한은 대상에서 다시 확인한다.
- 두 디렉터리를 **같은 전송 회차의 일관된 시점**으로 복사한다. 복사 도중 코드가 바뀌었다면 변경 파일을 재전송하고 기록한다. 전체 작업이 끝났다고 확인하기 전 원본을 삭제하지 않는다.
- 대상에서 두 디렉터리, 21개 원문 TXT, 942행 CSV, 세 evidence 디렉터리, `daylog/`, 이번 다섯 인계 문서, 최근 수정 코드·시험 파일을 확인한다. 단순 존재 확인은 내용 무결성 증명이 아니다.
- 가능한 경우 소스와 대상을 비교하는 읽기 전용 `rsync -aHnci --itemize-changes`를 **각 디렉터리별**로 사용한다. `-n`은 실제 수정을 하지 않지만 `-c`는 약 26GiB 이상을 다시 읽을 수 있으므로 전원·저장장치·시간 여유가 있을 때 직렬로 실행한다. 출력 차이를 검토하기 전 완료 체크를 하지 않는다. 이 비교도 이 컴퓨터에서는 수행하지 않았다.
- 비밀값은 위 예시처럼 전체 디렉터리 안에 함께 있을 수 있다. 보안 승인이 없으면 해당 명령을 실행하지 말고 안전한 별도 이전 절차를 먼저 정한다. 공개 저장소나 문서에 실제 비밀값을 기록하지 않는다.

## 6. 수령 체크리스트: 빈칸은 미완료

- [ ] 대상 컴퓨터와 승인된 안전한 전송 경로, 충분한 디스크 여유가 정해졌다.
- [ ] 제품 저장소 전체와 분석·원문·증거 전체가 복사됐다. 원본은 보존돼 있다.
- [ ] 미커밋 WIP, 숨김 파일, 권한/링크, 모델·설정과 저장소 밖의 필요 의존물을 확인했다.
- [ ] 21개 원문 분류, 942행 계획, 역사 원장, 세 evidence 회차, 양쪽 daylog와 이번 인계 문서를 열 수 있다.
- [ ] 전송 누락/차이를 읽기 전용으로 확인했고 차이가 있다면 해결 또는 목록화했다.
- [ ] 새 컴퓨터의 Python/Node/JDK/Android SDK 및 비밀값 취급을 확인했다.
- [ ] 선택 시험을 대상 컴퓨터에서 새로 실행해 통과/실패와 첫 오류를 기록했다.

- [ ] 새 컴퓨터 daylog에 시작 상태와 복원 결과를 기록한 후에만 기존 컴퓨터 작업 종료를 선언했다.

이 체크리스트를 새 컴퓨터에서 완료하기 전에는 **인계 문서 작성 완료**와 **작업 이전 완료**를 구별한다. 다른 컴퓨터에서의 실제 확인 결과를 이 파일에 미리 채워 넣지 않는다.
