최종 결론

팀원 UI/UX의 사용자 체감 P0/P1 누락은 없습니다. 브랜치를 통째로 병합하지 않고 현재의 안전고지·권한별 제한·1회 기기점검·결과 복원 구조 위에 화면별로 이식했습니다.

남은 차이는 밝은 색상 체계, Pretendard, 전역 버튼·입력칸·카드 마감 등 P2 시각 일치도입니다. 현재 앱은 어두운 네이티브 Android 화면으로 일관되어 있어 기능 장애나 즉시 수정해야 할 가독성 결함으로 판정하지 않았습니다.

현재 구조에 이식한 항목

화면채택 내용적용 방식
회원가입동의/상세 2단계, 필수 3개·선택 3개 약관 카드, 뒤로가기 배치, 내부/외부 스크롤이식 완료 현재 가입·OTP 정책을 유지한 채 UI만 적용
보행화면 구역과 구분선, 2열 동작 버튼, 마지막 음성 결과, 상태 낭독이식 완료 현행 보행 세션·안전정지 수명주기에 연결
TMAP목적지 입력 TalkBack 이름, 경로 이탈의 화면 안내와 동작이식 완료 기존 TMAP 상태기계에 연결
접근성·복구화면 전체 채움, 중첩 스크롤, 청취 햅틱, 한국어 TTS 데이터 설치 복구이식 완료 기능별 제한과 충돌하지 않게 적용

최종적으로 채택하지 않은 항목

항목판정이유
밝은 팔레트와 Theme.Material.Light.NoActionBar P2 디자인 결정 현재 프로그램식 UI는 어두운 배경·흰 글자로 구성됩니다. 테마만 단독 이식하면 기본 글자색과 기존 표면의 대비가 깨질 수 있어 색상·컴포넌트 스타일 전체를 한 묶음으로 결정해야 합니다.
Pretendard 400/500/700 폰트 P2 디자인 결정 기능상 필요하지 않고 APK 용량과 저시력 가독성 확인이 필요합니다. 최종 밝은 디자인 체계를 선택할 때 함께 적용할 항목입니다.
전역 버튼·입력칸·상태 카드의 밝은 디자인 마감 P2 시각 일치도 핵심 화면 구조와 동작은 이식됐지만 픽셀 단위 외형은 동일하지 않습니다. 현재 dark UI 안에서는 일관성과 조작 가능성을 유지합니다.
과거 MainActivity·최초실행·권한·기기점검 전체 교체 영구 제외 통째로 가져오면 안전고지 우회, 권한 하나 거부 시 전체 실패, 기기점검 결과 미복원, 보행 중 터치 제어 숨김이 다시 생깁니다. UI 요소만 현행 구조에 옮긴 이유입니다.
DEBUG 단계 미리보기·대기 화면 범위 제외 제품 기능이 아니며 현재 7단계 최초 실행 흐름과 맞지 않습니다. 기능 우선 원칙에 따라 별도 제어 도구를 늘리지 않았습니다.
중복 카메라/IMU 측정 구현 대체 구현 사용 현재 CameraX 프레임, 거리 측정, 장착 센서 경로가 더 최신이며 회귀 테스트가 연결돼 있어 팀원 버전의 중복 클래스를 가져오지 않았습니다.
macOS aapt2 설정, Backend 테스트 DB migration, handoff/daylog 앱 UI 범위 제외 현재 Android 기능과 무관한 로컬 환경·테스트 인프라·작업 기록입니다. 제품 UI 이식과 함께 병합할 이유가 없습니다.

왜 브랜치 전체 병합을 하지 않았는가

두 브랜치의 MainActivity와 최초 실행 상태 구조가 다릅니다. 전체 병합은 UI뿐 아니라 현재 고쳐 둔 기기점검·권한·안전 흐름까지 과거 구현으로 되돌립니다. 따라서 화면 단위 수동 이식이 가장 작은 안전한 변경이었습니다.
