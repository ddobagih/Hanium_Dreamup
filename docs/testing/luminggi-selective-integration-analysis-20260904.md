# Luminggi 변경분 선택 적용 전 분석

- 작성일: 2026-09-04
- 비교 범위: `6ed59af`(기준) → `835df5c`(검토 끝)
- 검토 규모: 5 commits, 20 files
- 목적: Luminggi가 작업한 UI/UX 및 기기 점검 변경 중 현재 프로젝트에 도움이 되는 부분만 선별 적용한다.
- 상태: 적용 전 의사결정 문서. 이 문서의 판정은 커밋 전체 병합을 승인하지 않는다.

## 1. 결론

현재 프로젝트의 위치 recorder, heading, PDR, ZUPT, purge fence 동작을 우선 보존한다. Luminggi 변경분은 커밋 단위로 합치지 않고, 밝은 색상 체계와 접근성 개선, 안전 배너, 계정 화면의 명확한 라벨, 오프라인 한국어 TTS 점검 흐름만 필요한 코드 조각으로 이식한다.

서버 기기 지원 matrix는 아직 정책과 스키마가 확정되지 않은 초안이므로 구현하지 않는다. PPK 정답지 분석 앱은 WalkSafe 본 앱과 분리된 Android 앱으로 추진하며, 이번 UI/UX 적용이 위치 측정 및 검증 데이터 계약을 바꾸지 않도록 경계를 둔다.

## 3. UI/UX 선별 판정

### 적용

- 밝은 `#1b4cd8` 계열 디자인 토큰과 충분한 명암 대비
- 장식용 카드 자식을 접근성 탐색 대상에서 제외
- 잠긴 카드에 잠김 이유 제공
- 키보드 및 보조기기 포커스 경로 보완
- 보행 전 위험 또는 차단 상태를 명확히 알리는 안전 배너
- 입력값이 있어도 의미가 사라지지 않는 고정 필드 라벨
- 화면 단계 숫자가 스크린 리더에서 중복 낭독되지 않도록 처리

### 부분 적용

- 홈 카드: 카드의 시각 표현과 접근성만 적용한다. 기존 목적지 선택, ARCore, 음성 안내, 신고, 상태 및 신고내역 연결은 삭제하거나 대체하지 않는다.
- landing/NavBar: 레이아웃 개선만 적용한다. 기존 화면 이동 규칙과 기능 연결은 유지한다.

### 보류

- 출처와 사용 라이선스를 확인할 수 없는 이미지·아이콘 에셋
- 현재 앱의 상태 모델과 맞지 않는 5단계 상태 매핑
- macOS `aapt` hash 검증: Android 빌드 및 배포 경로에서 실제 필요성과 재현 방법이 확인되기 전에는 추가하지 않는다.
- 서버 기기 지원 matrix: 정책 및 데이터 계약 승인 후 별도 작업으로 재검토한다.

### 제외

- 다섯 커밋 중 어느 것도 커밋 전체로 병합하지 않는다.
- OTP가 사전 consent에서 막히는데 consent는 후단에 있는 가입 흐름 재배치
- `DETAILS → OTP → CONSENT` 순서 오류와 화면에 보이지 않는 포커스 이동
- 기능 없이 잠겨 있기만 한 settings placeholder
- 현재 기능 행을 삭제하거나 삭제를 전제로 바꾼 assertion
- 실제 대비를 검증하지 못하는 의미 없는 contrast `1.0` 기준

## 4. TTS 기기 점검 적용 기준

오프라인 한국어 TTS가 준비되지 않은 기기에서 보행을 시작하지 못하게 하는 `false → BLOCKED` 처리는 적용한다. 이는 음성 안전 안내가 필요한 상태에서 조용히 기능을 계속 실행하는 것보다 현재 안전 정책에 맞다.

적용할 때 다음을 함께 보완한다.

1. 초기 점검과 실행 중 실패 메시지를 모두 "안전을 위해 보행을 중지한다"는 실제 동작과 일치시킨다.
2. 동일 목적의 설치 버튼이 중복 표시되지 않게 한다.
3. TTS 데이터 설치 화면에서 돌아오면 사용자가 다시 진입하지 않아도 재점검한다.
4. 점검 성공, 미설치 차단, 설치 후 복귀·재점검, 실행 중 실패를 동작 테스트로 확인한다.
5. 기존 TTS 설치 유도 및 재점검 경로가 이미 제공하는 기능은 교체하지 않고 이어서 사용한다.

## 5. `MainActivity` 보호 원칙

현재 작업 트리의 `MainActivity`에는 위치 recorder, heading, PDR, ZUPT, purge fence 관련 변경이 함께 존재한다. 따라서 Luminggi 버전의 파일 전체 교체, 커밋 전체 checkout, 충돌 해결 과정의 일괄 선택은 금지한다.

UI와 TTS 변경은 함수·상태·리소스 단위로 옮기며, 다음 항목은 적용 전후 동작이 같아야 한다.

- 위치 원시 로그 및 측정 시각 기록
- heading 계산과 센서 수명주기
- PDR 및 ZUPT 상태 갱신
- 위치 데이터 purge fence와 보존 정책
- 기존 목적지, 음성 안내, 신고 흐름

## 6. PPK 분석 앱과의 경계

PPK 정답지는 보행 후 결과를 채점하는 별도 Android 분석 앱이다. WalkSafe 본 앱에 기준국 다운로드나 PPK 계산 UI를 섞지 않는다.

| 영역 | WalkSafe 본 앱 | PPK 분석 앱 |
|---|---|---|
| 책임 | 실시간 위치 측정과 원시 로그 생성 | 보행 후 기준국 자료 자동 다운로드, PPK 계산, 시간 정렬, 오차 평가 |
| 공유 경계 | 문서화된 로그 export 형식과 UTC 측정 시각 | export 파일을 읽는 importer |
| 이번 적용 영향 | UI/UX와 TTS 기기 점검만 선별 변경 | 변경 없음 |
| 금지 사항 | PPK 계산, 기준국 포털 인증키, 정답 판정을 본 앱에 결합 | 본 앱의 위치 추정 상태를 직접 수정 |

양쪽 앱의 결합점은 버전이 명시된 파일 계약으로 제한한다. UI 변경 때문에 로그 필드, UTC 의미, 측정 주기 또는 개인정보 삭제 규칙이 바뀌면 별도 검토 없이 적용하지 않는다.

## 7. 권장 적용 순서와 검증

1. 디자인 토큰과 배너 스타일 적용 → 검증: 주요 화면 명암 대비와 기존 테마 회귀 확인
2. 홈 카드 및 landing/NavBar 레이아웃 이식 → 검증: 목적지, ARCore, 음성, 신고, 상태·신고내역 진입 경로 유지 확인
3. 카드·라벨·단계 표시 접근성 적용 → 검증: TalkBack 낭독 순서, 중복 낭독, 잠김 이유, 포커스 이동 확인
4. TTS 미설치 `BLOCKED` 처리와 보완 적용 → 검증: 성공·미설치·설치 복귀·실행 중 실패 시나리오 확인
5. `MainActivity` 통합 확인 → 검증: recorder, heading, PDR, ZUPT, purge fence 동작과 로그 계약 비교
6. PPK 분석 앱 경계 확인 → 검증: WalkSafe export를 읽을 수 있고 본 앱에 기준국 다운로드·PPK 의존성이 추가되지 않았는지 확인
