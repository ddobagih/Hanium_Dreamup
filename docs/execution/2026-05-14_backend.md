## API 계약 대조

### 클래스와 DetectionEvent/ReportMetadata

통과.

- `CLASS_NAMES`는 문서와 코드 모두 동일하다.
- `class_id`: `0..3`
- `class_name`: `damaged_tactile_block`, `parked_kickboard_bicycle`, `construction_obstacle`, `pothole`
- `source`: `fake`, `onnx`, `server`
- `heading`: `0 <= heading < 360`
- `bbox.x/y`: `0..1`
- `bbox.width/height`: `0 < value <= 1`
- `gps.latitude/longitude/accuracy_m` 범위가 코드에서 검증된다.

문서상 `DetectionEvent`와 코드상 `ReportMetadata`는 같은 payload 구조를 가리키는 용어 차이다. 필드 계약은 일치한다.

### ReportResponse

통과.

`backend/app/schemas.py`의 `ReportResponse`에는 문서에 필요한 `id`, `status`, detection fields, `gps`, `heading`, `image_path`, `image_content_type`, `metadata`, `location_quality`, `review_flags`, `duplicate_report_ids`, `created_at`, `updated_at`가 포함되어 있다.

### `/reports`

통과.

- `POST /reports`: multipart `metadata`, `image`, 성공 시 HTTP `201`.
- 이미지 저장명은 UUID 기반 `/uploads/{uuid}.{jpg|png|webp}`.
- 중복 후보는 저장 직전 `class_name`, GPS, `captured_at` 전후 10분, 반경 25m 기준으로 조회한다.
- `GET /reports`: `limit/status/class_name/source/created_from/created_to/lat/lng/radius_m` 계약이 문서와 코드에서 일치한다.
- `lat/lng/radius_m` 일부만 전달하면 HTTP `400` 문자열 detail을 반환한다.
- `PATCH /reports/{report_id}/status`: `new/reviewed/resolved`.

### `/detect` placeholder

통과.

- `GET /detect/health`는 모델 미설정 시 `model_status: "unavailable"`, `model_version: null`, `reason: "model_not_configured"`를 반환한다.
- `MODEL_ARTIFACT_PATH`가 존재하면 현재도 `model_status: "unavailable"`, `reason: "model_adapter_not_implemented"`가 된다.
- `POST /detect`는 `context`를 `DetectContext`로 검증하고, 이미지를 신고 업로드와 같은 정책으로 검증한 뒤 HTTP `503`과 `detail.code: "model_unavailable"`을 반환한다.
- fake detector 결과를 서버 모델 결과처럼 반환하지 않는다.

## 오류 계약 점검

통과.

직접 정의된 이미지 오류는 `detail.code` 기반이다.

| HTTP | `detail.code` |
| ---: | --- |
| 400 | `unsupported_image_type` |
| 400 | `image_extension_mismatch` |
| 400 | `empty_image` |
| 400 | `image_content_mismatch` |
| 413 | `upload_too_large` |
| 503 | `model_unavailable` |

문서대로 FastAPI/Pydantic 검증 오류와 일부 문자열 detail이 섞여 있다. 프론트는 `detail.code`가 있으면 우선 사용하고, 없으면 HTTP status와 `detail` fallback으로 처리해야 한다.

## 공유 요약

프론트엔드:

- 신고 생성은 `POST /reports` multipart `metadata`, `image` 유지.
- `metadata`는 `ReportMetadata` JSON 문자열이며 inference 문서의 `DetectionEvent`와 같은 필드 구조다.
- 업로드 오류는 `detail.code` 우선 처리.
- `model_unavailable`이면 fake/client detector fallback을 유지.
- `duplicate_report_ids`는 advisory이며 서버는 중복 후보가 있어도 생성을 막지 않는다.

모델:

- class order는 `0 damaged_tactile_block`, `1 parked_kickboard_bicycle`, `2 construction_obstacle`, `3 pothole`.
- `/detect` 성공 응답은 향후 `DetectResponse(model_status="ready", model_version, detections)` 형식.
- 각 detection은 `ReportMetadata` 검증을 통과해야 하며 `source`는 `server`.
- bbox는 원본 입력 이미지 기준 normalized 좌표다.

STT/TTS:

- 백엔드 신고 API는 `8000`.
- voice prototype 문서는 `9001`.
- 백엔드와 음성 서버의 포트/경로는 분리한다.
