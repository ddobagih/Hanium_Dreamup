# WalkSafe Assist UI 기능 정리

작성 기준일: 2026-05-13

이 문서는 UI를 다시 작성하거나 개선할 때 기준으로 쓰는 기능 목록이다. 현재 코드에 구현된 기능, 임시 대체 기능, 앞으로 넣을 예정 기능을 분리한다. UI 작업자는 이 문서를 기준으로 화면을 만들되, 구현되지 않은 기능을 실제 동작하는 것처럼 표현하지 않는다.

## 1. 앱 한 줄 요약

WalkSafe Assist는 스마트폰 카메라와 위치 정보를 이용해 시각장애인 및 저시력 보행자의 전방 보행 위험 요소를 감지하고, 음성 경고와 신고 기능을 제공하는 PWA 기반 보행 보조 앱이다.

## 2. 사용자 역할

| 역할 | 목적 | 주 화면 |
| --- | --- | --- |
| 보행자 | 보행 중 위험 요소를 확인하고 음성 경고를 받으며 필요 시 신고한다. | `/` 보행 보조 화면 |
| 운영자/관리자 | 수집된 위험 신고를 조회, 필터링, 검토, 처리한다. | `/admin` 신고 관리 화면 |
| 개발/데모 담당자 | 실제 모델 연결 전 fake detector로 UI/API 통합을 확인한다. | `/`, `/admin`, 백엔드 API |

## 3. 현재 구현된 보행자용 PWA 기능

### 3.1 카메라 기반 보행 화면

- 모바일 후면 카메라 권한을 요청한다.
- 카메라 영상이 화면 대부분을 차지한다.
- 카메라가 준비되지 않았거나 권한이 거부되면 안내 문구와 `카메라 다시 연결` 버튼을 보여준다.
- 카메라 영상 위에 탐지 박스와 위험 상태를 오버레이한다.
- 화면은 세로형 모바일을 기본으로 하고, 넓은 화면에서는 카메라 영역과 상태 패널을 좌우로 배치한다.

### 3.2 위험 탐지 표시

- 현재 탐지 상태를 상단 상태 영역에 표시한다.
- 탐지된 위험 유형과 신뢰도를 함께 보여준다.
- 탐지 박스는 카메라 프레임 기준 정규화 좌표로 위치와 크기를 잡는다.
- 탐지 박스 라벨에는 한국어 위험 유형을 표시한다.
- 현재 실제 모델은 연결되지 않았고, 기본값은 fake detector이다.
- 탐지 모드 표시는 `데모 탐지 모드` 또는 `모델 연결 대기`로 나뉜다.

### 3.3 탐지 클래스

| class_id | 내부 이름 | UI 표시명 | 의미 |
| ---: | --- | --- | --- |
| 0 | `damaged_tactile_block` | 점자블록 파손 | 파손, 단절, 규격 불량 점자블록 |
| 1 | `parked_kickboard_bicycle` | 방치 킥보드/자전거 | 보행로나 점자블록을 막는 킥보드, 자전거 |
| 2 | `construction_obstacle` | 공사 장애물 | 안전콘, 임시 펜스, 공사 구조물, 적치물 |
| 3 | `pothole` | 노면 파임 | 포트홀, 꺼짐, 깊게 패인 구간 |

### 3.4 위치와 방향 상태

- 브라우저 Geolocation으로 현재 GPS 위치를 수집한다.
- GPS가 있으면 위도와 경도를 소수점 5자리로 표시한다.
- GPS 권한이 없거나 실패하면 `위치 권한 필요` 또는 오류 상태를 표시한다.
- DeviceOrientation의 `alpha` 값을 이용해 방향을 도 단위로 표시한다.
- 방향 정보가 없으면 `대기 중`으로 표시한다.

### 3.5 음성 안내

- 위험 탐지 시 Web Speech API의 TTS로 한국어 경고를 읽는다.
- 위험 유형별로 짧은 경고 문구를 읽는다.
  - 점자블록 파손: `점자블록 파손. 발밑 주의.`
  - 방치 킥보드/자전거: `전방 장애물. 천천히 이동.`
  - 공사 장애물: `공사 장애물. 우회하세요.`
  - 노면 파임: `노면 파임. 발밑 주의.`
- 신뢰도 90% 이상이면 경고 뒤에 `강한 위험 신호.`를 덧붙인다.
- 같은 위험 유형이 반복될 때 6초 쿨다운을 둔다.
- 사용자는 `음성 켜짐` / `음성 꺼짐` 버튼으로 음성 안내를 토글할 수 있다.
- 위험 유형별 진동 패턴을 사용한다.
- 음성이 꺼져 있으면 더 강한 진동 패턴으로 위험을 알린다.

### 3.6 위험 신고

- `현재 위험 신고` 버튼으로 현재 탐지 결과를 신고한다.
- 신고 시 현재 카메라 프레임을 JPEG 이미지로 캡처한다.
- 위치가 있으면 신고 전 `GET /reports/duplicate-check`로 중복 후보를 조회한다.
- 중복 후보가 있어도 보행 중 확인 모달로 사용자를 멈추지 않고, 신고 상태 문구에 중복 가능성을 표시한다.
- 탐지 metadata와 캡처 이미지를 `multipart/form-data`로 백엔드에 전송한다.
- 신고 전송 중에는 버튼에 로딩 상태를 표시한다.
- 성공하면 `신고 저장 완료: {id 앞 8자리}`를 표시한다.
- 중복 후보가 있으면 `비슷한 신고 {n}건`을 함께 표시한다.
- 탐지 결과가 없거나 전송에 실패하면 오류 메시지를 표시한다.
- 신고 성공/실패 시 haptic feedback을 제공한다.

### 3.7 PWA 기능

- `manifest.webmanifest`가 있다.
- 앱 이름은 `WalkSafe Assist`, 짧은 이름은 `WalkSafe`이다.
- standalone display, portrait orientation을 사용한다.
- service worker가 `/`, `/manifest.webmanifest`, `/icon.svg`를 캐시한다.
- GET 요청이 네트워크 실패하면 캐시된 리소스 또는 `/`로 fallback한다.

## 4. 현재 구현된 관리자 기능

### 4.1 신고 목록 조회

- `/admin`에서 신고 관리 화면을 제공한다.
- 신고 목록은 최신순으로 표시한다.
- 신고 목록은 최신순, 신뢰도순, 상태순으로 정렬할 수 있다.
- 한 번에 최대 50건을 요청한다.
- 각 신고 행에는 상태, 위험 유형, 탐지 소스, 생성 시각, 신뢰도를 표시한다.
- 각 신고 행에는 GPS 좌표 또는 위치 없음, 위치 품질을 함께 표시한다.
- 신고 행을 선택하면 상세 정보가 오른쪽 또는 아래 영역에 표시된다.

### 4.2 신고 필터

관리자 화면에서 다음 조건으로 신고 목록을 필터링할 수 있다.

| 필터 | 값 |
| --- | --- |
| 상태 | 전체, 신규, 검토 중, 처리 완료 |
| 위험 유형 | 전체, 점자블록 파손, 방치 킥보드/자전거, 공사 장애물, 노면 파임 |
| 소스 | 전체, Fake, ONNX, Server |
| 시작일 | 날짜 입력 |
| 종료일 | 날짜 입력 |
| 위치 반경 | 위도, 경도, 반경 m를 모두 입력해야 적용 |

위치 반경 검색은 위도, 경도, 반경이 모두 있을 때만 요청한다.

### 4.3 신고 상세

선택된 신고에 대해 다음 정보를 보여준다.

- 신고 이미지
- 위험 유형
- 현재 처리 상태
- 신고 생성 시각
- GPS 좌표 또는 위치 없음
- 위치 품질
- 검토 플래그
- 이미지 content type
- 탐지 소스

### 4.4 신고 상태 변경

관리자는 신고 상태를 다음 3단계로 변경할 수 있다.

| 상태 값 | UI 표시명 | 의미 |
| --- | --- | --- |
| `new` | 신규 | 아직 검토하지 않은 신고 |
| `reviewed` | 검토 중 | 운영자가 확인 중인 신고 |
| `resolved` | 처리 완료 | 확인 또는 조치가 끝난 신고 |

상태 변경 중에는 해당 신고의 상태 버튼을 비활성화한다.

### 4.5 관리자 화면 상태

- 새로고침 버튼이 있다.
- 로딩 중에는 `불러오는 중` 상태를 표시한다.
- 조건에 맞는 신고가 없으면 빈 목록 메시지를 표시한다.
- API 오류가 있으면 오류 박스를 표시한다.
- 모바일에서는 필터, 목록, 상세 영역을 한 열로 쌓는다.

## 5. 백엔드/API 기능

### 5.1 기본 API

| 메서드 | 경로 | 기능 |
| --- | --- | --- |
| `GET` | `/health` | API 상태 확인 |
| `POST` | `/reports` | 신고 생성, metadata 검증, 이미지 저장 |
| `GET` | `/reports` | 신고 목록 조회 및 필터링 |
| `GET` | `/reports/{report_id}` | 신고 단건 조회 |
| `PATCH` | `/reports/{report_id}/status` | 신고 상태 변경 |
| `GET` | `/reports/duplicate-check` | 중복 후보 신고 조회 |
| `GET` | `/uploads/{filename}` | 저장된 신고 이미지 조회 |

### 5.2 신고 생성 데이터

신고 생성은 `multipart/form-data`를 사용한다.

| part | 내용 |
| --- | --- |
| `metadata` | `DetectionEvent` JSON 문자열 |
| `image` | 현재 카메라 프레임 캡처 이미지 |

백엔드는 metadata를 검증한 뒤 이미지 파일을 로컬 업로드 폴더에 저장한다.

### 5.3 DetectionEvent 형식

```json
{
  "class_id": 0,
  "class_name": "damaged_tactile_block",
  "confidence": 0.86,
  "bbox": {
    "x": 0.18,
    "y": 0.42,
    "width": 0.36,
    "height": 0.24
  },
  "captured_at": "2026-05-12T12:00:00.000Z",
  "source": "fake",
  "gps": {
    "latitude": 37.5665,
    "longitude": 126.978,
    "accuracy_m": 12.5
  },
  "heading": 180
}
```

### 5.4 저장되는 신고 정보

- 신고 ID
- 처리 상태
- class_id, class_name
- confidence
- bbox x/y/width/height
- captured_at
- source
- latitude, longitude, accuracy_m
- heading
- PostGIS location
- image_path
- image_content_type
- location_quality
- review_flags
- duplicate_report_ids
- 원본 metadata JSON
- created_at, updated_at

## 6. 현재 임시 대체 기능

현재 실제 YOLO/ONNX 모델은 PWA에 연결되어 있지 않다. UI/API 병렬 개발을 위해 fake detector를 사용한다.

| 임시 기능 | 현재 역할 | UI에서의 표현 |
| --- | --- | --- |
| Fake detector | 4개 탐지 클래스를 순환 생성 | 데모/개발 상태임을 표시 |
| `NEXT_PUBLIC_DETECTOR_MODE=fake` | fake 탐지 실행 | `Fake 탐지` 문구 |
| `source: "fake"` | API 통합 확인용 신고 소스 | 관리자 필터와 상세에 Fake로 표시 |

주의: fake 탐지 결과는 실제 보행 안전 판단, 모델 성능 수치, 최종 정확도 근거로 사용하면 안 된다.

## 7. 계획되어 있지만 아직 완성되지 않은 기능

아래 기능은 프로젝트 계획에 포함되어 있으나, 현재 UI/코드에서는 일부만 있거나 아직 연결되지 않았다. UI를 만들 때는 “준비 중”, “연결 예정”, “프로토타입”처럼 상태를 분명히 표시한다.

| 기능 | 현재 상태 | UI 반영 방식 |
| --- | --- | --- |
| 실제 YOLO/ONNX 브라우저 추론 | 미연결 | 모델 상태, 로딩, 실패, 지연시간 표시 영역을 준비 |
| 서버 추론 모드 | 미연결 | source가 `server`일 때도 같은 DetectionEvent UI 사용 |
| IMU+GPS 센서퓨전 | 일부만 있음 | GPS, 방향, 정확도, 보정 상태를 분리 표시 |
| DeviceMotion 기반 이동 방향/속도 | 미구현 | 실제 값이 없으면 보여주지 않거나 준비 중으로 표시 |
| STT 음성 명령 | 미구현 | 목적지 설정/명령 버튼은 후순위 |
| 목적지 설정과 경로 안내 | 미구현 | 현재 보행 위험 감지와 분리해서 설계 |
| 지자체 민원 API 연동 | 후순위 | 실제 전송처럼 표현하지 않음 |
| 신고 지도/히트맵 분석 | API 기반 일부 가능, UI 미구현 | 관리자 확장 화면 후보 |
| 현장 데이터 업로드/MLOps | 문서와 모델 스크립트 중심 | 운영자용 별도 탭 후보 |
| 모델 성능 대시보드 | 미구현 | 실제 지표가 생긴 뒤 추가 |

## 8. 모델/데이터 관련 기능

UI의 직접 기능은 아니지만 앱 기능과 연결되는 시스템이다.

- YOLO 모델 v1은 4개 위험 클래스를 대상으로 한다.
- 한국 보행 환경 데이터셋 `datasets/walksafe_kr_v1`을 최종 기준으로 둔다.
- 해외 공개 데이터셋 `datasets/walksafe_v1`은 smoke test 또는 pretrain 후보로만 사용한다.
- 데이터셋 검증 스크립트가 있다.
- YOLO 학습 스크립트가 있다.
- smoke training 결과가 저장되어 있다.
- 최종 UI에서는 fake detector가 아니라 ONNX 또는 서버 추론 결과를 DetectionEvent 형식으로 받아야 한다.

## 9. UI 작성 시 반드시 지킬 점

- 첫 화면은 마케팅 랜딩 페이지가 아니라 보행 보조 화면이어야 한다.
- 카메라 화면이 첫 viewport의 핵심이어야 한다.
- 시각장애인/저시력 사용자를 위해 현재 위험, GPS, 음성 상태, 신고 상태가 스크롤 없이 보여야 한다.
- 모든 주요 버튼은 최소 48px 높이를 유지한다.
- 색상만으로 위험/상태를 구분하지 않는다.
- 화면 낭독기용 label과 aria-live 영역을 둔다.
- 한국어 문구는 짧고 직접적으로 쓴다.
- 반복 경고로 사용자를 방해하지 않도록 음성 안내 쿨다운 개념을 유지한다.
- 관리자 화면은 예쁜 소개 페이지가 아니라 반복 조회와 처리를 위한 업무형 화면이어야 한다.
- 현재 미구현 기능은 실제 동작하는 것처럼 디자인하지 않는다.

## 10. 화면 구성 권장안

### 10.1 보행자 홈 화면 `/`

필수 영역:

- 카메라 프리뷰
- 카메라 권한/오류 fallback
- 현재 위험 상단 배너
- 탐지 모드 표시
- 탐지 bbox 오버레이
- 현재 위험 카드
- GPS 카드
- 방향 카드
- 신고 상태 카드
- 음성 안내 토글
- 위험별 진동 feedback
- 카메라/센서 재연결 버튼
- 현재 위험 신고 버튼
- 중복 신고 advisory

권장 상태:

- 카메라 준비 중
- 카메라 권한 필요
- 위치 권한 필요
- 탐지 대기
- 위험 탐지됨
- 신고 전송 중
- 신고 저장 완료
- 신고 실패
- 중복 후보 있음
- 음성 켜짐/꺼짐

### 10.2 관리자 신고 관리 화면 `/admin`

필수 영역:

- 페이지 제목과 새로고침
- 정렬 select
- 필터 바
- 신고 목록
- 신고 상세
- 이미지 미리보기
- 위치 품질/검토 플래그
- 상태 변경 버튼
- 로딩/빈 목록/오류 상태

권장 확장:

- 지도 기반 반경 검색
- 신고 위치 미니맵
- 위험 유형별 집계
- 처리 상태별 집계
- 실제 운영 단계에서만 CSV export 또는 지자체 연동 버튼 추가

## 11. UI에 바로 쓰기 좋은 핵심 문구

| 상황 | 문구 |
| --- | --- |
| 기본 위험 상태 | 위험 요소 없음 |
| 탐지 전 | 탐지 대기 |
| 카메라 준비 | 카메라 준비 중 |
| 카메라 권한 오류 | 카메라 권한을 허용해야 보행 화면을 사용할 수 있습니다. |
| GPS 대기 | 위치 대기 중 |
| GPS 권한 오류 | 위치 권한 필요 |
| 방향 대기 | 대기 중 |
| 신고 대기 | 신고 대기 중 |
| 신고 전송 | 신고 전송 중 |
| 신고 성공 | 신고 저장 완료 |
| 신고 실패 | 신고 전송 실패 |
| 음성 켜짐 | 음성 켜짐 |
| 음성 꺼짐 | 음성 꺼짐 |
| 관리자 빈 목록 | 조건에 맞는 신고가 없습니다. |
| 관리자 빈 상세 | 신고를 선택하면 상세 정보가 표시됩니다. |
